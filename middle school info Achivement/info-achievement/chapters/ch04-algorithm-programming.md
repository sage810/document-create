# Ch04: (3) 알고리즘과 프로그래밍 — 성취수준과 예시 평가 도구 (인쇄 p.31~34, 43~44, 67~86)

## 핵심
성취기준 9개([9정03-01]~[9정03-09])의 A~E와 영역별 성취수준을 담았다. 이 영역은 **A와 B의 차이가 "설명"에 있는 경우가 많다.** 프로그램의 "동작을 설명"([9정03-05]·[9정03-06]), "장단점을 설명"([9정03-03]), "문제 해결 방식을 설명"([9정03-08]), "적용 과정을 설명"([9정03-04]) 같은 말이다. D·E는 **"구분"**, **"구현"**, **"부분적으로 모듈화"**, **"발견"(수정 없음)**, **"단일 데이터 구조"**로 내려간다. 예시 평가 도구는 정보-5(서·논술형, A~E), 정보-6(실험·실습, A~B), 정보-7(실험·실습, A~B)이다.

### [9정03-01] 문제의 상태를 정의하고 수행 가능한 형태로 구조화한다.

| 수준 | 성취기준별 성취수준 (원문) |
|---|---|
| A | 문제의 초기 상태와 목표 상태, 현재 상태의 의미를 설명하고, 문제의 초기 상태와 목표 상태, 현재 상태를 구체적으로 정의하여 수행 가능한 동작으로 구조화할 수 있다. |
| B | 문제의 초기 상태와 목표 상태, 현재 상태의 의미를 설명하고, 문제의 초기 상태와 목표 상태를 정의하여 수행 가능한 동작을 탐색할 수 있다. |
| C | 문제의 초기 상태와 목표 상태의 의미를 설명하고, 문제의 초기 상태와 목표 상태를 정의하여 수행 가능한 동작을 탐색할 수 있다. |
| D | 문제의 초기 상태와 목표 상태의 의미를 설명하고, 제의 초기 상태와 목표 상태를 구분할 수 있다. |
| E | 문제에 여러 상태가 있음을 인지하고, 문제의 초기 상태와 목표 상태를 구분할 수 있다. |

- **수준을 가르는 말 (정리)**: 다루는 상태는 초기·목표·**현재** 상태(A·B) → 초기·목표 상태(C·D) → 여러 상태가 있음을 인지(E). 기능은 "구체적으로 정의하여 수행 가능한 동작으로 구조화"(A) → 정의하여 동작을 "탐색"(B·C) → 상태를 "구분"(D·E).
- 원문 D의 "제의 초기 상태와"는 "문제의"에서 '문'이 빠진 것으로 보인다. (원문 오류 의심)

### [9정03-02] 문제 해결을 위한 추상화의 중요성을 이해하고, 핵심요소를 중심으로 알고리즘을 표현한다.

| 수준 | 성취기준별 성취수준 (원문) |
|---|---|
| A | 문제를 추상화하는 과정을 설명하고, 이를 적용하여 문제를 해결하기 위한 알고리즘을 핵심 요소를 중심으로 명확하게 설계하는 과정을 통해 추상화의 중요성을 내면화할 수 있다. |
| B | 문제를 추상화하는 과정을 설명하고, 이를 적용하여 문제를 해결하기 위한 알고리즘을 핵심 요소를 중심으로 설계하는 과정을 통해 추상화의 중요성을 인식할 수 있다. |

| D | 문제 추상화 과정을 설명하고, 문제에서 문제 해결에 필요한 핵심요소를 구분하며 추상화의 중요성을 수용할 수 있다. |
| E | 문제 추상화 과정을 인지하고, 문제에서 문제 해결에 필요한 핵심요소를 구분하며 추상화의 중요성을 수용할 수 있다. |

- **수준을 가르는 말 (정리)**: 추상화 과정을 "설명"(A~C) → "설명"하고 핵심요소만 "구분"(D) → 과정 "인지"(E). 기능은 추상화를 "적용"해 핵심 요소 중심으로 "명확하게 설계"(A) → 적용해 설계(B) → 적용 언급 없이 설계(C) → 핵심요소 "구분"(D·E). 가치·태도는 추상화의 중요성을 "내면화"(A) → "인식"(B·C) → "수용"(D·E).

  | 수3 | 순차적 데이터 구조 동작 설명하기 | 2: 리스트 참조 동작을 이해하고 변수 값 정확 / 1: 참조는 이해했으나 값 일부 오류 / 0: 참조 동작을 이해하지 못함 |

- **핵심 문장**: "성취수준 A를 달성하기 위해서는 문항 3번을 정확하게 해결하여야 한다." 성취수준 A의 "프로그램의 동작을 설명"이 문항 3에 대응한다(정리).
- **채점 시 고려 사항**: 텍스트 기반 언어를 쓰면 그 환경의 순차 구조를 충분히 설명한 뒤 같은 문항과 채점 기준을 준용한다. 큰 범위의 프로그래밍 수행평가 안에 넣어 평가할 수도 있다.

### 정보-7: 함수 작성·활용과 디버깅 — '딸기 줍기' (p.79~86)
- **성취기준** [9정03-07] | **유형** 실험·실습 | **목표 성취수준** A~B | **배점** 10점 | Ⅰ장 개발 과정 예시 ①과 같은 도구다([ch00](ch00-understanding.md) Worked Example).
- **문항** (블록 코딩, 로봇이 딸기를 옮김): 1. '딸기 줍기' 함수의 잘못된 블록 하나를 고친다. 2. '딸기 놓기' 함수를 '딸기 줍기'보다 블록을 많이 쓰지 않고 작성한다. 3. '실행' 부분의 두 오류를 고친다. 블록 추가는 금지하고 위치·값 수정만 허용한다. 4. 두 함수로 새 배치 문제를 푼다. 회색 칸은 이동 불가이고, 실행 블록 수를 최소로 한다.
- **채점 기준**

  | 문항 | 채점 요소 | 척도 |
  |---|---|---|
  | 수1 | 오류 발견 및 디버깅 | 1: 논리적 오류를 찾아 올바르게 수정 / 0: 못 함 |
  | 수2 | 함수 작성하기 | 2: 오류 없이 + 블록 수 적절 / 1: 오류 없으나 블록이 너무 많음 / 0: 논리 오류, 미작성 |
  | 수3 | 오류 발견 및 디버깅 | 2: 실행부 오류 수정 + 함수 블록 연결로 올바르게 실행 / 1: 오류는 고쳤으나 연결해도 실행 안 됨 / 0: 못 함 |
  | 수4 | 함수 활용 프로그래밍 | 5: 두 함수로 해결 + 블록 수 적당 / 4: 해결했으나 블록 많음 / 3: 두 함수 사용, 일부 해결 / 2: 한 함수로 해결 / 1: 한 함수, 일부 해결 / 0: 함수 미사용, 미해결 |

- **채점 시 고려 사항**
  - 코드가 논리적으로 이상 없고 올바르게 수행되면 해결로 본다.
  - 수3·수4는 학생이 수1·수2에서 만든 함수를 참조한다고 보고 판정한다.
  - '일부 해결'은 "함수를 활용하여 사각형으로 배치된 딸기 8개를 모두 줍거나, 모두 내려놓는 행동을 한 번 이상 수행했을 때"다.
  - 블록 수는 '시작 버튼을 클릭했을 때'에 연결된 블록 수다. 해결하고 10개 이하면 5점, 10개를 넘으면 4점이다.
  - 텍스트 기반 언어는 함수 작성·활용법을 충분히 설명한 뒤 준용한다.
- **수준과의 연결 (정리)**: 블록 수 기준은 성취수준 A의 "효율적으로 모듈화"를 숫자로 바꾼 것이다. 수1·수3의 "올바르게 수정"은 A·B·C의 "수정", D·E의 "발견"을 가른다.

## 세특·평가에 쓰기 (제안)
- **A를 확인하는 질문 하나**: 이 영역의 A는 대부분 "설명"이 붙어 있다. 수행평가 끝에 ‘네 프로그램이 어떻게 동작하는지 변수 값으로 설명해 보라’는 문항이나 구술 확인을 넣으면 A/B를 가를 근거가 생긴다(정보-6 문항 3이 그 예).

- **[9정03-09] 협력**: "공유"(A·B)를 관찰하려면 결과물 공유 단계(코드 공유, 발표, 피드백 주고받기)가 수업에 있어야 한다.
