## 2. 판단 규칙 — 상황 → 할 일 → 근거

| 상황 | 이렇게 | 근거 |
|---|---|---|
| 피지컬 컴퓨팅 난이도를 정할 때 | 초등 실과 수준 코드, 미리 구성된 시스템 동작 또는 간단 구현. HW·SW 통합 동작 인식에 초점 | 컴퓨팅 시스템 고려 2 |
| 프로그래밍 경험이 적은 학급 | 피지컬 컴퓨팅을 프로그래밍 입문으로 앞에 배치 | 컴퓨팅 시스템 고려 4, 방향 (마) |
| 데이터 실습 도구를 고를 때 | 운영 체제를 타지 않는 도구(웹 기반) 우선 | 데이터 고려 1 |
| 데이터 활동 수준이 학생마다 다를 때 | 시각적 표현 → 스프레드시트 분석으로 단계화 | 데이터 고려 2 |
| 알고리즘 단원 평가 증거 | 결과 코드 + 사고 과정 누적 기록(보고서·포트폴리오) | 알고리즘 고려 1, 평가 방향 (라) |
| 프로그래밍 언어를 고를 때 | 학생 수준에 맞는 언어. 단 순차 저장 구조·논리 연산·중첩 제어를 쓰는 수준의 프로젝트 | 알고리즘 고려 2 |
| AI 실습 도구를 고를 때 | 이미 익숙한 언어·환경, 인지적 부하 최소 | AI 고려 1, 방법 (나) |
| 윤리 토의를 채점할 때 | 결론이 아니라 근거의 논리성과 다면적 검토 | AI 고려 2, 해설 [9정04-05] |
| 진로 탐색 차시 배치 | 다른 영역을 실제로 배운 뒤(학기 후반) | 디지털 문화 고려 1 |
| 교과서 순서를 바꾸고 싶을 때 | 가능. 문제 상황·난이도·준비 상태·학습 환경 중 근거를 적는다 | 방향 (마) |
| 앞서가는 학생 / 뒤처진 학생 | 상위·하위 학년군 성취기준 활용, 개인차 소집단 | 방향 (바), 방법 (마) |
| 결석·원격 상황 | 온라인 교실·커뮤니티로 결손 방지 | 방법 (다) |
| 평가에 디지털 도구(자동 채점, LMS)를 쓸 때 | 평가 전에 사용법 교육 | 평가 방법 (나) |
| 채점 방식을 정할 때 | 개념·기능 → 정량, 품질·심미성 → 정성 | 평가 방법 (다) |
| 평가 항목 이름을 정할 때 | 교과 역량 하위 요소 이름으로 | 평가 방향 (가) |

## 4. 어긋남 점검 — 이런 계획이면 고시와 맞지 않다

| 신호 | 어긋나는 항목 |
|---|---|
| 평가가 지필뿐이다 | 평가 방법 (가) |
| 프로그래밍이 알고리즘 영역에만 있다 | 교수·학습 방법 (라) |
| 결과물만 채점하고 과정 기록이 없다 | 평가 방향 (나)·(라), 알고리즘 고려 1 |
| 피지컬 컴퓨팅에서 복잡한 회로·긴 코드를 요구한다 | 컴퓨팅 시스템 고려 2 |
| AI 실습에서 새 텍스트 언어를 처음 배운다 | AI 고려 1 |
| 윤리 토론에 ‘정답’이 있다 | AI 고려 2, 디지털 문화 고려 2 |
| 진로 탐색이 학기 첫 주다 | 디지털 문화 고려 1 ("실제로 학습한 내용을 바탕으로") |
| 평가 당일 처음 쓰는 도구가 있다 | 평가 방법 (나) |
| 03-07 활동에 디버거(실행 추적) 사용이 없다 | 성취기준 [9정03-07] 문장 |
| 02-01에서 문자·이미지·소리·동영상 중 일부만 다룬다 | 해설 [9정02-01] |
| 05-02 실천 방안이 개인 차원뿐이다 | 해설 [9정05-02] ("개인과 사회가 각각") |

## 5. 표기 — 공문서(평가 계획, 수업 계획, 학교생활기록부)에는 고시 표기

| 고시 원문 | 지도서 기록(info-guide)에 적힌 표기 |
|---|---|
| 구성요소 | 구성 요소 |
| 운영 체제 | 운영체제 |
| 핵심요소 | 핵심 요소 |
| 비교⋅분석, 수집⋅분류⋅저장 (가운뎃점 ⋅) | 비교·분석 (·) — 문자만 다르고 뜻은 같음 |

info-guide 기록의 띄어쓰기가 지도서 인쇄본 그대로인지, 옮겨 적으면서 바뀐 것인지는 지도서 원본으로 확인하지 못했다.
