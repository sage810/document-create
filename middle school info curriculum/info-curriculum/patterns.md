# 패턴 — 교육과정 문서를 수업·평가 설계로 바꾸는 방법

고시의 성취기준·해설·고려 사항·교수·학습 및 평가 항목에서 뽑은 설계 기법이다. **근거**는 고시 원문 위치이고, **어떻게**의 구체적 칸 구조는 정리하면서 붙인 제안이다.

---

## 1. 해설 → 도달 기준 → 채점 기준
**언제**: 성취기준으로 수행 평가 기준이나 활동지 평가 칸을 만들 때.
**어떻게**: ① 해설에서 "~할 수 있어야 한다" 절을 하나씩 떼어 도달 기준 목록으로 만든다(영역 파일의 「해설에서 뽑은 도달 기준」 표). ② 성취기준 끝 동사를 최상위 기준으로 둔다. ③ 도달 기준을 몇 개, 얼마나 정확하게 충족했는지로 수준을 나눈다.
**주의**: 해설은 25개 중 12개에만 있다. 해설이 없으면 내용 체계의 과정⋅기능 요소를 도달 기준으로 쓴다.
**근거**: 각 영역 (가) 성취기준 해설.

### Worked Example — [9정04-05] (제안)
성취기준: "인공지능 학습에 필요한 데이터의 수집과 활용에서 발생하는 윤리적인 문제의 해결 방안을 구상한다."
해설에서 뽑은 도달 기준: ⓐ 현실적 문제를 법적·사회적·윤리적 측면에서 봄 ⓑ 타당한 해결 방안 제시 ⓒ 방안별 장단점 정리 → 결론 도출 ⓓ 인공지능의 사회적 역할과 가치 판단

| 활동지 칸 | 대응 도달 기준 |
|---|---|
| ① 문제 상황 (예: 얼굴 사진을 동의 없이 학습 데이터로 수집) | — |
| ② 측면별 쟁점: 법적 / 사회적 / 윤리적 | ⓐ |
| ③ 해결 방안 2개 이상 + 각각의 장점·단점 | ⓑ ⓒ |
| ④ 나의 결론과 근거, 인공지능이 사회에서 해야 할 역할 | ⓒ ⓓ |

| 수준 | 기준 |
|---|---|
| 상 | 세 측면을 모두 분석하고, 해결 방안 2개 이상의 장단점을 비교해 근거 있는 결론을 내며, 인공지능의 사회적 역할과 가치를 판단한다 |
| 중 | 두 측면 이상을 분석하고 방안별 장단점을 정리했으나, 결론의 근거나 가치 판단이 부분적이다 |
| 하 | 한 측면에서 해결 방안을 제시하는 데 그친다 |

결론의 ‘정답’ 여부로 채점하지 않는다. AI 고려 사항 2가 "근거를 가지고 논리적으로" 주장하는지를 보라고 한다. 지도서의 실제 성취 수준은 [info-guide ch09](<../../middle school info book read/info-guide/chapters/ch09-ai-problem-solving.md>)에서 확인한다.

## 2. 성취기준 하나 → 수업 목표 세 줄
**언제**: 차시·단원 목표를 쓸 때.
**어떻게**: 영역 파일의 「성취기준 ↔ 내용 요소」 표에서 그 성취기준 행의 지식⋅이해 / 과정⋅기능 / 가치⋅태도를 한 줄씩 목표로 쓴다. 가치⋅태도 칸이 비면 해설의 "판단", "태도" 문장을 가져온다.
**주의**: 대응표는 고시에 없고 정리한 것이다. 공문서에는 성취기준 원문을 그대로 적는다.
**근거**: 개요 p.6 "세 범주는 … 성취기준을 통해 연결되고 완성".

## 3. 추상화 3단 칸 + 사고 과정 포트폴리오
**언제**: 알고리즘·프로그래밍 활동 전부. 다른 영역에서 프로그래밍을 쓸 때도.
**어떻게**: 활동지 앞부분을 「문제 발견 → 상태 정의(초기·현재·목표) → 핵심요소 추출 → 알고리즘」으로 고정하고, 매 활동지를 모아 포트폴리오로 평가한다.
**주의**: 칸이 형식적이 되지 않게, 상태 정의가 바뀌면 알고리즘도 바뀌는 문제를 고른다.
**근거**: 알고리즘 고려 사항 1, 평가 방향 (라), 평가 방법 (가).

## 4. 데이터 활동 사다리
**언제**: 데이터 영역에서 학급 수준이 고르지 않을 때.
**어떻게**: ① 손으로 표·그래프 그리기 → ② 스프레드시트 정렬·필터 → ③ 함수·차트·피벗으로 분석 → ④ 데이터에 근거한 주장 쓰기. 모든 단계를 「해결할 질문」으로 시작한다.
**주의**: 특정 운영 체제에 묶인 프로그램을 피하고 웹 기반 도구를 쓴다.
**근거**: 데이터 고려 사항 1~3, 해설 [9정02-04].

## 5. 근거 있는 주장 토의
**언제**: AI 윤리 [9정04-05], 디지털 윤리 [9정05-02], 개인 정보·저작권 [9정05-03].
**어떻게**: ① 학급이 논의 규칙(다른 견해 인정·존중)을 먼저 정한다 ② 쟁점을 측면별로 나눈다 ③ 각자 주장 + 근거 ④ 해결 방안 장단점 ⑤ 결론. 05-02는 실천 방안을 개인/사회로 나누어 쓴다.
**주의**: 민감 사례(사이버 폭력, 과의존)는 가상·공개 사례로 한다. 자기 공개를 요구하지 않는다.
**근거**: AI 고려 사항 2, 디지털 문화 고려 사항 2, 해설 [9정04-05]·[9정05-02].

## 6. 디지털 역량 진단 → 보충 → 소집단
**언제**: 학기 초, 새 도구를 처음 쓰기 전.
**어떻게**: 영역별로 필요한 디지털 역량(로그인, 파일 저장, 타자, 블록 코딩, 스프레드시트)을 목록으로 만들어 점검한다 → 부족한 학생에게 보충 자료·시간 → 개인차를 고려해 소집단을 짠다.
**근거**: 개요 p.6, 교수·학습 방향 (나), 방법 (마).

## 7. 루브릭 공동 구성
**언제**: 프로젝트·토의처럼 정성 평가가 많은 과제.
**어떻게**: 교사가 성취기준과 도달 기준(패턴 1)을 보여 주고 → 모둠이 「잘한 결과물의 모습」을 쓰고 → 학급이 합쳐 수준별 문장을 정한다 → 중간에 자기 평가, 끝에 동료 평가.
**근거**: 평가 방향 (다), 평가 방법 (가)·(다).

## 8. 영역 묶음 프로젝트
**언제**: 차시가 모자라거나 깊이 있는 학습이 필요할 때.
**어떻게** (고시가 연결을 허용·권장한 조합):

| 묶음 | 근거 |
|---|---|
| 알고리즘 [9정03-08] + 피지컬 컴퓨팅 [9정01-03] | 알고리즘 고려 사항 3 |
| 데이터 [9정02-05] + 다른 교과 데이터 | 성취기준 "여러 학문 분야의 사례", 방향 (라) |
| 알고리즘 [9정03-09] + 다른 교과 문제, 짝·모둠 개발 | 성취기준 "다양한 학문 분야", 방법 (가) 짝 프로그래밍 |
| AI [9정04-02·05] + 데이터 [9정02-02] | 핵심 아이디어 "데이터는 윤리적 편향성이 없도록" |
| 디지털 문화 [9정05-01] + 앞 영역에서 실제로 배운 내용 → 진로 | 디지털 문화 고려 사항 1 |
| 아무 영역 + 범교과 주제(생태전환, 지속가능발전) | 방향 (다) |

**주의**: 순서를 바꿀 때는 방향 (마)의 기준(문제 상황, 난이도, 준비 상태, 학습 환경) 가운데 무엇 때문인지 계획서에 적는다.

## 9. 영역마다 프로그래밍 한 번
**언제**: 연간 계획을 점검할 때.
**어떻게**: 데이터(분석 프로그램), AI(AI 블록·확장으로 분류기), 디지털 문화(규칙 안내 챗봇·퀴즈), 컴퓨팅 시스템(피지컬 컴퓨팅) 영역에 프로그래밍으로 문제를 해결하는 활동을 하나씩 넣는다.
**근거**: 교수·학습 방법 (라), 해설 [9정02-04] "소프트웨어나 프로그래밍으로 분석".

## 10. 인지 부하 관리
**언제**: 새 도구와 새 개념이 겹칠 때(피지컬 컴퓨팅, AI).
**어떻게**: 미리 만들어 둔 시스템·코드를 동작시키고 수정하는 것부터 시작한다. 이미 익숙한 언어·환경을 쓴다.
**근거**: 컴퓨팅 시스템 고려 사항 2, AI 고려 사항 1, 방법 (나).
