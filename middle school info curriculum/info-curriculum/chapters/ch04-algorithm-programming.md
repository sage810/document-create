## 한눈에
성취기준 9개로 가장 큰 영역이다. 흐름은 **문제 상태 정의(추상화) → 알고리즘 표현·비교·전략 설계 → 프로그래밍 요소 3종(순차 저장 구조, 논리 연산·중첩 제어, 함수·디버거) → 실생활 문제 해결 → 협력 개발**이다. 고려 사항의 핵심은 두 가지다. 추상화 단계(문제 발견 → 상태 정의 → 핵심요소 추출)를 거쳐 알고리즘을 설계하게 할 것, 그리고 그 사고 과정을 **보고서나 포트폴리오로 누적 기록**해 과정 전체를 평가할 것.

- "알고리즘은 다양한 설계 전략을 통해 일상생활의 문제를 해결하는 데 활용된다."
- "자동화를 고려해 설계된 알고리즘은 컴퓨터가 이해할 수 있는 언어로 구현되어 생활을 더욱 편리하게 하는 데 활용된다."
- "프로그램 개발은 협력이 필요하며, 공유하는 문화를 통해 더 좋은 프로그램이 개발된다."

## 성취기준 (원문, p.12)
- **[9정03-01]** 문제의 상태를 정의하고 수행 가능한 형태로 구조화한다.
- **[9정03-02]** 문제 해결을 위한 추상화의 중요성을 이해하고, 핵심요소를 중심으로 알고리즘을 표현한다.
- **[9정03-03]** 알고리즘의 중요성을 이해하고, 문제를 해결하는 다양한 알고리즘을 비교⋅분석한다.
- **[9정03-04]** 사례를 중심으로 문제 해결에 적합한 전략을 선택하여 알고리즘을 설계한다.
- **[9정03-05]** 데이터를 순차적으로 저장할 수 있는 구조를 활용하여 문제 해결 프로그램을 작성한다.
- **[9정03-06]** 논리 연산과 중첩 제어 구조를 활용하여 문제를 해결하는 프로그램을 작성한다.
- **[9정03-07]** 프로그램 작성에서 함수를 활용하고, 프로그램 수행 결과를 디버거로 분석하여 오류를 수정한다.
- **[9정03-08]** 실생활의 문제를 탐색하여 발견하고, 프로그래밍을 통해 해결한다.
- **[9정03-09]** 다양한 학문 분야의 문제 해결을 위해 협력하여 소프트웨어를 개발한다.

## (가) 성취기준 해설 (원문, p.12~13) — 03-03, 03-04, 03-05만 해설 있음
- **[9정03-03]** "문제를 해결하는 알고리즘은 여러 가지 방식으로 나타날 수 있으나 정보 과목에서 추구하는 목표는 문제를 효과적이고 효율적으로 해결하는 알고리즘임을 인식하고, 하나의 문제를 해결하는 여러 알고리즘에 어떠한 장단점이 존재하는지를 비교⋅분석하여 논리적으로 설명할 수 있어야 한다."
- **[9정03-04]** "문제를 해결하기 위해 정보 분야에서 활용하는 문제 해결 전략을 이해하고, 문제 해결 과정에 적절한 전략을 활용하여 문제를 해결할 수 있어야 한다."
- **[9정03-05]** "입력된 데이터를 처리하여 결과 데이터를 도출하는 형태로 프로그램이 제작된다는 개념을 이해하고, 배열이나 리스트 등 데이터를 순차적으로 저장할 수 있는 구조를 활용하여 많은 양의 데이터를 효과적으로 처리할 수 있어야 한다."

### 해설에서 뽑은 도달 기준 (정리)
| 성취기준 | 학생이 할 수 있어야 하는 것 | 평가 동사 |
|---|---|---|
| 03-03 | ① 목표는 **효과적이고 효율적인** 알고리즘임을 인식 ② 한 문제를 푸는 여러 알고리즘의 **장단점 비교·분석** ③ **논리적으로 설명** | 비교·분석, 설명 |
| 03-04 | ① 정보 분야의 문제 해결 **전략** 이해 ② 문제 해결 과정에 적절한 전략 활용 | 선택, 설계 |
| 03-05 | ① 프로그램 = 입력 데이터 → 처리 → 결과 데이터 (**입력–처리–출력 개념**) ② **배열이나 리스트**로 많은 양의 데이터를 효과적으로 처리 | 작성 |

## (나) 성취기준 적용 시 고려 사항 (원문, p.13)
1. "문제를 해결하는 과정에서 문제 발견, 상태 정의, 핵심요소 추출 등의 추상화 단계를 거쳐 알고리즘을 설계하는 과정을 자연스럽게 경험할 수 있도록 교수⋅학습 절차를 설계하고, 문제 해결 과정 전반을 평가할 수 있도록 보고서나 포트폴리오 등을 활용하여 학생의 사고 과정을 누적하여 기록하도록 한다."
2. "학생의 수준을 고려하여 적합한 프로그래밍 언어를 선정하고, 초등학교 실과 과목에서 학습한 기초적인 프로그래밍 기능을 바탕으로 데이터를 순차적으로 저장하는 구조, 논리 연산, 중첩 제어 구조를 활용할 수 있도록 프로젝트의 수준을 적절하게 설정하도록 한다."
3. "프로젝트 활동에서는 실생활의 문제를 해결하기 위한 알고리즘을 설계하고 이를 적용한 소프트웨어를 개발하는 활동을 중점으로 교수⋅학습을 설계하도록 한다. 필요에 따라서는 '컴퓨팅 시스템' 영역과 연계하여 피지컬 컴퓨팅 시스템을 설계, 제작하고 이를 동작하게 하는 소프트웨어를 결합하는 형태의 프로젝트도 제공할 수 있다."
4. "효율적인 알고리즘 설계와 프로그램 작성은 시간, 에너지, 컴퓨팅 시스템 자원을 절약하는 방안임을 학생들이 인식할 수 있도록 안내한다."

## 수업·평가 설계 포인트 (제안)
- **추상화 3단 칸**: 고려 사항 1 → 모든 프로그래밍 활동지 앞부분에 「문제 발견 → 상태 정의(초기·현재·목표) → 핵심요소 추출」 칸을 고정한다. 같은 칸이 학기 내내 반복되면 그 자체가 포트폴리오가 된다.
- **포트폴리오로 과정 평가**: 고려 사항 1 + 평가 방향 (라)([ch07](ch07-teaching-assessment.md)) → 결과 코드만 채점하지 않는다. 사고 과정 기록(상태 정의, 알고리즘 초안, 디버깅 기록)을 누적해 평가한다.
- **언어 선택 기준**: 고려 사항 2 → "학생의 수준을 고려하여 적합한 프로그래밍 언어를 선정"하라고 하므로 블록형/텍스트형 모두 가능하다. 프로젝트 수준은 순차 저장 구조·논리 연산·중첩 제어 구조를 **쓰도록** 설정한다(이 세 요소가 빠진 프로젝트는 성취기준을 덮지 못한다).
- **03-03 평가 문항 틀**: 같은 문제를 푸는 두 알고리즘을 주고 「작업량·시간·자원」 기준으로 장단점을 비교하게 한다. 고려 사항 4의 "시간, 에너지, 컴퓨팅 시스템 자원을 절약"하는 관점을 비교 기준으로 그대로 쓴다.
- **03-07은 디버거까지**: 성취기준 문장이 "디버거로 분석하여"이다. 오류 찾기 활동에 실행 추적(한 단계씩 실행, 변수 값 관찰) 도구 사용을 넣는다.
- **03-09 협력의 근거**: 핵심 아이디어 3 + 교수·학습 방법 (가) "짝 프로그래밍"([ch07](ch07-teaching-assessment.md)) → 역할 분담표·코드 공유 기록을 평가 증거로 남긴다.
- **피지컬 결합 프로젝트**: 고려 사항 3 → 03-08 프로젝트를 [ch02](ch02-computing-system.md) 01-03과 묶어 한 번에 운영할 수 있다.
