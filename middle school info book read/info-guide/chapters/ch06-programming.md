## 핵심 한 줄
- 많은 데이터는 **리스트**(하나의 이름 + 번호 붙은 항목, 1번부터)로 저장·관리하고, **논리 연산자(그리고/또는/~가 아니다)** 와 **중첩 제어문**(조건문·반복문 안의 조건문·반복문)으로 복잡한 상황을 표현하며, 반복되는 코드를 **함수**(정의 → 호출, 매개 변수)로 묶어 재사용하고, 실행 결과를 분석해 **디버깅**(문법 오류·논리 오류 수정)한다. 모든 활동은 "문제 정의(초기·현재·목표 상태) → 핵심 요소(오브젝트·변수·기능) → 알고리즘 설계 → 코드 → 실행·수정" 틀로 진행됨. (p.214~245)

  - 생각의 씨앗 심기로 사회적 약자를 위해 개발된 프로그램 사례를 보여 주며 "누군가를 위한 프로그램을 만들게 된다면 누구를 위해 어떤 프로그램을 만들고 싶은지, 그 프로그램은 누군가에게 어떤 도움을 줄 수 있는지" 생각해 보고 자유롭게 발표하게 함.

  - 유의점: 30개의 변수에 각각 이름을 지어 프로그래밍하면 하나하나 선택하며 작업해야 해서 불편함 → 하나의 이름으로 30개 이상 기억 공간을 설정해 관리하면 더 효율적임을 설명.

    - 유의점: 하나의 이름으로 여러 기억 공간을 만들어 순차 저장하는 리스트 구조의 장점 설명. 실생활 순차 저장 구조의 예(학급 명단, 음악 플레이리스트 등) 이야기하기.

  - ➌ 리스트 항목 관리하기: 항목 추가 실습, 항목 수정·삭제 실습, 명령어를 활용한 리스트 관리 방법 설명.
  - ➍ 나만의 버킷 리스트 만들기 실습하기.
    - 유의점: 학생들이 직접 실습할 충분한 시간 제공, 실생활 연계 예로 리스트의 활용성 이해 돕기.
- **정리**: 변수와 리스트의 개념, 리스트의 장점 정리 / 리스트의 특징과 리스트를 만들고 프로그램에 활용하는 방법 정리 / 다음 차시 예고. 유의점: 형성 평가로 학습 내용을 스스로 정리.

  - C "프로그래밍에서 데이터를 저장하는 방식이 다양함을 인지하고 간단한 순차 구조를 사용할 수 있다."

- **정리**: 실습한 두 프로그램의 차이점 비교·분석 / 실습 과정에서 어려웠던 점 공유 / 학습 내용 정리 및 자기 평가 / 다음 차시 예고. 유의점: 형성 평가로 스스로 정리.

### 동기 유발 — 새싹 틔우기
(p.215, 교 107쪽) 제목 발문: **"수많은 데이터, 어떻게 처리할까요?"**
- 만화 4칸(칸 순서는 렌더링으로 확인)
  1. 여학생이 명단 종이를 들고 — "우리 반 학생들 이름을 변수에 저장해서 프로그램에 활용해 볼까?"
  2. '변수' 상자에 '강OO' 이름을 넣는 그림 "×30개" — "30명이니까 변수를 30개나 만들어야 해."
  3. 여러 상자에 둘러싸인 학생 — "너무 많은데 더 편한 방법 없을까?"
  4. 강아지 캐릭터가 '리스트' 칸 상자를 가리킴 — "리스트를 만들어 봐."
- 본문 그림 Ⅲ-15(변수와 리스트의 구조) 말풍선: "프로그램이 실행되는 동안 값을 저장하기 위한 기억 장소를 변수라고 해요." / "100개, 1,000개, 각각의 이름으로 변수를 만들려니 힘들어요." / "리스트는 하나의 이름으로 수많은 데이터를 처리할 수 있어요."
- 도입 글: "프로그램에서 데이터의 순차 구조를 활용하면 많은 양의 데이터를 효과적으로 처리할 수 있다."
- **해설**: 학생 30명 명단을 각 변수에 저장하려면 30개 변수 이름을 설정하고 일일이 선택하며 저장해야 해 프로그램 효율이 크게 떨어짐 → 하나의 이름으로 30개 이상 기억 공간을 묶어 처리·관리하는 리스트가 더 효율적임을 설명. (p.215)
- 지도상의 유의점(소단원): 순차 저장 구조의 장점을 설명하고 일상생활 순차 저장 구조(학급 명단, 음악 플레이리스트 등)의 예를 들어 보게 함. (p.215)

### 전개 — 본문 흐름과 핵심 개념

#### 1 순차적인 데이터 저장 (교 107~108쪽, p.215~216)
- **(1) 변수와 리스트**: 컴퓨팅 시스템은 실행 중 데이터를 변수에 저장 → 데이터가 많으면 변수도 많아져 저장·출력이 번거로움 → 여러 데이터를 순차 저장하고 하나의 이름으로 관리하는 구조 = **배열 또는 리스트**.
  - 지도서 비유: 변수 = 이름이 적힌 **상자**(숫자·문자·참/거짓 등 저장), 리스트 = 여러 칸으로 나뉜 **큰 서랍장**. (p.215)
- **(2) 리스트 만들기**: 엔트리 [자료]-[리스트 만들기], 스크래치 [변수]-[리스트 만들기] (그림 Ⅲ-16). 말풍선: "프로그래밍 언어에 따라 배열 또는 리스트 중 하나를 사용하기도 해요." / "엔트리와 스크래치에서는 배열이 아닌 리스트로 순차 구조를 구현할 수 있어요." (p.216)
- 지도서 보충 (p.216)
  - 리스트의 장점: 여러 데이터를 하나의 이름으로 묶어 관리 / 추가·삭제·수정이 쉬움 / 반복문으로 효율적 처리.
  - 리스트를 만들 때 주의점: 이름은 저장할 데이터와 연관 있는 글자로, 너무 길지 않게. 만든 뒤 반드시 내용을 저장.
  - **배열과 리스트 비교 표**: 크기 — 배열은 처음 크기로 고정·변경 어려움 / 리스트는 유동적, 추가·제거 쉬움. 데이터 종류 — 배열은 같은 종류만 / 리스트는 다양한 종류. 성능 — 배열은 고정 크기라 접근이 빠르고 효율적 / 리스트는 유동적이지만 때로 느릴 수 있음.

#### 2 리스트의 특징 (교 109쪽, p.217)
- 교과서 특징 4가지: 서로 다른 유형의 데이터 저장 가능 / 입력된 데이터를 **항목**이라 하며 순차 저장 / 각 항목에 번호가 부여되며 **번호는 1번부터** 시작 / 항목 번호로 검색·수정·삭제가 쉬움.
- 보조단 QnA: "Q.리스트 관련 명령어는 어디에 있나요?" → "A.리스트 관련 명령어는 리스트 만들기 이후에 활성화되어요."
- 그림 Ⅲ-17 리스트 관련 명령어 블록(엔트리 9개, 스크래치 12개).
- 지도서 "프로그래밍 언어에서 리스트의 특징": 순서대로 저장, 색인(번호)으로 원하는 위치 접근, 같은 값 중복 저장 가능, 숫자·문자열 혼합 가능, 생성 후 추가·삭제·변경 자유, 항목 수 쉽게 확인, 일부분만 선택 사용, 반복문으로 전체 처리, 편리한 명령문 다수. (p.217)
- **엔트리 리스트 명령어 자세히** (p.217, 예: 리스트 이름 '과일')
  | 기능 | 엔트리 블록 | 비고 |
  |---|---|---|
  | 항목 데이터 가져오기 | `과일 의 (1) 번째 항목` | |
  | 데이터 추가 | `(사과) 항목을 과일 에 추가하기` | 맨 마지막 순번에 추가 |
  | 전체 항목 수 | `과일 항목 수` | |
  | 포함 여부 | `과일 에 (포도) 이 포함되어 있는가?` | 참/거짓 |
  | 보이기/숨기기 | `리스트 과일 보이기` / `리스트 과일 숨기기` | 실행 화면 목록 |
  | 수정 | `과일 (2) 번째 항목을 (바나나) (으)로 바꾸기` | |
  | 삭제 | `(1) 번째 항목을 과일 에서 삭제하기` | 뒤 항목이 앞으로 1개씩 이동 |
  | 삽입 | `(오렌지) 을(를) 과일 의 (2) 번째에 넣기` | 기존 2번째부터 한 칸씩 뒤로 이동 |

#### 3 리스트의 활용 — '오늘의 메뉴' 예 (교 110~111쪽, p.218~219)
- 도입 지시문: "'오늘의 메뉴' 리스트를 만들고 먹고 싶은 메뉴를 리스트 항목에 추가 및 수정하는 과정을 통해 리스트를 활용하는 과정을 알아보자." 삽화 말풍선 "오늘은 뭐 먹지? 김밥, 떡볶이, 어묵, 튀김"
- **(1) 리스트 추가하기**: [리스트 만들기] 클릭 → 이름 입력 → 모든 오브젝트 사용/해당 오브젝트에서만 사용 선택(그림 Ⅲ-18). 말풍선: 엔트리 '모든 오브젝트에서 사용', 스크래치 '모든 스프라이트에서 사용'을 선택하면 다른 오브젝트에서도 사용 가능해 활용도가 높음.
  - 지도서: 엔트리는 추가로 현재 프로그램 저장 / 서버의 **공유 리스트·실시간 리스트** 저장 선택 가능. 엔트리 [리스트 내보내기](항목 복사·엑셀·테이블)와 [리스트 불러오기](입력창에 한꺼번에 입력 후 저장). (p.218)
- **(2) 리스트 속성에서 항목 입력·수정**: 항목 수(길이) 지정 → 메뉴 입력(그림 Ⅲ-19). 말풍선: "리스트 항목을 직접 입력하려면 항목 수를 설정한 후 입력해야 하고, 명령어를 활용하여 리스트를 입력받을 때는 항목 수를 설정하지 않아도 되어요."
- **(3) 명령어로 항목 추가하기** (그림 Ⅲ-20, 엔트리)
  ```
  시작하기 버튼을 클릭했을 때
  (4) 번 반복하기
      (추가할 데이터를 입력해 주세요.) 을(를) 묻고 대답 기다리기
      (대답) 항목을 오늘의 메뉴 에 추가하기
  ```
  (스크래치: `4번 반복하기 / 추가할 데이터를 입력해 주세요. 라고 묻고 기다리기 / 대답 을(를) 오늘의 메뉴 에 추가하기`)
- **(4) 명령어로 항목 수정·삭제하기** (그림 Ⅲ-21): 수정 — "수정할 항목의 번호를 입력해 주세요." 묻고 → 번호=대답 → "어떤 내용으로 바꿀까요?" 묻고 → 내용=대답 → `오늘의 메뉴 (번호) 번째 항목을 (내용)(으)로 바꾸기`. 삭제 — "삭제할 데이터의 번호를 입력해 주세요." 묻고 → `(대답) 번째 항목을 오늘의 메뉴 에서 삭제하기`. 말풍선: "번호, 내용 등 때에 따라 필요한 변수를 사용할 수 있어요."
- 지도서 "반복문과 리스트": 반복문으로 모든 항목에 순차 접근 → 탐색·수정, 조건에 맞는 항목 찾기, 새 리스트 만들기, 합계 구하기 등. 반복문과 리스트의 결합이 대량 데이터 처리의 핵심. (p.219)
- 지도서 "리스트에 있는 데이터 가져오기" (p.219)
  - 차례대로 출력하기: `번호를 1로 정하기 / 오늘의 메뉴 항목 수 번 반복하기 { 오늘의 메뉴 의 (번호 값) 번째 항목 을(를) 2초 동안 말하기 / 번호에 1만큼 더하기 }`
  - 항목 번호로 가져오기: "리스트의 몇 번째 데이터를 보고 싶나요?" 묻고 → `오늘의 메뉴 의 (대답) 번째 항목` 말하기. 합친 값 기능을 쓰면 "대답 + 번째 데이터는 + … + 입니다." 처럼 여러 메시지를 결합해 출력. 예: `(안녕!) 과(와) (엔트리) 을(를) 합친 값`.
  - 무작위 수로 하나만 출력: `오늘의 메뉴 의 (1부터 오늘의 메뉴 항목 수 사이의 무작위 수) 번째 항목` 말하기.
- **지식 플러스 — 자료 구조의 종류** (p.219): 선형 구조(요소가 한 줄로 순서대로 — 리스트, 배열, 스택, 큐) / 비선형 구조(계층적·네트워크형 — 트리, 그래프). 그림: 스택(삽입·삭제가 위에서), 배열 A B C, 트리, 그래프.

#### 실습 「나의 버킷 리스트 만들기」 (교 112~113쪽, p.220~221) — 개인, 엔트리/스크래치
- **지시문**: "희수의 버킷 리스트를 활용하여 리스트 만들기, 리스트 추가, 리스트 수정, 리스트 삭제 방법을 실습해 보자."
- 희수의 버킷 리스트: 1. 하루에 책 한 권씩 읽기 2. 성적 올리기 3. 친구와 여행 가기 4. 나만의 게임 만들기 5. 세계 일주하기 6. 가족사진 찍기
- **단계 1 화면 구성하기**: 배경·캐릭터·글자 오브젝트 추가, 화면에 '나의 버킷 리스트' 출력.
  - 지도서: 엔트리는 오브젝트 추가하기-글상자-내용 입력-추가하기(한 줄 쓰기/여러 줄 쓰기). 스크래치는 스프라이트 고르기-그리기-텍스트 도구(벡터 기본, 필요시 비트맵). (p.220)
- **단계 2 프로그램 작성하기** (지시문 원문)
  1. "리스트 만들기: '버킷 리스트'란 이름으로 리스트를 만들어 보자."
  2. "항목 추가: 만든 리스트에 아래의 항목을 입력받아 추가해 보자." → `6번 반복하기 { (버킷 리스트를 입력해 주세요) 묻고 대답 기다리기 / 대답 항목을 버킷 리스트에 추가하기 }`
  3. "항목 수정: 리스트 항목 중 3번째 항목을 '친구와 잠옷 파티 하기'로 수정해 보자." → `버킷 리스트 (3) 번째 항목을 (친구와 잠옷 파티 하기)(으)로 바꾸기`
  4. "항목 삭제: 리스트 항목 중 두 번째 항목을 삭제해 보자." → `(2) 번째 항목을 버킷 리스트 에서 삭제하기`
  5. "항목 추가: 세 번째와 네 번째 항목 사이에 '친구와 부산 여행 가기'를 넣어보자." → `(친구와 부산 여행 가기) 을(를) 버킷 리스트 의 (4) 번째에 넣기`
  6. "출력하기: 리스트 전체 항목 수를 출력해 보자." → `(전체 항목 개수:) 과(와) (버킷 리스트 항목 수) 을(를) 합친 값 을(를) 말하기`
- **단계 3 나만의 프로그램 작성하기**: "나의 버킷 리스트를 자유롭게 작성한 후 차례대로 화면에 출력하는 프로그램을 만들어 보자." (빈 칸 "_____의 버킷 리스트")
- **예시 답안 전체 코드(엔트리)**: 시작 → 6번 반복(입력받아 추가) → 3번째 수정 → 2번째 삭제 → 4번째에 삽입 → 전체 항목 개수 말하기. (p.221)
- **유의점**: 단계별 지시에 따라 실습. 생성·수정·삭제가 원활히 끝나면 직접 버킷 리스트 목록을 작성해 프로그램을 만들게 함.
- **활동 평가 항목**: "리스트를 생성하는 방법을 알고 있는가?" / "주어진 지시사항에 맞게 리스트를 구성하였는가?" / "문제 해결을 위해 리스트 명령어를 활용할 수 있는가?"

#### 심화 활동 「'도전! 골든 벨!' 퀴즈 프로그램 만들기」 (교 116~117쪽, p.224~225) — 문제 기반 학습 / 짝 프로그래밍, 엔트리·스크래치
- **상황 지시문**: "학교에서 과목별 문제 풀이에 도전하는 '도전! 골든벨!'이 열릴 예정이다. 다음 규칙을 적용하여 도전 골든 벨을 준비하기 위한 퀴즈 프로그램을 만들어 보자."
- **[규칙]** 1) 문제는 '문제' 리스트에 미리 만들어 저장한다. 2) 문제의 정답은 '정답' 리스트에 미리 만들어 저장한다. 3) 정답인 경우와 정답이 아닌 경우의 명령을 다르게 처리한다.
- 결과 화면 예시: 문제 출제자(로봇) 오브젝트 + 문제·정답 리스트 창.
- **단계와 예시 답안**
  1. 문제 정의 — 초기: 리스트가 비어 있고 점수 변수가 만들어진 상태 / 현재: 리스트에 문제·정답이 저장되고 점수에 0 저장 / 목표: 모든 문제가 출제되고 점수가 화면에 표시된 상태
  2. 핵심 요소 — 오브젝트: 문제 리스트, 정답 리스트, 문제 출제자 / 변수: 점수, 문제 번호 / 기능: 문제 출제, 답 입력, 정답 확인 후 결과 출력, 점수 계산, 결과 표시
  3. 알고리즘(문제 출제자): 시작하면 점수·문제 번호를 0으로 → 클릭하면 문제 번호 증가·문제 출력 → 입력한 답을 정답 리스트와 비교 → 정답이면 "정답입니다." + 점수 증가 / 오답이면 "오답입니다." ('문제'·'정답' 알고리즘도 같이 설계하게 지도)
  4. "다음 코드를 참고하여 프로그램을 작성해 보고 다양한 주제의 퀴즈 프로그램을 만들어 보자." 문제 출제자 코드(엔트리):
     ```
     시작하기 버튼을 클릭했을 때
         (소늘 AI 로봇_1) 모양으로 바꾸기 / 대답 숨기기
         점수 를 0 으로 정하기 / 문제 번호 를 0 으로 정하기
         (안녕! 도전 골든 벨 연습을 위한 퀴즈를 시작해 볼까요?) 을(를) 4초 동안 말하기
         (준비가 되면 저를 클릭해 주세요.) 을(를) 4초 동안 말하기
     오브젝트를 클릭했을 때
         (소늘 AI 로봇_1) 모양으로 바꾸기
         (문제 항목 수) 번 반복하기
             문제 번호 에 1 만큼 더하기
             (문제 의 (문제 번호 값) 번째 항목) 을(를) 묻고 대답 기다리기
             만일 (정답 의 (문제 번호 값) 번째 항목 = 대답) (이)라면
                 (정답입니다.) 을(를) 2초 동안 말하기 / 점수 에 1 만큼 더하기
             아니면
                 (정답이 아닙니다.) 을(를) 2초 동안 말하기
     ```
     - 지도서: 문제·정답 리스트를 먼저 만든 뒤 코드 참고. 실행·수정: 정답/오답 메시지와 점수 계산 확인.
  5. "'신호 보내기' 기능을 이용하여 다음과 같은 기능을 추가해 보자." — "정답 신호를 받으면 화면에 O가 표시되고 정답이 아니라는 신호를 받으면 화면에 X를 표시하기"
     - 예시: 문제 출제자의 정답 분기에 `정답 신호 보내기` + `점수에 10만큼 더하기`, 아니면 분기에 `오답 신호 보내기`. O 오브젝트: 시작 시 `모양 숨기기` / `정답 신호를 받았을 때 → 모양 보이기 → 2초 기다리기 → 모양 숨기기`. X 오브젝트는 `오답 신호`로 같은 구조. 소리를 추가해 효과음 재생도 가능.
  6. "친구들과 완성된 프로그램을 비교해 보고 다른 점을 이야기해 보자."
- **유의점**: 흐름 파악 → 알고리즘 설계 → 프로그래밍 순. 문제·정답 리스트는 미리 입력.
- **짝 프로그래밍**: 리스트에 넣을 문제·정답 데이터를 만드는 학생 / 퀴즈 프로그램을 작성하는 학생으로 역할 분담. **문제 기반 학습**: 문제 분석 → 자료 조사 → 해결책 제시 → 실행 및 검증 → 결과 공유.
- **평가 후 지도 방법**: 리스트 개념·특징 이해(변수와 리스트 구조의 차이 설명, 리스트 장점 설명) / 리스트 활용(리스트 만들고 항목 저장, 데이터 출력).
- **평가하기(자기 평가, 상·중·하)**: "리스트의 개념과 특징을 설명할 수 있는가?" / "프로그램에서의 리스트의 필요성을 인식하고 리스트를 만들어 활용할 수 있는가?"

### 형성 평가 · 핵심 개념 정리하기 (p.225)
- 형성 평가 1: 빈칸 공통 용어 — "컴퓨터는 프로그램 실행 중에 발생하는 데이터를 ( )에 저장한다. 그래서 여러 개의 데이터를 저장하기 위해서는 여러 개의 ( )가 필요하다." → **변수**
- 형성 평가 2: 설명하는 내용 — "여러 개의 데이터를 하나의 이름으로 한꺼번에 순차적으로 저장하고 관리하는 구조이며 블록 프로그래밍에서 주로 사용하는 데이터 구조이다." → **리스트**
- 핵심 개념 정리: 변수(실행 중 발생하는 데이터를 저장하는 기억 공간) / 리스트(여러 데이터를 순차 저장, 하나의 이름으로 묶어 효율적으로 저장·관리).

### 활동지 제작 아이디어 (제안)
1. **"변수 30개 vs 리스트 1개" 도입지**: 새싹 만화 4칸 빈 말풍선 채우기 → 상자(변수)·서랍장(리스트) 그림에 데이터 넣기 → 실생활 순차 저장 구조 3가지 쓰기. 발문 "수많은 데이터, 어떻게 처리할까요?"
2. **리스트 명령어 카드 매칭지**: 엔트리 블록 9종 ↔ 기능 연결, '과일' 리스트에 삭제·삽입을 적용한 뒤 항목 번호가 어떻게 바뀌는지 표로 추적(삭제 시 앞으로 당겨짐, 삽입 시 뒤로 밀림).
3. **버킷 리스트 실습 체크리스트**: 단계 2의 6개 지시문을 체크박스로, 각 단계 후 리스트 상태를 손으로 그려 보기(예: 6개 → 3번 수정 → 2번 삭제 후 5개 → 4번째 삽입 후 6개).
4. **골든벨 짝 역할 카드**: 문제 출제자 역할 / 프로그래머 역할, 문제·정답 리스트 5문항 작성표 + 신호(O/X) 확장 과제.

  - ➋ (심화 활동) 369 게임 만들기: 1~30 출력 → 3의 배수·10의 배수 처리 → 조건 조합에 따른 출력 → 구현(반복문 숫자 출력, 중첩 조건문 규칙, 논리 연산자 조건).
  - 유의점: 두 프로그램 난이도를 고려해 시간 배분 / 짝 프로그래밍 / 중첩 제어문의 다양한 활용 비교 / 기본 기능 후 추가 기능.
- **정리**: 두 프로그램에서 중첩 제어문 활용 방법 비교 / 결과물 공유·피드백 / 게임에 규칙 추가해 보기 / 다음 차시 예고.
- **성취 수준**: 5차시와 같음 (p.184).

### 동기 유발 — 새싹 틔우기
(p.226, 교 118쪽) 제목 발문: **"어떤 연산자를 사용할까요?"**
- 삽화: 엄마(말풍선) "마트 가서 / 우유 또는 사과 사 와." (그림: 마트, 우유, '또는', 사과)
- 도입 글: "중첩 제어 구조는 제어문 안에 또 다른 제어문이 포함된 구조이다. 논리 연산자를 활용하면 다양한 조건문을 작성할 수 있다."
- **해설**: 우유 또는 사과를 사 오라고 하면 사과만 또는 우유만 사 오라는 의미가 있음을 설명하고, **논리 연산자의 '또는'과 어떤 차이가 있을지** 생각해 보게 함. 일상에서 여러 상황을 고려해 결정하듯 프로그래밍에도 상황에 맞는 여러 연산자가 필요함을 인식시킴. (p.226)
  - 정리자 메모: 일상어 '또는'은 배타적(둘 중 하나)으로 쓰이는 경우가 많지만 논리합(OR)은 둘 다 참이어도 참 — 이 차이가 이 도입의 핵심 비교 포인트임. 차시 계획(p.181)은 "둘다 사 오던지"까지 포함해 설명함.
- 지도상의 유의점(소단원): 실생활 예시로 개념을 구체화. (p.226)

### 전개 — 본문 흐름과 핵심 개념

#### 1 논리 연산자 (교 118~119쪽, p.226~227)
- 정의: 연산자 간 논리적 관계를 나타내는 연산자 — 논리곱(AND), 논리합(OR), 논리 부정(NOT). 결과는 참 또는 거짓. 보조단 용어 "연산자: 일정한 규칙에 따라 계산할 때 사용하는 기호이다."
- **[표 Ⅲ-1] 논리 연산자의 종류 및 특징 — 진리표** (엔트리 블록 `< A 그리고 B >`, `< A 또는 B >`, `< A (이)가 아니다 >`)
  | 구분 | 설명 | 예(삽화 말풍선) | 진리표 |
  |---|---|---|---|
  | 논리곱(AND) | "두 연산 A, B가 모두 참인 경우에만 전체 결과가 참이고, 나머지는 거짓인 연산이다." | "사과도 먹고 싶고 오렌지도 먹고 싶다." | 참·참→참 / 참·거짓→거짓 / 거짓·참→거짓 / 거짓·거짓→거짓 |
  | 논리합(OR) | "두 연산 A, B 중 하나라도 참이면 전체 결과가 참이고, 둘 다 거짓일 때만 거짓인 연산이다." | "사과 또는 오렌지를 먹고 싶다." | 참·참→참 / 참·거짓→참 / 거짓·참→참 / 거짓·거짓→거짓 |
  | 논리 부정(NOT) | "연산 A가 참이면 거짓, 거짓이면 참인 연산이다." | "사과 말고 다른 과일을 먹고 싶다." | 참→거짓 / 거짓→참 |
- 논리 연산자는 조건문·반복문의 조건식을 만드는 데 주로 쓰이며 여러 개를 결합해 다양한 조건식을 만듦. 보조단 용어: "조건문: 특정 조건에 따라 실행 여부를 결정하는 명령문이다." / "반복문: 특정 조건을 만족할 때까지 반복 실행하는 명령문이다."
- **[그림 Ⅲ-22] 다양한 논리 연산 예** (말풍선 "장애물 피하기 게임에 사용할 수 있는 논리 연산자예요.")
  - 논리곱: `만일 <(생명 값 > 0) 그리고 (딸기에 닿았는가?)> (이)라면 { 점수에 10만큼 더하기 / (보너스 10점을 드립니다.) 말하기 }` — 설명 "만약 생명값＞0이고 딸기에 닿았으면 점수에 10만큼 더하고 '보너스 10점을 드립니다.'를 화면에 출력해요."
  - 논리합: `<(x좌표 값 > 100) 또는 (y좌표 값 > 50)> 이 될 때까지 반복하기 { 이동 방향으로 10만큼 움직이기 }` — "X 좌푯값 > 100 또는 Y 좌푯값 > 50이 될 때까지 이동 방향으로 10만큼 움직이기를 반복해요."
  - 논리 부정: `만일 <(벽에 닿았는가?) (이)가 아니다> (이)라면 { y 좌표를 -2만큼 바꾸기 }` — "'만일 벽에 닿았는가?'가 아니면 y 좌표를 –2만큼 바꿔요."
- **잠깐** "산술 연산자와 비교 연산자의 차이는 무엇인가요?" — 산술 연산자: 수치로 +, -, × 또는 *, / 계산 / 비교 연산자: 크다(>), 작다(<), 같다(=), 같지 않다(!=) 등 두 수 비교. (교 119쪽)
- 지도서 보충 (p.226~227) — "초등학교에서 배운 산술 연산자와 비교 연산자를 상기하고 논리 연산자를 학습할 수 있도록 한다."
  - 산술 연산자: 사칙연산 + 제곱, 몫, 나머지 등. 엔트리 계산 블록 예: `(5)/(2)의 나머지`, `(5)/(2)의 몫`, `(10)의 제곱`, `소수점 부분`, `소수점 버림값`, `소수점 올림값`, `소수점 반올림값`, `절댓값`. 출력은 `말하기` 블록 사용.
  - 비교 연산자: 결과 참(True)/거짓(False), 주로 조건문·반복문과 결합. 예: 3 > 2 참 / 3 <= 2 거짓 / 3 != 2 참. 엔트리 6종: 같다, 같지 않다, 크다, 작다, 크거나 같다, 작거나 같다.
  - 논리 연산자 특징: 항상 참/거짓 반환 / 여러 조건을 하나로 결합 / AND·OR는 첫 조건만으로 결과가 확실하면 나머지 조건을 평가하지 않음(단락 평가) / 주로 제어 구조의 조건 / 일반적으로 NOT → AND → OR 순 우선순위, 괄호로 조정.
  - 활용 예시 "온도와 습도에 맞는 운동 추천하기": "만약 온도가 20도 이상이고 습도가 70도 이하이면 '야외 운동 추천!'이라고 말하고 그렇지 않으면 '실내 운동 추천!'이라고 말하기"
  - 논리 연산자 + 조건문 → 복잡한 상황을 정확히 표현, 문제 해결 능력·논리적 사고력 향상.

#### 2 중첩 제어문 (교 120~121쪽, p.228~229)
- 정의: 제어문(조건문·반복문) 안에 또 다른 제어문을 포함한 구조. 반복문 안에 조건문·반복문, 조건문 안에 조건문·반복문. 불필요한 계산·반복 작업을 줄여 효율을 높임.
- **(1) 조건문 안에 조건문 = 중첩 조건문** (그림 Ⅲ-23 순서도: 조건식 참 → 안쪽 조건식 참/거짓 → 문장, 바깥 거짓 → 문장)
  - [그림 Ⅲ-24] 중첩 조건문의 예(엔트리):
    ```
    만일 (생명 값 > 0) (이)라면
        만일 (폭탄에 닿았는가?) (이)라면
            생명 에 -1 만큼 더하기
            점수 에 -5 만큼 더하기
    아니면
        (게임 종료!) 을(를) 말하기
        모든 코드 멈추기
    ```
    코드 설명: "만약 생명값＞0이고 만약 폭탄에 닿았다면 생명값을 1만큼 줄이고 점수를 5만큼 감점한다. 생명값＜＝0이면 게임 종료!를 말하고 모든 코드를 종료한다." 말풍선: "'-5만큼 더하기'는 '5만큼 뺀다.'는 말과 같아요."
  - **잠깐** "중첩 조건문을 논리 연산으로 표현하면 프로그램을 좀 더 간단하게 표현할 수 있어요." — 중첩: `만일 (점수 = 0) { 만일 (생명 = 0) { 모든 코드 멈추기 } }` → 논리 연산: `만일 <(점수 = 0) 그리고 (생명 = 0)> { 모든 코드 멈추기 }`
- **(2) 반복문 안에 반복문 = 중첩 반복문** (그림 Ⅲ-25): 많은 데이터 처리에 주로 사용. 잘못 쓰면 느려지거나 종료되지 않을 수 있음. 말풍선: "반복문의 형식에 조건을 잘못 입력하면 무한 루프에 빠질 수 있으므로 반복문이 종료되는 조건이 있는지 확인해 주세요."
  - [그림 Ⅲ-26] 예: `(다람쥐의 x좌푯값 < -220) 이 될 때까지 반복하기 { (2) 번 반복하기 { 다음 모양으로 바꾸기 / 0.1초 기다리기 } / x좌표를 -10만큼 바꾸기 }` (다람쥐가 걷는 애니메이션으로 왼쪽 이동)
- **(3) 조건문과 반복문이 겹쳐 있는 경우**: 필요한 만큼 겹쳐 사용 가능. 말풍선: "조건문과 반복문을 3중으로 겹쳐서 사용하는 경우도 있어요."
  - [그림 Ⅲ-27] 반복문 안에 조건문(엔트리):
    ```
    시작하기 버튼을 클릭했을 때
    숫자 를 0 (으)로 정하기
    (숫자 값 < 30) 인 동안 반복하기
        숫자 에 1 만큼 더하기
        만일 ((숫자 값)/(3)의 나머지 = 0) (이)라면
            (만세) 을(를) 1초 동안 말하기
        아니면
            (숫자 값) 을(를) 1초 동안 말하기
    ```
    (출력 예: 1, 2, 만세, 4, 5, 만세 … 30까지 — 3의 배수에서 '만세')
  - [그림 Ⅲ-28] 조건문 안에 반복문(스크래치): `만약 <Ball에 닿았는가?> (이)라면 { 4번 반복하기 { 다음 모양으로 바꾸기 / 0.1초 기다리기 } / 1초 동안 x:-170 y:-50 으로 이동하기 }`
- 지도서 보충 (p.228~229)
  - 조건문 유형: 조건식이 참일 때만 실행(`만일~(이)라면`, 예: 아이디 = 대답이면 "로그인 성공!") / 참·거짓으로 나누어 실행(`만일~아니면`, 거짓이면 "아이디를 잘못 입력하셨습니다.")
  - 반복문 유형: 정해진 횟수(`10번 반복하기`) / 조건이 참인 동안(`참 인 동안 반복하기`) / 계속 반복(무한 반복, `계속 반복하기`)
  - 중첩 제어문의 정의(동작 순서): 외부 제어문의 조건을 먼저 판단 → 참이면 내부 제어문으로 이동해 조건 판단 → 끝날 때까지 반복.
  - 장점: 여러 조건 조합을 세밀하게 제어, 조건 간 계층 관계를 명확히 표현. 단점: 과도한 중첩은 흐름 추적을 어렵게 해 가독성·수정·오류 수정을 어렵게 함.
  - 4가지 유형: 조건문 안 조건문(추가 조건 검사, 복잡한 의사 결정) / 반복문 안 반복문(외부 1회당 내부 전체 반복, 여러 단계 반복) / 조건문 안 반복문(조건 만족 시에만 반복) / 반복문 안 조건문(단계마다 조건 검사, 리스트 처리에 효과적).
  - **지식 플러스 "중첩 조건문과 논리 연산자 활용 예시"**: 조건문 안 조건문은 AND로 표현 가능.
    ```
    [중첩]  만일 (점수 ≥ 80) { 만일 (출석률 ≥ 90) { 이수입니다. 말하기 } 아니면 { 미이수입니다. } } 아니면 { 미이수입니다. }
    [AND ]  만일 <(점수 ≥ 80) 그리고 (출석률 ≥ 90)> { 이수입니다. } 아니면 { 미이수입니다. }
    ```
- **활동 플러스 "중첩 제어문을 활용한 오늘의 운세 프로그램 만들기"** — "무작위 수를 활용하여 오늘의 운세를 알려주는 프로그램을 작성해 보자." (p.229) 예시 코드:
  ```
  시작하기 버튼을 클릭했을 때
  계속 여부 를 Y 로 정하기
  <(계속 여부 값 = Y) 또는 (계속 여부 값 = y)> 인 동안 반복하기
      (오늘의 건강 운세를 알려드릴게요.) 4초 말하기
      운세 를 (1 부터 4 사이의 무작위 수) 로 정하기
      만일 (운세 = 1) → (활력이 넘치는 하루예요. 가벼운 운동을 해 보는 게 어때요?)
      만일 (운세 = 2) → (충분한 휴식이 필요한 날이에요. 일찍 자는 것이 좋겠어요.)
      만일 (운세 = 3) → (건강에 좋은 음식을 먹으면 기분도 좋아질 거예요.)
      만일 (운세 = 4) → (친구들과 함께 운동하면 더 재미있을 거예요.)
      (프로그램을 계속 하시겠어요?(Y/N)) 묻고 대답 기다리기
      계속 여부 를 대답 으로 정하기
  (다음에 또 이용해 주세요.) 2초 말하기
  ```
  (반복문 안 조건문 + 반복 조건에 논리합 — 대·소문자 Y/y 모두 허용)

#### 활동으로 쑥쑥 8 「중첩 제어문과 논리 연산자 이해하기」 (교 122쪽, p.230) — 개인, 엔트리 (태그: 비교·분석·표현)
- **지도 목표**: 논리 연산자의 기능을 익히고 복잡한 조건을 표현할 수 있다 / 실생활 문제를 중첩 제어문과 논리 연산자로 표현할 수 있다.
- **1 "제시한 조건을 논리 연산자로 조건식을 표현해 보자."** — 예시 답안:
  | 조건 | 논리 연산자 활용 |
  |---|---|
  | 국어 점수가 90점 이상이고 수학 점수가 90점 이상이면 | `<(국어 점수 값 ≥ 90) 그리고 (수학 점수 값 ≥ 90)>` |
  | 국어 점수가 90점 이상이거나 수학 점수가 90점 이상이면 | `<(국어 점수 값 ≥ 90) 또는 (수학 점수 값 ≥ 90)>` |
  | 수학 점수가 50점 이상이 아니면 | `<(수학 점수 값 ≥ 50) (이)가 아니다>` |
- **2 "제시한 중첩 제어문을 논리 연산자를 활용하여 코드를 작성해 보자."** — 제시: `만일 (수학 점수 ≥ 90) { 만일 (국어 점수 ≥ 90) { 합격입니다. 말하기 } }` → 답: `만일 <(수학 점수 ≥ 90) 그리고 (국어 점수 ≥ 90)> { 합격입니다. 말하기 }`
- **3 "제시한 알고리즘을 중첩 제어문 또는 논리 연산자를 활용하여 프로그램을 만들어 보자."**
  - [알고리즘] 숫자를 입력받는다 / 입력된 숫자가 0보다 크면 2로 나눈 나머지가 0인지 판단, 0이면 짝수·1이면 홀수 출력 / 그렇지 않으면 "숫자를 잘못 입력했습니다" 출력
  - [코드] (교과서 제시, 엔트리):
    ```
    시작하기 버튼을 클릭했을 때
    (숫자를 입력해 주세요.) 을(를) 묻고 대답 기다리기
    숫자 에 10 만큼 더하기        ← 원문 그대로(아래 "원문 오류 의심" 참조)
    숫자 를 대답 (으)로 정하기
    만일 (숫자 값 > 0) (이)라면
        만일 ((숫자 값)/(2)의 나머지 = 0) (이)라면
            (짝수) 말하기
        아니면
            (홀수) 말하기
    아니면
        (숫자를 잘못 입력했습니다.) 말하기
    ```
  - 해설: 알고리즘 속 조건식을 먼저 작성한 뒤 코드를 작성 — 사용된 조건식 `(숫자 값 > 0)`, `((숫자 값)/(2)의 나머지 = 0)`.
- **유의점**: 단순한 예부터 점진적으로 난이도 높이기 / 직접 조건을 만들어 코드로 작성하는 참여형 활동 / 논리 연산자는 비교·산술 연산자와 결합해 표현됨을 인식시킨 뒤 조건식 실습.
- **활동 평가 항목**: "제시된 조건을 논리 연산자를 활용하여 조건식을 작성할 수 있는가?" / "조건식이 여러 개 사용된 중첩 제어문을 논리 연산자를 활용한 조건식으로 표현할 줄 아는가?"

#### 활동으로 쑥쑥 9 「숫자 맞히기 게임 만들기」 (교 123쪽, p.231) — 개인/짝, 엔트리·스크래치

  4. "다음 코드를 참고하여 프로그램을 만들어 보자." (엔트리):

     시작하기 버튼을 클릭했을 때
     변수 정답 숨기기
     대답 횟수 를 0 (으)로 정하기
     정답 를 (1 부터 100 사이의 무작위 수) (으)로 정하기
     (1부터 100까지의 수 중 하나를 골랐습니다. 제가 어떤 수를 골랐는지 맞혀 보세요.) 4초 말하기
     계속 반복하기
         (예상 숫자를 입력해 주세요.) 을(를) 묻고 대답 기다리기
         대답 횟수 에 1 만큼 더하기
         만일 (정답 값 = 대답) (이)라면

             반복 중단하기
         아니면
             만일 (정답 값 > 대답) (이)라면
                 (그것보다는 커요.) 2초 말하기
             아니면
                 (그것보다는 작아요.) 2초 말하기
     ```

- **유의점**: 작은 단계로 나눠 구현하고 단계마다 오류 확인, 스스로 해결할 기회 제공 / 사용자 경험을 고려해 명확한 안내 메시지를 포함한 완성도 있는 프로그램.

#### 활동으로 쑥쑥 10 「장애물 피하기 게임 만들기」 (교 124~125쪽, p.232~233) — 모둠/짝, 엔트리·스크래치

  ```

4. **숫자 맞히기 전략 비교지**: 1~100 중 선생님 숫자를 세 전략(순서대로·중간값·무작위)으로 맞히며 횟수 기록표 작성 → 중간값 전략이 최대 7번인 이유 토의(알고리즘 효율 연결).

#### 1 함수 (교 128쪽, p.236)
- 정의: 특정 기능을 수행하기 위해 여러 명령어를 작은 단위의 블록으로 묶어 놓은 것. 호출을 통해 적용되며 필요할 때마다 호출. 같은 작업을 반복하는 부분을 함수로 만들면 시간·노력 절약, 함수만 수정해 재사용하므로 수정이 쉬움.
- **[그림 Ⅲ-29] 함수 사용 전과 후 비교 — 오각형 그리기**. 말풍선: "다음과 같이 오각형 그리기 프로그램에서 함수 사용 전과 후의 차이가 무엇인지 비교해 보세요." / "반복되는 코드를 하나의 함수로 만들어 재사용하면 프로그램이 더 간단해져요."
  ```
  [함수를 사용하지 않은 코드]
  시작하기 버튼을 클릭했을 때
  그리기 시작하기 / 붓의 색을 무작위로 정하기
  5 번 반복하기 { 이동 방향으로 50 만큼 움직이기 / 방향을 72° 만큼 회전하기 / 1 초 기다리기 }
  방향을 -72° 만큼 회전하기
  5 번 반복하기 { 이동 방향으로 50 만큼 움직이기 / 방향을 72° 만큼 회전하기 / 1 초 기다리기 }   ← 같은 묶음 반복
  …
  [함수를 사용한 코드]
  함수 정의하기 [오각형 그리기]
      5 번 반복하기 { 이동 방향으로 50 만큼 움직이기 / 방향을 72° 만큼 회전하기 / 1 초 기다리기 }
  시작하기 버튼을 클릭했을 때
  그리기 시작하기 / 붓의 색을 무작위로 정하기
  오각형 그리기 / 방향을 -72° 만큼 회전하기 / 오각형 그리기 / 그리기 멈추기
  ```
- 지도서 "함수의 종류" (p.236): **내장 함수**(기본 제공, 정의 없이 즉시 사용 — 엔트리·스크래치의 말하기, 움직이기, 반복하기 등) / **사용자 정의 함수**(사용자가 직접 정의 — 엔트리 [함수 만들기], 스크래치 [블록 만들기]).

#### 2 함수의 활용 — 사각형 그리기 (교 129쪽, p.237)
- 도입 지시문: "선으로 사각형을 그리는 작업을 함수로 만들고, 호출하는 프로그램을 만드는 과정을 살펴보면서 함수의 활용 방법을 알아보자."
- **(1) 함수 만들기**: [함수 만들기] 클릭 → 함수 이름 입력. 함수와 같이 쓸 문자·숫자 값·논리식 추가 가능. 엔트리 [블록]-[함수]-[함수 만들기], 스크래치 [내 블록]-[블록 만들기]. 말풍선: "함수 이름은 '사각형 그리기'로 정의했어요."
  ```
  [엔트리] 함수 정의하기 [사각형 그리기]
      그리기 시작하기 / 그리기 색을 (빨강) (으)로 정하기
      4 번 반복하기 { 이동 방향으로 100 만큼 움직이기 / 방향을 90° 만큼 회전하기 / 1 초 기다리기 }
      그리기 멈추기
  [스크래치] 사각형 그리기 정의하기
      모두 지우기 / 펜 내리기 / 펜 색깔을 (빨강)(으)로 정하기
      4 번 반복하기 { 100 만큼 움직이기 / 방향으로 90 도 돌기 / 1 초 기다리기 }
      펜 올리기
  ```
  - 보조단(함수 삭제): 스크래치는 함수 명령어 블록을 휴지통에 버리거나 delete 키로 삭제, 엔트리는 [속성-함수]에서 삭제·수정.
- **(2) 함수 호출하기**: 생성된 함수는 호출 과정을 거쳐야 실행됨. 말풍선: "사각형을 그리려면 '그리기 함수'를 호출하는 코드가 있어야 해요."
  ```
  시작하기 버튼을 클릭했을 때
  (선의 굵기를 입력해 주세요.) 을(를) 묻고 대답 기다리기
  그리기 굵기를 (대답) (으)로 정하기
  사각형 그리기          ← 함수 호출 명령
  ```
- 지도서 보충 (p.237)
  - 함수의 장점: 같은 코드를 여러 번 쓰지 않고 호출 / 작은 기능 단위로 나눠 복잡한 문제를 체계적으로 해결 / 적절한 이름으로 코드 목적이 명확 / 문제 시 관련 함수만 수정 → 오류 수정·유지 보수 쉬움.
  - 함수 정의 시 유의 사항: 기능과 연관된 이름, 너무 길지 않게 / 함수 하나에 한 가지 작업만 / 블록을 너무 많이 넣지 않기. 정의 후 호출해야 실행됨.
  - 함수 호출: 필요한 곳에 함수 이름 블록을 넣으면 실행, 매개 변수가 있으면 값과 함께 호출.
- **활동 플러스 "특정 기능을 함수로 정의하고 호출해서 사용하기"** — "앞으로, 뒤로, 오른쪽, 왼쪽 함수를 만들고 그 함수를 호출하여 오브젝트를 이동시키는 프로그램을 작성해 보자." (p.237)
  - 1. 함수 정의: `함수 정의하기 [앞으로] { (앞으로 이동!) 말하기 / y 좌표를 10 만큼 바꾸기 }`, `함수 정의하기 [뒤로] { (뒤로 이동!) 말하기 / y 좌표를 -10 만큼 바꾸기 }` …
  - 2. 활용: `아래쪽 화살표 키를 눌렀을 때 → 뒤로`, `오른쪽 화살표 키를 눌렀을 때 → 오른쪽` …

#### 더 알아보기 — 매개 변수를 활용한 함수 만들기 (교 130쪽, p.238)
- 매개 변수: 함수 이름 다음에 추가되는 변수로, 호출 시 전달되는 입력값을 받아 저장해 함수에서 사용. 말풍선 "매개 변수란 특정 값을 함수에 전달하는 데 사용되는 변수를 말해요." 사용자 요구에 맞춘 다양한 기능 → 활용도·효율성 향상.
- 예: 그릴 사각형의 개수를 매개 변수로 받는 함수 (그림 Ⅲ-32)
  ```
  [엔트리] 함수 정의하기 [사각형 여러 번 그리기 (문자/숫자값 1)]
      그리기 시작하기
      (문자/숫자값 1) 번 반복하기
          4 번 반복하기 { 이동 방향으로 50 만큼 움직이기 / 방향을 90° 만큼 회전하기 / 0.5 초 기다리기 }
          방향을 -45° 만큼 회전하기
          붓의 색을 무작위로 정하기
      그리기 멈추기
  [호출] 시작하기 버튼을 클릭했을 때
      (사각형을 몇 개 그릴까요?) 을(를) 묻고 대답 기다리기
      사각형 여러 번 그리기 (대답)
  ```
  (스크래치: `사각형 여러 번 그리기 (number or text) 정의하기`, 펜 색깔 30만큼 바꾸기, 방향으로 45도 회전)
- 지도서 보충 (p.238): 매개 변수 — 함수 작업에 필요한 입력값을 받는 변수, 외부에서 동작 제어·데이터 전달, 숫자·문자·조건식·변수명 가능. 장점 — 다양한 입력값으로 재사용, 코드 중복 감소, 입력을 보면 동작을 이해하기 쉬움. 만드는 순서 ❶ 이름 정의·매개 변수 유형 추가(여러 개 가능) ❷ 매개 변수 이름을 드래그해 원하는 위치로 ❸ 정의 후 블록 `사각형 여러 번 그리기 (10)` — "여기에 숫자를 넣으면 함수 내부로 그 값이 전달된다." 호출 시 "입력받은 숫자를 매개 변수 위치에 넣어 함수를 호출한다."
- **활동 플러스 "매개 변수를 포함한 함수 프로그램 만들기"** — "숫자가 짝수인지 홀수인지 판별하는 프로그램을 작성해 보자." 알고리즘: 입력 숫자가 0보다 크면 짝·홀 판별해 알려 주고, 0보다 작거나 문자를 입력하면 "잘못 입력하셨습니다." 출력, q를 입력하면 반복 종료. 코드 요지: `함수 정의하기 [짝수 홀수 판별 (문자/숫자값1)] { 만일 (값1 > 0) { 만일 (값1/2의 나머지 = 0) → 짝수입니다. / 아니면 → 홀수입니다. } 아니면 { 만일 (값1 = q) → 프로그램을 종료합니다. / 아니면 → 잘못 입력하셨습니다. 다시 입력해 주세요. } }` (p.238, 그림 판독 — 세부 문구 일부 불확실)

#### 3 디버깅 (교 132~133쪽, p.240~241)
- 정의: 실행 중 오류가 발생하면 오류가 발생한 코드를 찾아내고 수정하는 과정. 오류는 (1) 잘못된 명령문 사용과 경고 메시지 출력으로 정상 실행되지 않는 경우, (2) 실행은 되지만 의도대로 작동하지 않는 경우로 구분. 디버깅을 반복하면 안정적으로 동작하는 프로그램을 만들 수 있음.
- **[그림 Ⅲ-33] 디버깅 과정** (3칸 만화: 오류 → 디버깅 → 실행): "프로그램이 제대로 실행 안 되네. 무엇이 문제일까?" → "아! 내가 명령어를 잘못 사용했구나. 이렇게 수정하면 되겠네." → "이제야 프로그램이 제대로 실행되는구나!" 보조단 말풍선: "우리가 사용하는 프로그램은 테스트 과정을 여러 번 거친 후에 사용자에게 제공되어요."
- **말랑말랑 정보 이야기 "왜 컴퓨터의 오류를 찾아내는 것을 벌레를 잡는다고 할까요?"**: debugging = de(없애다) + bug(벌레). 초창기 거대한 컴퓨터에 불빛을 따라 들어온 벌레가 부품에 붙어 죽어 고장이 잦았고, 이를 수동으로 떼어 내던 데서 용어가 생김. (사진: 'First actual case of bug' 기록 노트 배경)
- 지도서 보충 (p.240)
  - 디버깅의 중요성: 안정적·정확한 작동 / 신뢰도·안정성 향상 / 체계적 분석·해결 능력 → 실생활 문제 해결에도 도움.
  - **오류의 종류**: 문법 오류(syntax error) — 언어 규칙 위반, 블록 프로그래밍은 미리 정의된 블록을 쓰므로 가능성이 상대적으로 낮음 / 논리 오류(logical error) — 문법은 맞지만 의도대로 동작하지 않음, 알고리즘 설계·제어문 사용 잘못이 원인, 오류 메시지 없이 실행되어 발견·수정이 어려움.
  - **디버깅 방법**: 단계별 실행(한 블록씩 실행하며 결과 확인) / 값 확인하기(말하기 블록으로 변수 값·중간 결과 표시) / 논리 흐름 검토(조건문·반복문 구조 검토).
- **교과서 "프로그래밍에서 발생하는 오류" 3유형 — 오류 코드 → 디버깅** (교 133쪽, 렌더링 확인)
  | 유형 | 예(의도) | 오류 코드 | 디버깅 |
  |---|---|---|---|
  | 경고 메시지 출력과 함께 프로그램의 실행이 안되는 경우 | "'야호' 소리를 재생하고 '야호' 모양으로 바꾼다." | `소리 (야호-모양 블록) 재생하기` / `(야호-소리 블록) 모양으로 바꾸기` — 소리·모양 선택 블록이 서로 바뀜 | 소리 블록엔 소리 '야호', 모양 블록엔 모양 '야호'로 교체. 말풍선: "소리와 모양 블록이 서로 바뀌게 되면 아래와 같은 경고 블록이 나타나요." → 경고 "빨간색으로 표시된 블록을 확인해 주세요." |
  | 잘못된 명령문을 사용하여 실행 결과가 다르게 출력되는 경우 | "당근에 닿으면 점수가 10점 증가한다." | `계속 반복하기 { 만일 (당근에 닿았는가?) { 점수 를 10 (으)로 정하기 } }` | `점수 에 10 만큼 더하기` 로 교체 |
  | 명령어의 구조를 잘못 사용하여 실행 결과가 다르게 출력되는 경우 | "만일 대답이 '창문 열어'이면 창문 열어 신호를 보내고 그렇지 않고 대답이 '창문 닫아'이면 창문 닫아 신호를 보내며 두 개의 경우가 아니면 '다시 입력해 주세요.'를 출력한다." | `만일 (대답=창문 열어) { 창문 열어 신호 보내기 / 만일 (대답=창문 닫아) { 창문 닫아 신호 보내기 } 아니면 { 다시 입력해 주세요. } }` — 두 번째 조건이 첫 조건 안에 중첩됨 | `만일 (대답=창문 열어) { 창문 열어 신호 } 아니면 { 만일 (대답=창문 닫아) { 창문 닫아 신호 } 아니면 { 다시 입력해 주세요. } }` — '아니면' 안으로 옮김 |
- **블록 프로그래밍에서 자주 발생하는 오류**(교과서 박스): '묻고 대답 기다리기'의 활용 방법을 모르는 경우 / 변수에서 '정하기'와 '만큼 더하기'의 차이를 구분하지 못하는 경우 / '신호 추가' 후 '신호 보내기'와 '신호 받았을 때'의 구조를 이해하지 못하는 경우 / 함수를 만들고 호출하는 과정을 이해하지 못하는 경우 / 함수의 매개 변수를 잘못 사용하는 경우 / 조건식을 논리 구조에 맞게 설정하지 못하는 경우 / 반복문을 상황에 맞게 사용하지 못하는 경우.
  - 지도서 첨언: 블록 프로그래밍은 명령어 입력 오류로 인한 문법 실수는 적은 대신 블록 구조·순서 배치 잘못으로 인한 **논리 오류가 더 흔함**을 안내. (p.241)
- 지도서 "블록 프로그래밍에서 발생하는 오류" 분류 (p.241)
  - 실행이 안 되는 경우: 필수 블록 누락(예: 조건문에 조건식이 없음) / 부적절한 블록 조합(예: 숫자 자리에 문자열 블록).
  - 잘못된 명령문으로 결과가 다른 경우: 잘못된 연산자 / 조건문의 논리 오류(반복 횟수·종료 조건 잘못) / 순서 오류 / 잘못된 함수 사용(기능 오해, 잘못된 매개 변수).
  - 명령어 구조 잘못으로 결과가 다른 경우: 조건 블록 구조 오류('만일~아니면' 순서 잘못) / 반복 블록 구조 오류(종료 조건 잘못 → 일찍 끝나거나 무한 반복, 중첩 반복의 내·외부 순서 잘못) / 데이터 블록 오류(잘못된 저장·접근).
- **지식 플러스 "알쏭달쏭 명령어 블록"** (p.241): 1. `숫자에 10만큼 더하기` vs `숫자를 10(으)로 정하기` 2. `x: 10 위치로 이동하기` vs `x 좌표를 10만큼 바꾸기` 3. `(숫자 값 = 10) 이 될 때까지 반복하기` vs `(숫자 값 = 10) 인 동안 반복하기`.
- **활동 플러스 "디버깅해 보기"** (p.240): "다음은 두 수를 입력받아 함수를 활용하여 두수의 덧셈을 출력하는 프로그램이다. 오류를 찾고 수정해 보자."
  ```
  함수 정의하기 [덧셈 함수]
      (두수의 덧셈은) 을(를) 2초 동안 말하기
      (((첫번째 수 값) - (두번째 수 값)) 과(와) (입니다.) 를 합친 값) 을(를) 말하기   ← 오류: '-'
  시작하기 버튼을 클릭했을 때
      (첫번째 수를 입력해 주세요.) 묻고 대답 기다리기 → 첫번째 수 를 대답 으로 정하기
      (두번째 수를 입력해 주세요.) 묻고 대답 기다리기 → 두번째 수 를 대답 으로 정하기
      덧셈 함수
  ```
  - 1. "이 프로그램의 실행 결과 입력값과 출력값은 무엇인지 적어 보자." → 입력값 5, 3 / 출력값 2
  - 2. "코드의 어떤 부분에 오류가 있는지 적어 보자." → 합을 출력하는 프로그램인데 빼기 기호가 삽입되어 뺄셈으로 출력됨
  - 3. "오류를 수정한 코드를 작성해 보자." → `-`를 `+`로 교체(정리자 보충: 결과 8)

#### 활동으로 쑥쑥 11 「꽃 그리기」 (교 131쪽, p.239) — 개인, 엔트리·스크래치(펜 확장)
- **지시문**: "선의 굵기와 도형을 입력하면 꽃 모양의 도형을 그려 주는 프로그램을 만들어 보자."
- 결과 화면 예시: '꽃 그리기' 제목, 연필 오브젝트, 변수 '도형'·'선 굵기', 입력창 → 다각형을 회전시켜 그린 꽃 모양.
- 보조단: "스크래치에서는 [확장 기능 추가하기]에서 펜을 추가해야 그리기 기능을 사용할 수 있어요."
- **단계와 예시 답안**
  1. 문제 정의 — 초기: 꽃 그리기 함수가 정의된 상태, 선 굵기·도형 입력 준비 / 현재: 사용자가 선 굵기·도형 종류를 입력, 함수 호출 / 목표: 입력에 맞는 완성된 꽃 모양이 그려진 상태
  2. 핵심 요소 — 오브젝트: 배경, 연필 / 변수: 선 굵기, 도형 / 기능: 사용자 입력받기, 도형 그리기
  3. 알고리즘(연필): 선 굵기 입력받기 → 선 굵기 설정 → 도형 종류 입력받기 → 도형 변수에 저장 → 꽃 그리기 함수 호출
  4. "꽃 그리기 함수를 만들어 보자." —
     ```
     함수 정의하기 [꽃 그리기]
         5 번 반복하기                         ← 꽃잎 5장
             (도형 값) 번 반복하기              ← 도형(다각형) 한 개
                 이동 방향으로 50 만큼 움직이기
                 방향을 ((360) / (도형 값)) 만큼 회전하기
                 0.1 초 기다리기
             방향을 72° 만큼 회전하기           ← 다음 꽃잎 방향(360/5)
     ```
  5. "다음 코드를 참고하여 프로그램을 만들어 보자." (엔트리)
     ```
     시작하기 버튼을 클릭했을 때
     (선의 굵기와 도형을 선택하면 예쁜 꽃을 그려 드립니다.) 4초 동안 말하기
     그리기 색을 (분홍) (으)로 정하기
     (선의 굵기를 입력하세요.) 묻고 대답 기다리기 → 선 굵기 를 대답 으로 정하기 → 그리기 굵기를 (선 굵기 값) 으로 정하기
     (원하는 도형의 변의 개수를 입력해 주세요.(3~8)) 묻고 대답 기다리기 → 도형 를 대답 으로 정하기
     x: 0 y: 0 위치로 이동하기
     그리기 시작하기 / 꽃 그리기 / 그리기 멈추기
     ```
     입출력 예: 선 굵기 3, 도형 5 입력 → 오각형 5개를 72°씩 돌려 그린 꽃.
- **유의점**: 기본 도형 그리기부터 단계적으로 접근해 함수에 대한 자신감 기르기 / 함수 호출 결과가 화면에 그려지는 과정으로 코드와 결과물의 관계를 명확히.
- **활동 평가 항목**: "함수의 개념을 이해하고 반복되는 부분을 함수로 정의할 수 있는가?" / "문제 해결에 필요한 함수를 정의하고 활용할 수 있는가?"

#### 활동으로 쑥쑥 12 「프로그램의 오류 찾아보기」 (교 134쪽, p.242) — 개인/모둠 토의, 엔트리·스크래치 (태그: 분석·추론)
- **지시문**: "임의의 수 N을 입력받아 1부터 N까지의 합을 구하는 코드이다. 코드를 그대로 구현한 후 디버깅을 해 보자(변수: 시작 값, 종료 값, 합계)."
- 화면: 배경과 오브젝트(변수 종료값·합계·시작값 표시, 캐릭터)
- **오류 코드**(교과서 제시):
  ```
  시작하기 버튼을 클릭했을 때
  시작 값 를 1 (으)로 정하기
  (원하는 숫자를 입력하세요.) 을(를) 묻고 대답 기다리기
  종료 값 를 대답 (으)로 정하기
  (종료 값) 번 반복하기
      시작 값 에 1 만큼 더하기
      합계 에 (시작 값) 만큼 더하기
  ((합:) 과(와) (합계 값) 를 합친 값) 을(를) 말하기
  ```
- **1 "프로그램이 제대로 실행되는지 시험해 보자."** — 제시된 기대값: ① 입력 5 → 출력 15 ② 입력 10 → 55 ③ 입력 100 → 5050. 예시 답안 표:
  | 입력값 | 제시된 출력값 | 실제 출력값 |
  |---|---|---|
  | 5 | 15 | 20 |
  | 10 | 55 | 65 |
  | 100 | 5050 | 5150 |
- **2 "프로그램의 오류가 있다면 오류 코드를 찾고 올바르게 수정해 보자."** — 원인: 시작값이 1인 상태에서 반복문 안에서 먼저 1을 더하므로 1이 아닌 2부터 더해짐(2+3+…+(N+1)). 지도: 실제 출력이 더 크게 나오므로 수를 계산하는 부분에 오류가 있음을 예측하게 지도.
  - **해결 방법 1** "시작값을 0으로 변경하기": `시작 값 를 0 (으)로 정하기` → 반복문 안에서 1 더한 뒤 1부터 더해짐.
  - **해결 방법 2** "합계에 시작값을 먼저 더하고 수를 증가하기": 반복문 안 순서를 `합계 에 시작 값 만큼 더하기` → `시작 값 에 1 만큼 더하기` 로 바꿈.
- **유의점**: 실행 결과 확인 후 디버깅으로 원인을 스스로 찾게 / 1~N 합 알고리즘을 먼저 생각하고 코드 분석 / 코드 분석으로 찾기 어려우면 직접 프로그래밍해 결과 분석으로 찾을 수 있음을 설명.
- **활동 평가 항목**: "프로그램의 논리적인 구조를 이해하고 결과를 예측할 수 있는가?" / "프로그램의 오류를 찾아내고 수정할 수 있는가?"
- 실습 파일: 134쪽 활동 프로그램 오류 찾기.ent/.sb3 (https://dtqr.kr/wuIARnA)

#### 활동으로 쑥쑥 13 「운동 동작 만들기」 (교 135쪽, p.243) — 개인/짝, 엔트리·스크래치
- **상황 지시문**: "소연이는 건강을 위해 운동을 하기로 했다. 학교 운동장을 일정 시간 동안 걷기, 뛰기, 뒤로 걷기 등 다양한 동작을 반복하면서 운동을 하려고 한다. 소연이가 운동하는 동작을 함수로 정의하고 활용하는 프로그램을 작성해 보자."
- **단계(원문)와 예시 답안**
  1. "해결해야 할 문제를 정의해 보고 필요한 핵심 요소를 찾아보자." — 초기: 운동 동작을 함수로 정의, 운동장 시작 지점 위치 / 현재: 운동 동작 함수 실행 중, 다음 동작 대기 / 목표: 정해진 시간 안에 동작이 순서대로 실행, 운동 완료 메시지 출력 // 오브젝트: 배경, 캐릭터 / 변수: 운동 횟수, 대답 / 기능: 각 동작을 함수로 정의, 운동 횟수 입력받기, 횟수만큼 반복
  2. "배경과 캐릭터를 추가해 보자." → 운동장 배경, 사람 캐릭터(육상선수)
  3. "운동에 필요한 동작을 정의하고 함수로 만들어 보자." — 표(동작/세부 동작(알고리즘)/함수 정의(코드)):
     - 걷기: 걷기 동작 1과 2를 벽에 닿을 때까지 반복 → 벽에 닿으면 방향 바꾸기 → 두 번 반복 (교과서 제시)
     - 달리기·점프하기: 같은 구조(답안)
     ```
     함수 정의하기 [걷기]
         2 번 반복하기
             이동 방향으로 20 만큼 움직이기
             (벽에 닿았는가?) 이 될 때까지 반복하기
                 육상선수(1)_2 모양으로 바꾸기 / 0.2 초 기다리기
                 육상선수(1)_3 모양으로 바꾸기 / 0.2 초 기다리기
                 이동 방향으로 20 만큼 움직이기
             화면 끝에 닿으면 튕기기
     [달리기] 위와 같은 구조, 이동 40, 모양 육상선수(1)_4/_5
     [점프하기] 이동 50, 모양 _4 → y 좌표 50 만큼 바꾸기 → 0.2초 → 모양 _5 → y 좌표 -50 → 0.2초 → 이동 50
     ```
  4. "아래의 조건을 참고하여 함수를 활용한 프로그램을 만들어 보자." — [조건] "1) 운동할 동작의 반복 횟수를 정한다." "2) 하나의 동작을 출발 지점으로 다시 올 때까지 반복한다." 예시 코드:
     ```
     시작하기 버튼을 클릭했을 때
     육상선수(1)_1 모양으로 바꾸기
     (오늘의 운동을 시작합니다.) 2초 말하기
     (운동을 몇 세트 할까요?) 묻고 대답 기다리기
     운동 횟수 를 1 (으)로 정하기
     (대답) 번 반복하기
         걷기 / 달리기 / 점프하기
         ((운동 횟수 값) 과(와) (번 완료!) 를 합친 값) 1초 말하기
         운동 횟수 에 1 만큼 더하기
     육상선수(1)_1 모양으로 바꾸기
     (운동끝!) 말하기
     ```
- **유의점**: 각 동작을 개별 함수로 정의해 모듈화·재사용의 장점 경험 / 거리·시간 등을 매개 변수로 쓰면 함수의 유연성이 높아짐을 보충 설명.

3. **디버깅 탐정 수첩**: 오류 3유형 표(경고/잘못된 명령문/구조 잘못)에 사례 카드(야호, 당근, 창문) 분류 → 1~N 합 프로그램 "예상값 vs 실제값" 표 작성 → 차이(=N)에서 원인 추리 → 해결 방법 2가지 비교. '알쏭달쏭 명령어 블록' 3쌍 O/X 퀴즈로 마무리.
4. **운동 루틴 함수 설계지**: 동작(걷기·달리기·점프·뒤로 걷기) × 세부 동작 × 함수 블록 3열 표 → 세트 수 입력 → "n번 완료!" 출력 흐름도 작성.

## 오개념 · 지도 유의점 모음
- **리스트 번호는 1부터**: 엔트리·스크래치 리스트 항목 번호는 1번부터 시작(텍스트 언어의 0부터 인덱스와 다름). (p.217)
- **삭제·삽입 시 번호 이동**: 삭제하면 뒤 항목이 앞으로 1칸씩, 중간 삽입하면 기존 항목이 뒤로 1칸씩 이동 — 버킷 리스트 실습에서 2번째 삭제 후 '3번째와 4번째 사이' 삽입을 4번째에 넣는 이유를 확인시킬 것. (p.217, p.221)
- **속성 직접 입력 vs 명령어 입력**: 속성에서 직접 입력하려면 항목 수를 먼저 정해야 하고, 명령어로 입력받으면 항목 수 설정이 필요 없음. (p.218)
- **리스트 명령어 비활성**: 리스트 관련 블록은 리스트를 만든 뒤에야 나타남. (p.217)
- **일상어 '또는' vs 논리합**: 일상 '또는'은 하나만 고르는 의미로 쓰이기 쉬우나 논리합은 둘 다 참이어도 참. (p.181, p.226)
- **논리 연산자 결과는 항상 참/거짓**이며 비교·산술 연산자와 결합해 조건식이 됨 — 단독 사용보다 조건문·반복문 안에서 쓰임. (p.181, p.227, p.230)
- **우선순위·단락 평가**: NOT → AND → OR, 괄호로 조정. AND/OR는 첫 조건만으로 결과가 정해지면 나머지를 평가하지 않음. (p.227)
- **중첩 조건문 ↔ AND**: 바깥·안쪽 조건이 모두 참일 때만 실행하는 중첩은 AND 하나로 줄일 수 있음. 단, 바깥 조건의 '아니면' 분기가 따로 있으면 그대로 바꿀 수 없음(제안 — 그림 Ⅲ-24는 아니면 분기가 있음). (p.228)
- **무한 루프 주의**: 반복문 종료 조건이 있는지 확인. 과도한 중첩은 가독성·수정성을 떨어뜨림. (p.229)
- **369 게임 조건 순서**: 가장 좁은 조건(3과 10의 공배수)을 먼저 검사해야 '만세'가 출력됨(정리자 보충). 단순 조건문만으로는 구현이 어려움을 인식시키는 것이 지도 포인트. (p.234)
- **함수 정의 ≠ 실행**: 정의만 하고 호출하지 않으면 아무 일도 일어나지 않음 — 생성과 호출의 차이를 명확히 구분. (p.185, p.237)
- **모든 함수가 매개 변수를 가져야 하는 것은 아님**(형성 평가 3). (p.245)
- **블록 프로그래밍은 문법 오류보다 논리 오류가 흔함** — 블록 구조·순서 배치 오류에 주목. 논리 오류는 메시지 없이 실행되므로 다양한 테스트 값으로 검증해야 함. (p.186, p.240, p.241)
- **헷갈리는 블록 3쌍**: 만큼 더하기 vs 로 정하기 / x: ( ) 위치로 이동하기 vs x좌표를 ( )만큼 바꾸기 / ~이 될 때까지 vs ~인 동안. (p.241)
- **'-5만큼 더하기' = '5만큼 빼기'**: 엔트리는 감소도 음수 더하기로 표현. (p.228)
- **스크래치 펜**: [확장 기능 추가하기]에서 펜을 추가해야 그리기 블록 사용 가능. (p.239)
- **'모든 오브젝트에서 사용'**: 변수·리스트를 다른 오브젝트에서도 쓰려면 이 옵션 선택. (p.218)
- **수업 운영**: 모든 활동 차시에 수준별 개별 지도·짝 프로그래밍·단계적 힌트·완성 후 응용을 반복 권장. 문제 기반 학습 절차 "문제 분석 → 자료 조사 → 해결책 제시 → 실행 및 검증 → 결과 공유". (p.180, p.183, p.224, p.234)

## 원문 오류 의심
- **p.186 (10차시 디버깅) 도입 유의점**: "함수의 필요성을 자연스럽게 인식하도록 유도한다." — 디버깅 차시인데 함수 차시(p.185) 문구가 그대로 복사된 것으로 보임(디버깅의 필요성이 맞을 듯).
- **p.187 (11차시) 도입**: "전시 학습 내용을 확인한다. [함수와 디버깅]" — 전시는 디버깅 차시이므로 [디버깅]이 자연스러움(경미).
- **p.230 활동 8-3 제시 코드**: `숫자를 입력해 주세요` 묻기 다음에 `숫자에 10만큼 더하기` 블록이 있고 곧바로 `숫자를 대답으로 정하기`로 덮어써짐 — 의미 없는 블록이 섞인 것으로 보임(렌더링 확인).
- **p.230 활동 8-3**: 지시문은 "중첩 제어문 또는 논리 연산자를 활용하여" 만들라고 하고 해설은 "논리 연산자 활용 코드 작성하기"라고 했으나, 제시 코드는 중첩 조건문만 사용하고 논리 연산자는 쓰지 않음.
- **p.232 vs p.233 배경 이동 좌표**: 알고리즘 설계에는 "x 좌표가 –480 이하이면 480 위치로 이동", 예시 코드(p.233)는 `x좌푯값 < -470`이면 `x: 470`으로 이동 — 수치 불일치. 또 알고리즘은 "이하(≤)", 코드는 "<".
- **p.233 장애물 오브젝트 이름**: 블록 문구가 "검은 동맹이"로 보임(렌더링) — '검은 돌멩이'의 오타 의심(그림 해상도 한계로 확정 불가).
- **p.234 심화 369 게임 '짝 프로그래밍'**: "움직이는 캐릭터와 장애물이 작동하는 방식이 다르므로 … 오브젝트에 따라 서로의 역할을 나누어" — 369 게임에는 장애물이 없음. 장애물 피하기 게임용 문구가 들어간 것으로 보임.
- **p.235 심화 369 5번**: 지시문은 "다음 빈칸에 조건식 코드를 넣어 프로그램을 완성해 보자."인데 교사용 축쇄면에는 이미 완성 코드가 들어가 있어 학생용 빈칸 위치를 확인할 수 없음(학생 교과서 확인 필요).
- **p.227 지도서 "논리 연산자"**: "참은 1, 거짓은 0으로 결괏값이 출력된다."는 설명은 같은 쪽의 "항상 참(true) 또는 거짓(false)의 결과를 반환한다."와 표현이 엇갈림(엔트리 블록은 참/거짓으로 표시함).
- **p.227 활용 예시**: "습도가 70도 이하이면" — 습도 단위는 %이므로 '70% 이하'가 맞음.
- **p.241 지도서 오류 분류**: "조건문의 논리 오류: 반복 횟수나 종료 조건을 잘못 설정하여 반복문이 예상과 다르게 실행될 때" — 제목은 '조건문', 설명은 '반복문' 내용으로 어긋남.
- **p.181 vs p.226 우유·사과 설명**: 차시 계획(p.181)은 "사과만…우유만…둘다"라 하고, 소단원 해설(p.226)은 "사과만 사 오거나 아니면 우유만 사 오거나"까지만 적음 — 의도(일상 '또는'과 논리합 비교)는 같으나 진술이 다름. 또 p.181 문구 "사 오던지"는 '사 오든지'의 맞춤법 오류.
- **p.236 차시 안내 텍스트**: "①-②-…-❽-❾-❿- /11차시"에서 ⑪이 텍스트 추출에서 빠졌으나 그림에는 ⑪까지 강조되어 있음(추출 문제, 원문 문제 아님).
- **p.240 활동 플러스**: "두수의 덧셈" — 띄어쓰기 '두 수'.
- **p.183 정리**: "결과물을 공유하고 및 피드백을 주고받도록 한다." — '공유하고 및' 중복.
- **p.235 핵심 개념 정리하기**: 논리 연산자 설명 "논리적인 관계를 나타날 때" — '나타낼 때'의 오타.
