# ch05 추상화와 알고리즘
> 대단원: Ⅲ. 알고리즘과 프로그래밍 | 지도서 p.172~213 (차시별 지도 계획은 p.174~178만 해당) | 교과서 84~105쪽 (본문 84~101쪽, 쉬어가기 102~103쪽, 프로그래밍 미리 보기 104~105쪽) | 성취기준: [9정03-01], [9정03-02], [9정03-03], [9정03-04] | 차시: 7차시 (01 문제 추상화 2차시, 02 알고리즘 표현과 분석 5차시)

## 핵심 한 줄
- 문제를 상태(초기·현재·목표)로 정의하고 핵심 요소를 뽑아 구조화하며 IPO로 추상화한 뒤, 알고리즘(조건 5가지)을 자연어·의사 코드·순서도로 표현하고, 여러 알고리즘을 정확성·작업량·수행 시간·기억 장소로 비교·분석하며, 4가지 문제 해결 전략(전체 탐색·분할 정복·규칙 찾기·되추적) 중 알맞은 것을 골라 설계한다. (p.192, 교 84쪽)
- 7차시의 흐름: 도서관 책 분류(사람 vs 컴퓨터) → 자율주행 상태 정의 → 여행 가방 핵심 요소 → 표·그림 구조화 → IPO 추상화(성적 관리·앱 정리) → 닭 튀기는 로봇·키오스크로 알고리즘 개념·조건 → 덧셈 알고리즘 3가지 표현 → 스티커 알고리즘 → 1~n 합 2가지 비교(O(n) vs O(1)) → 음악 파일 찾기 → 업다운 게임 전략 → 방학 주말 활동 계획 보고서(총괄). (p.174~178)

## 대단원 개관
### 대단원 개관 문장 (요약)
- 단원은 문제 발견, 상태 정의, 핵심 요소 추출 등 추상화 단계를 거쳐 알고리즘을 설계하는 과정을 자연스럽게 경험하도록 교수·학습 절차를 설계함. 학생 수준을 고려해 데이터를 순차적으로 저장하는 구조, 논리 연산, 중첩 제어 구조를 활용하는 프로젝트 수준을 설정함. (p.172)

### 대단원 지도 목표 (원문)
1. "문제의 상태를 정의하고 수행 가능한 형태로 구조화할 수 있고, 추상화의 중요성을 이해하고, 핵심 요소를 중심으로 알고리즘을 표현할 수 있다."
2. "알고리즘의 중요성을 이해하고, 문제를 해결하는 다양한 알고리즘을 비교·분석하여. 사례를 중심으로 문제 해결에 적합한 전략을 선택하여 알고리즘을 설계할 수 있다."
3. "데이터를 순차적으로 저장할 수 있는 구조, 논리 연산과 중첩 제어 구조를 활용하여 문제를 해결하는 프로그램을 작성할 수 있다."
4. "프로그램 작성에서 함수를 활용하고, 프로그램 수행 결과를 디버거로 분석하여 오류를 수정할 수 있다."
5. "실생활의 문제를 탐색하여 발견하고 프로그래밍을 통해 해결하고, 다양한 학문 분야의 문제 해결을 위해 협력하여 소프트웨어를 개발할 수 있다." (p.172)

### 대단원 핵심 역량 (p.173, 요약)
- **컴퓨팅 사고력**: 컴퓨팅을 활용한 문제 해결을 전제로 문제를 발견·분석하여 실생활과 다양한 학문 분야의 문제를 해결하는 새로운 방법론을 제시하는 능력. '추상화 능력', '자동화 능력', '창의·융합 능력' 포함. 이 단원에서는 컴퓨터로 문제 해결을 하기 위해 알고리즘을 설계함.
- **디지털 문화 소양**: 디지털 사회 구성원으로서 윤리 의식·시민성을 갖추고 디지털 기술로 의사소통·협업하는 능력. '디지털 의사소통 협업 능력', '디지털 윤리 의식', '디지털 기술 활용 능력' 포함. 이 단원에서는 일상생활 사례를 프로젝트로 모둠원과 협업하여 해결함.

  - B "문제를 추상화하는 과정을 설명하고, 문제를 해결하기 위한 알고리즘을 핵심 요소를 중심으로 설계하며 추상화의 중요성을 인식할 수 있다."
  - C "문제 추상화 과정을 인지하고, 문제에서 문제 해결에 필요한 핵심 요소를 구분하며 추상화의 중요성을 수용할 수 있다."

### 전개 — 본문 흐름과 핵심 개념
**1 문제 해결을 위한 상태 정의하기** (교 85쪽, p.193)
- 생활 속에서 해결해야 하는 질문 또는 과제 = '문제'. 문제를 이해·분석하여 초기 상태, 현재 상태, 목표 상태를 정의해야 함.
- 컴퓨팅 시스템이 해결하는 문제는 대체로 입력값을 처리하여 출력값을 얻는 과정. 예: 숫자 정렬 문제 → 목표와 현재 상태를 정의해야 함.
- 정의 상자: 문제를 시작할 때의 상황 = '초기 상태', 현재 상황 = '현재 상태', 목표에 도달한 상황 = '목표 상태'.
- [그림 Ⅲ-1] 상태 정의 — 자율주행 자동차로 집 → 마트: 초기 상태 "집(출발 지점)" / 현재 상태 "집에서 1km 떨어진 지점" / 목표 상태 "마트(도착 지점)". 삽화: 집 건물–도로 위 자동차('가는 중')–마트.
- 지도서 해설 ① 문제 상태를 표로 정리하기: 2015 개정과 달리 **2022 개정에서는 '초기 상태'가 추가**됨. 집 출발=초기, 길을 가며 얼마나 남았는지 확인하는 순간=현재, 마트 도착=목표. 표: 초기 상태 집 / 현재 상태 확인하는 지점 / 목표 상태 마트. (p.193)

**2 문제 해결에 필요한 핵심 요소 찾기** (교 86쪽, p.194)
- 문제 해결에서 중요한 부분과 중요하지 않은 부분을 찾아야 함. 현재 상태에서 목표 상태로 가려면 문제를 작은 부분으로 나누고 핵심 요소를 찾음.
- 예: 여행 가방 챙기기 — [그림 Ⅲ-2] 현재 상태(펼쳐진 물건들) 파악 → 물건을 가방에 담은 목표 상태 정의 → 가지고 가야 하는 물건과 가지고 가면 안 되는 물건(조건·요소) 확인. 삽화는 짐 목록 → 가방 → 공항으로 이어지는 흐름.
- 보조단 말풍선: "문제에서 찾아낸 중요한 요소를 핵심 요소 또는 필요한 요소라고 해요."
- 지도서 해설 ① 핵심 요소 = 문제 해결에 꼭 필요한 조건이나 요소. 일상생활의 핵심 요소 → 컴퓨팅 문제의 핵심 요소 순서로 진행. **핵심 요소는 목적에 따라 다름**:
  | 상황 | 핵심 요소 |
  |---|---|
  | 배낭을 메고 등산 | 벌레를 대비한 물품, 에너지 보충 식품 등 |
  | 비행기를 타고 해외 여행 | 비행 반입 가능 물품과 금지 물품, 전체 가방 무게 등 |
  - 짐을 많이 챙기는 것이 목적인지, 여행지 활동 관련 짐을 챙기는 것이 목적인지에 따라서도 달라짐. (p.194)

**3 문제 구조화하기** (교 86쪽, p.194)
- 정의: 상태를 정의하고 핵심 요소를 찾은 후, 핵심 요소들을 정리 및 배열하여 통일된 구조로 만드는 것 = '문제 구조화'. 요소를 체계적으로 분석하고 요소 간 관계를 쉽게 이해해 효율적으로 해결.
- 예: 가족 여행 음식 메뉴를 표로, 방문할 곳을 그림으로 정리.
- 표로 문제 구조화하기 (교과서 표, 행=구성원, 열=음식 종류):
  | 구성원 | 한식 | 양식 | 중식 | 일식 |
  |---|---|---|---|---|
  | 아빠 | O | | O | O |
  | 엄마 | O | O | | O |
  | 나 | O | | O | |
  | 동생 | | O | O | O |
  - (그림 렌더링으로 칸 위치 확인. 모든 가족이 공통으로 고른 음식은 없음 → "어디서 먹을까?" 판단 근거로 활용 가능.)
- [그림 Ⅲ-3] 그림으로 문제 구조화하기 — 서울 도심 명소·시장 노선도형 그래프(서촌, 경복궁, 덕수궁, 남대문 시장, 명동, 을지로3가, 종각, 운현궁, 종묘, 광장 시장, 동묘, 경동 시장, 마장동 축산물 시장, 서울 풍물 시장, 신당동 중앙 시장, 동대문 디자인 플라자(환승지), 중부 시장). 출처: 서울 정보 소통광장. 옆에 노드-간선 그래프 도식.
- 지도서 해설
  - ② 구조화 방법: 표, 그림 등. 일상생활 문제 해결에 많이 사용. (p.194)
  - ③ 표로 구조화할 만한 문제 찾기 활동: 운동 계획 세우기(종류, 시간, 장소 등), 공부 계획 세우기(요일, 과목, 시간, 장소 등), 놀이기구 타기(시간, 원하는 기구 등). (p.194)
  - ④ 그림으로 구조화: 크게 **그래프 그리기**와 **트리 그리기**. 그래프는 공간 관련 문제에 많이 쓰임(예: 학교 수업 이동 경로, 모둠 구성도, 지하철 노선도, 놀이공원 약도, 화학 분자 구조, 전자 회로). 트리는 나무가 가지를 치듯 위에서 아래로 뻗으며 데이터 간 관계를 계층으로 표현(예: 학생회, 회사 조직도, 우리 집 가계도, 책의 목차, 폴더 구조). 이진 트리 그림(렌더링 확인): 1 아래 7·5 / 7 아래 2·6 / 6 아래 5·11 / 5 아래 8 / 8 아래 3. (p.194)

**4 문제 추상화하기** (교 87쪽, p.195)
- 컴퓨팅 시스템이 처리할 수 있는 형태로 만들기 위해 문제 추상화가 필요함.
- 정의: 문제 해결을 위해 문제에 대한 공통적인 특성이나 핵심 요소를 추출하는 것. 과정 = 문제 이해·분석 → 상태 파악 → 작은 부분으로 나눔 → 핵심 요소 추출 → 구조화. 불필요한 요소 제거, 요소 간 관계 파악 → 효율적 해결 방법을 찾는 데 중요.
- IPO: 입력(Input)–처리(Process)–출력(Output) 형태로 표현하면 데이터와 처리 절차의 흐름을 한눈에 알기 쉬움. 보조단 용어 "IPO: 입력, 처리, 출력의 방식으로 문제를 추상화하는 방법이다."
- 교과서 예: 입력 "옷, 세면도구, 전자 기기, 책" → 처리 "여행 가방 무게 20kg 이하 체크" → 출력 "물건이 든 여행 가방".
- 지도서 해설
  - ⑤ 일반적 추상화 = 본질이 되는 핵심 부분만 표현. 컴퓨터 과학에서는 (좁은 의미) 핵심 요소 추출 + (넓은 의미) 문제 이해·분석, 핵심 요소 추출, 문제 구조화, 알고리즘 만들기까지 포함하는 광의의 추상화. 개념으로서의 추상화는 핵심을 나타내는 것, 과정으로서의 추상화는 프로그래밍 전 과정에서 추상적 모델을 만드는 행위. 본문은 IPO 방법을 적용함. (p.195)
  - ⑥ 추상화의 필요성: 불필요한 요소 제거, 요소 간 관계와 중요도 확인 → 효율적 해결. (p.195)

### 활동
#### 활동으로 쑥쑥 1 "성적 관리 문제 추상화하기" (교 87쪽, p.195)
- 형태: 개인(차시 계획 유의점 "개인별로 작성", p.174) / 도구: 종이
- **목표**: 시험 성적으로 평균을 구하는 문제를 IPO로 추상화.
- **제시 상황(원문)**: "학생들의 시험 성적을 관리하고 성적표를 출력하는 프로그램을 만들려고 한다. 시험 성적으로 평균을 계산하는 문제를 해결하기 위해 컴퓨팅 시스템이 처리할 수 있는 형태로 추상화해 보자."
- **단계**
  1. "문제의 초기 상태, 목표 상태, 핵심 요소를 찾아보자." — 칸 3개: 초기 상태 / 목표 상태 / 핵심 요소 (현재 상태 칸 없음)
  2. "입력, 처리, 출력의 과정으로 문제를 추상화해 보자." — 칸 3개: 입력 → 처리 → 출력
- **예시 답안**
  - 초기 상태: 각 과목별 점수만 있음 / 목표 상태: 과목별 평균, 개인별 평균 / 핵심 요소: 과목별 점수, 학생 수, 과목 수
  - 입력: 개인별, 과목별 점수 / 처리: 과목 평균=과목별 총합/학생 수, 개인 평균=개인 점수/과목 수 / 출력: 과목별 평균, 개인별 평균 (p.195)
- **지도상의 유의점**: 차시 계획에서 개인별 작성. 입력→처리→출력 과정을 실습하며 추상화의 중요성 설명. (p.174)

#### 활동 플러스 "실생활의 문제를 IPO로 추상화해 보기" (지도서 전용, p.195)
- 지시문: "실생활의 다양한 문제를 해결하기 위해 IPO(입력-처리-출력) 형태로 추상화해 보자."
- 1. "키오스크의 주문 처리 문제를 IPO로 추상화해 보자." — 입력: 원하는 상품 개수, 결제 방식, 포장 유무, ⋮ / 처리: 개별 가격, 전체 가격 / 출력: 주문 번호, 영수증
- 2. "해결하고 싶은 실생활의 문제를 IPO로 추상화해 보자." 보기: 이동 경로 계산, 운동 시간 계산, 성적 계산, 쇼핑 비용 계산. 예시 — 문제: 이동 경로 계산 / 입력: 출발지, 목적지, 이동 수단 / 처리: 부분 구간 경로, 이동 수단 별 경로 / 출력: 전체 이동 경로

#### 실습 "앱 정리 문제 추상화하기" (교 88쪽, p.196)
- 형태: 모둠(실습 보고서 작성·발표, p.174) / 도구: 스마트폰(없으면 컴퓨터 응용 소프트웨어로 대체)
- **지도 목표**: 앱을 목적이나 기능에 따라 분류해 관리하는 과제로 문제를 추상화. (p.196)
- **제시 상황(요약)**: 하준이는 새 앱을 내려받을 때마다 배경 화면에 바로 설치 → 앱이 많아져 불편해짐. 지시문: "스마트폰을 편리하게 사용하기 위해 새로운 앱을 설치할 때, 분류하여 앱을 관리해 보자." (삽화: 앱 아이콘이 가득한 스마트폰)
- **단계(원문) / 칸 구조 / 예시 답안**
  1. "문제를 이해하고 분석한다." — 칸 "문제가 무엇인지 적어 보기". 예시: 앱 아이콘이 많아 원하는 앱이 어디 있는지 안 보여 당황함 → 유사 유형끼리 또는 목적에 맞게 폴더별로 정리하면 편리함.
  2. "앱을 정리하기 위해 필요한 핵심 요소가 무엇인지 찾아본다." — 칸 "핵심 요소 적어 보기"(교과서에 "예 앱의 기능, 사용 빈도 등" 힌트). 예시: 앱의 기능, 사용 빈도, 앱의 종류, 주 사용 시간, 주 사용 장소 등.
  3. "앱을 정리하기 위한 입력, 처리, 출력 과정을 정리해 본다." — 입력: 앱 목록, 분류 기준(예 기능, 사용 빈도, 사용 장소 등) / 처리: 기준에 맞춰 해당 폴더에 배치 / 출력: 각 폴더에 정리된 앱
  4. "어떤 분류를 기준으로 앱을 정리할 것인지 정해 목표 상태의 앱 목록을 작성한다." — 표(행: 기능 / 앱 이름). 예시: 사진(구글포토, 스노우, 에픽) / SNS(카카오톡, 인스타그램) / 학교 소통(밴드, 학교 앱)
  5. "위와 같은 방법으로 컴퓨팅 시스템에 설치된 프로그램이나 파일을 정리해 본다." — 예시: PC 프로그램 정리(입력 프로그램 목록·분류 기준 / 처리 기준에 맞춰 아이콘 배치 / 출력 아이콘이 정리된 바탕 화면), 파일 정리(입력 파일 종류·파일 목록·발생 연도 / 처리 기준에 맞춰 폴더에 배치 / 출력 해당 폴더에 정리된 파일)
- 보조단 Q/A: "Q.'앱'이 아닌 '음악'을 정리하려면 필요한 핵심 요소는 무엇일까?" "A.분야, 가수 이름, 제작사 등"
- **지도상의 유의점**: 스마트폰을 사용하지 않는 학생은 컴퓨터 응용 소프트웨어 설치 사례로 변경 가능 / 기준에 따라 분류가 달라지므로 기준 설정이 필요함을 지도 / IPO 방법으로 추상화하도록 지도. (p.196)
- **활동 평가 항목**: 문제를 이해하고 분석할 수 있는가? / 핵심 요소를 추출하는가? / 문제를 IPO 형태로 추상화할 수 있는가? (p.196)

### 형성 평가 · 핵심 개념 정리하기
- 핵심 개념 정리하기 (p.196): 상태 정의하기(초기=문제를 시작할 때의 상황, 현재=현재 상황, 목표=목표에 도달한 상황) / 핵심 요소(현재→목표 도달을 위한 중요한 요소) / 문제 구조화(핵심 요소를 정리·배열해 통일된 구조로) / 문제 추상화(공통 특성·핵심 요소 추출, IPO로 하면 처리 절차를 쉽게 앎) — 입력(Input) → 처리(Process) → 출력(Output)
- 평가 도구: 수행 평가 — 지도서 270~272쪽 수행 평가 활동지 / 지필 평가 — 지도서 286~293쪽 시험 대비 문제 (p.196)
- 형성 평가 (O/X) (p.196)
  1. 문제를 시작할 때의 상태를 '현재 상태'라고 한다. → X (초기 상태)
  2. IPO 방법은 '입력-출력-처리' 순이다. → X (입력-처리-출력)

### 활동지 제작 아이디어 (제안)
1. **"사람 vs 컴퓨터 도서관"**: 생각의 씨앗 장면의 컴퓨터 열 4칸을 비워 두고 사람 열만 제시 → 학생이 문제 추상화(초기·현재·목표·핵심 요소) 칸을 채움 → 마지막에 "컴퓨팅을 이용해서 문제를 해결한 사례에는 어떤 것이 있을까?" 3줄 쓰기. (제안)
2. **"상황 따라 달라지는 가방"**: 등산/해외 여행/수학여행 3가지 카드 중 하나를 뽑아 초기·현재·목표 상태 표 → 핵심 요소(가져갈 것/가져가면 안 되는 것) → IPO(예: 처리 "무게 20kg 이하 체크") 작성. 정리 문항: 형성 평가 O/X 2문항. (제안)
3. **"우리 반 구조화"**: 표 구조화(가족 음식 선호 표 형식으로 모둠원 점심 메뉴 선호) + 그림 구조화(학교 이동 경로 그래프 또는 학생회 트리) 중 각 1개 그리기. (제안)
4. **"내 폰 정리 보고서"**: 실습 5단계 칸 구조 그대로 + 확장 질문 "'앱'이 아닌 '음악'을 정리하려면 필요한 핵심 요소는 무엇일까?" (제안)

### 전개 — 본문 흐름과 핵심 개념
**1 알고리즘의 개념** (교 89~90쪽, p.197~198)
- 정의: 문제 해결의 방법을 단계적인 절차로 표현한 것, 어떤 문제를 해결하기 위한 동작들의 모임. 즉 문제를 이해·분석·추상화한 후 문제 해결 과정을 순서대로 나열한 것. 알고리즘으로 표현해야 컴퓨팅 시스템이 정확하게 처리함.
- [그림 Ⅲ-4] 닭을 튀겨 주는 로봇 — 로봇 팔이 튀김 바구니를 다루는 그림, 손글씨 메모(기름을 언제 끓이고 치킨을 넣어야 하나? 치킨을 넣고 기름을 끓여야 하나? — 그림 속 손글씨, 대략 복원). 교과서 발문: "예를 들어 닭을 튀겨 주는 로봇은 어떤 알고리즘으로 작동할까?" → 순서가 바뀌거나 온도가 잘못 설정되면 어떤 일이 벌어질지 생각하면 알고리즘이 왜 필요하고 얼마나 중요한지 알 수 있음.
- 지도서 해설 ① 알고리즘의 중요성: 초등 정보에서 개념을 배웠으므로 정의를 다시 정립하고 문제 추상화와 연계. '닭을 튀겨 주는 기계' 알고리즘이 잘못되면 어떤 일이 벌어질지 예측 → 중요성 설명. 모둠별로 비슷한 사례를 생각하고 알고리즘의 중요성을 토의·토론하는 활동 제시 가능. (p.197)

  - 방법 3 "점프 코드를 만들어 놓고 사용하기": 점프하기 = 올라가기-기다리기-내려오기 정의 후 점프하기 ×3 (함수)

  - 지도서 해설: 방법 1 순차 구조(실제 점프 코드는 x 좌표도 이동하게 값을 넣으면 좋음), 방법 2 반복 구조, 방법 3 함수(다음 단원에서 처음 배우므로 간단히, 교 128쪽 Ⅲ-2-03 '함수와 디버깅'에서 배울 것이라고 안내). (p.198)
  - 보조단 "알고리즘의 어원": 중세 수학자·천문학자 '알콰리즈미(Alkhwarizmi, 780~850)'의 이름에서 유래. (p.198)

**2 알고리즘의 특징(조건)** (교 91쪽, p.199)
- 알고리즘은 순서가 정확해야 하며 문제 해결에 적합한 조건이 따라야 함. 예: 음식 주문 알고리즘(키오스크). [그림 Ⅲ-6] 알고리즘의 조건 — 가운데 키오스크 앞 학생 "먼저 메뉴를 고르고, 음료를 추가해야지!", 둘레에 5가지 조건:
  - **입력(input)**: 시작 전에 필요한 정보나 데이터 — 음식 메뉴, 개수, 지불 수단 등.
  - **명확성**: 각 단계에서 무엇을 하는지 명확해야 함 — 메뉴 고르기·개수 선택의 순서, 반복 횟수 등.
  - **수행 가능성**: 각 명령이 논리적으로 수행 가능하고 현실에서 실행할 수 있는 연산이어야 함.
  - **유한성**: 주어진 절차와 횟수만큼 처리한 후 반드시 종료 — 주문 과정이 끝나야 함.
  - **출력(output)**: 수행 후 결과로 나타난 값 — 주문 목록과 금액.
- 보조단 말풍선 발문: "알고리즘대로 수행하였을 때 알고리즘이 끝나지 않는다면 어떻게 될까요? 또, 알고리즘의 조건이 하나라도 빠지면 어떻게 될까요?"
- 지도서 해설 ② 알고리즘의 조건: 키오스크를 작동하면서 겪었던 일을 상기 — 순서대로 잘 조작할 수 있는지, 순서가 틀려 당황한 적은 없었는지 경험 이야기. (p.199)

**3 알고리즘 표현 방법** (교 92~93쪽, p.200~201)
- 자연어, 의사 코드, 순서도 등. 순서대로 나열하고 조건을 명확히 나타내는 것이 중요. 지도서: 초등에서 배웠으나 알고리즘 분석에 꼭 필요하므로 상기하고 심화. (p.200)
- [그림 Ⅲ-7] a, b 두 수의 덧셈 알고리즘 (예제 전체)
  - 자연어: 변수 a에 10을 저장한다. / 변수 b에 5를 저장한다. / a와 b를 더해서 변수 sum에 저장한다. / sum값을 출력한다.
  - 의사 코드: `a ← 10` / `b ← 5` / `sum ← a + b` / `sum값 출력`
  - 순서도: 시작 → [a = 10, b = 5](처리, 주석 "변수 a와 b에 10과 5 저장") → [sum = a+b](주석 "합을 구해 변수 sum에 저장") → [sum](입출력, 주석 "sum에 저장된 값 출력") → 끝
  - 파이썬 코드: `a = 10` / `b = 5` / `sum = a + b` / `print(sum)`
- (1) 자연어: 특별한 형식 없이 일상 언어로. 초기 상태, 수행 과정, 목표 상태를 순서대로 작성. 작성자는 쉽게 이해하지만 표현이 불명확하면 다른 사람은 이해하기 어려움.
- (2) 의사 코드: 특정 언어 문법을 따르지 않고 프로그래밍 언어로 변환하기 쉬운 형태. 조건·반복·함수·연산자 사용, 들여쓰기로 코드 범위 표현. 흐름 파악과 오류 위치 찾기가 쉬움.
  - 보조단 Q/A: "Q.의사 코드(pseudo code)란 무엇일까요?" "A.'흉내 코드'라는 의미로, 완벽한 프로그래밍 언어는 아니지만, 알고리즘을 알 수 있는 정도의 코드를 말해요."
  - 지도서 해설 ② 의사 코드 기호: if(조건), then(조건 만족 시 실행문) 예 `if 가격 < 30,000원 then 물건 사기`, for·while(반복), 연산자(+, -, ×, /), 값 입력 `a ← 10`(a에 10 입력). 자연어·의사 코드와 비슷한 블록 코딩: 엔트리·스크래치로 나타낸 덧셈 알고리즘 그림. (p.200)
- (3) 순서도: 정해진 기호를 쓰는 대표 방법. 흐름을 한눈에 파악, 프로그램 작성이 쉬우나 기호를 알아야 작성 가능.
  - 순서도의 기호와 의미(교과서): 단말(시작과 끝) / 입출력(데이터의 입력과 출력, 평행사변형) / 처리(연산 등 처리, 직사각형) / 판단(조건에 따른 비교·판단, 마름모) / 흐름선(실행의 흐름).
  - 보조단 말풍선: "순서도 기호는 국제표준화기구(ISO)에서 정한 기호를 사용해요."
  - 지도서 해설 ③④: 장점(정확한 표현, 흐름 한눈에) / 단점(기호와 의미를 알아야 함). 1965년 ISO 총회에서 결의한 기호 사용 권장. 작성 원칙 ① 기호로 처리 내용을 적음 ② 위→아래, 왼쪽→오른쪽 원칙, 그 외에는 화살표 ③ 흐름선은 교차해도 서로 영향 없고 여러 개가 하나로 합쳐질 수 있음. 추가 기호: 문서(물결 밑변), 준비 또는 초기화(육각형), 데이터 파일 또는 데이터베이스(원통). (p.201)

**4 알고리즘 분석** (교 94~95쪽, p.202~203)
- 알고리즘 성능 분석 방법(교과서 상자): 원하는 결과가 정확히 출력되는지 / 전체 구조가 단순하고 오류 수정이 쉬운지 / 작업량과 수행 시간 확인·비교 / 기억 장소 사용량 크기 확인·비교.
- 같은 문제도 효율성과 수행 시간을 고려해 다양한 구조로 설계 가능, 순차·선택·반복 구조를 적절히 활용. 효율적인 알고리즘 = 작업량이 적어 수행 시간이 짧고 기억 장소 사용량이 적은 알고리즘.
- 보조단 용어: 작업량(데이터가 많거나 연산이 복잡하면 많아짐, 예 비교 연산·산술 연산 횟수) / 수행 시간(작업량, 컴퓨터 성능, 알고리즘 효율성 등에 영향) / 알고리즘의 구조(순차 구조: 처음부터 끝까지 차례대로 / 선택 구조: 조건에 따라 처리 내용·순서가 달라짐 / 반복 구조: 조건을 만족할 때까지 특정 명령 반복).
- **예제 1: [그림 Ⅲ-8] 숫자 1부터 10까지의 합을 구하는 다양한 방법**
  - 방법 1: 1+2+3+…+10 = 55. 1부터 10까지 순차적으로 더함. 단순하지만 더하는 숫자가 많아질수록 작업량이 많아져 수행 시간이 길어짐.
  - 방법 2: 1 2 … 9 10 / 10 9 … 2 1 을 위아래로 놓고 더하면 11 11 … 11 11 → 11×10÷2 = 55. 오름차순과 내림차순을 더한 뒤 더한 횟수를 곱하고 반으로 나눔. 규칙만 이해하면 적은 작업량으로 숫자 범위와 상관없이 수행 시간이 일정.
  - 결론: 같은 입력·출력이라도 방법에 따라 수행 시간이 다름 → 효율적인 알고리즘을 설계·선택하고 정확하게 수행되었는지 확인해야 함.
  - 지도서 해설 ② 가우스가 (초등) 3학년 때 풀었다는 일화. 공식 (n+1)*n/2. (p.202)
- **예제 2: [그림 Ⅲ-9] 숫자 1부터 n까지의 합 구하기** (순서도, 그림 확인)
  - 방법 1 (반복 구조, 약 n번 반복; n=100이면 약 100번): 시작 → [n을 입력받는다.] → [num = 1, sum = 0] → [sum = sum+num] → ◇"num과 n이 같은가?" — 아니요 → [num = num+1] → sum = sum+num으로 되돌아감 / 예 → [sum을 출력한다.] → 끝
  - 방법 2 (공식, 순차 구조, n에 관계없이 실행 횟수 같음): 시작 → [n을 입력받는다.] → [num = 1, sum = 0] → [num = n+1] → [sum = num×n/2] → [sum을 출력한다.] → 끝
  - 말풍선(여학생): "방법 1은 1부터 순서대로 더하니까 만들기 쉽겠어. 그런데 계산하려면 입력받은 숫자 n까지 더하는 것을 계속 반복해야 하니까 상대적으로 수행 시간이 길어질 것 같아."
  - 말풍선(남학생): "방법 2는 공식을 이용해서 더하는 방식이라 사람이 생각하기는 어렵지만, 컴퓨터가 계산한다면 반복이 없어져서 수행 시간이 짧을 것 같아."
  - 캐릭터 발문: "n이 10,000,000이 된다면 수행 시간이 얼마나 차이 날까요?"
  - 지도서 해설 ③ 수행 시간 분석 = 명령을 몇 번 수행하는지 확인. 방법 1 O(n), 방법 2 상수 시간 O(1). ④ 빅오 그래프(가로 자료 입력, 세로 시간; 곡선 O(1), O(log n), O(n), O(n²), O(n³), O(nⁿ)) — 입력이 많아질수록 방법 1이 오래 걸림, 학생 수준에 따라 그래프로 시각적으로 보여 주면 효과적. ⑤ 방법 2는 비교를 위해 변수를 맞췄으나 num 없이 바로 sum = (n+1)×n/2 를 구해 출력해도 됨. (p.203)
- **지식 플러스 "시간 복잡도"** (p.202): 공간 복잡도(메모리 사용량 분석) / 시간 복잡도(수행 시간을 대략적으로 분석). 빅오(O) 표기법은 수행 시간이 가장 오래 걸리는 최악의 경우를 가정해 계산.
- **좋은 알고리즘을 작성할 때 고려할 사항** (지도서 해설 ①, p.202): "원하는 결과가 제대로 출력되는가?" / "구조가 단순하고 한눈에 파악하기 쉬운가?" / "오류 수정이 쉽게 이루어지는가?" / "작업량과 수행 시간이 적은가?" / "기억 장소의 사용량이 적은가?" — 초창기부터 자원을 적게 쓰고 결과를 빨리 보여 주는 알고리즘을 중시.
- **활동 플러스 (탐색 비교)** (p.203): 오름차순 정렬된 숫자 10개(n=10)에서 원하는 숫자 찾기 — 방법 1 앞에서부터 순서대로 찾기: 최대 10번 비교, O(n) / 방법 2 중간 숫자를 비교해 절반씩 줄이며 찾기(이진 탐색법): 최대 4번 비교, O(log n). 출처: 이솦 '숨어있는 데이터를 찾아라, 탐색'.

**5 문제 해결 전략** (교 97~98쪽, p.205~206)
- 일상 전략: 그림 그리기, 표 만들기, 기호 사용하기(여행 계획=표 만들기, 수학 문제=기호 사용하기). [그림 Ⅲ-10] 짐 더미 앞 학생 "다 가지고 갈 수 없을까?" "어떤 방법으로 짐을 챙기면 좋을까?"
- **(1) 전체 탐색(처음부터 끝까지 해 보기)**: 가장 단순, 모든 가능성을 적용해 처음부터 끝까지 탐색. 있으면 반드시 찾지만 데이터가 많을수록 오래 걸림. 예: 짐을 이것저것 챙기다가 개수·무게가 넘치면 멈춤 / 식물원에서 특정 식물 이름을 식물 백과사전 처음부터 끝까지 검색. [그림 Ⅲ-11] "꽃 이름을 찾아볼까?"
  - 지도서 ②: 완전 탐색(Exhaustive Search). 도서관 책꽂이 앞에서부터 찾기. (p.205)
- **(2) 분할 정복(나누어 해결하고 합치기)**: 크고 복잡한 문제를 작은 문제로 나누어 해결 후 합침, 잘 나누면 수행 시간 단축. 예: 짐을 옷·스마트 기기·세면도구 등 용도별로 나누고 개수·무게를 배정한 후 합침 / 수행 평가지를 10단위 번호대(0번대, 10번대, 20번대, 30번대)로 정리 후 합침. [그림 Ⅲ-12] 말풍선 "먼저 번호대별로 구분한 뒤 순서대로 정리해야지." "13번이니까 10번대에 두어야겠어."
  - 지도서 ③: Divide & Conquer. 핵심은 하위 문제가 원래 문제와 같은 방식으로 해결되는가. 정렬·검색에서 많이 쓰이나 중학교 범위가 아니므로 생활 예로 제시. 짐 챙기기는 용도별 무게 제한 + 가장 중요한 물건 선택으로, 수행 평가지 정리는 10번대로 그룹화 → 그룹별 병합 정렬 → 전체 병합으로 설명하면 좋음. (p.205)
  - 지식 플러스 "병합 정렬 문제" (p.205): ① 데이터를 반으로 최소 단위까지 나눔 ② 맨 밑에서부터 합치며 정렬. 예(그림 렌더링으로 확인, 숫자 9개): [7 2 5 9 6 4 1 3 8] → 나누기 [7 2 5 9 6] [4 1 3 8] → [7 2 5] [9 6] [4 1] [3 8] → [7 2] [5] [9] [6] [4] [1] [3] [8] → [7] [2] / 합치기 [2 7] → [2 5 7] [6 9] [1 4] [3 8] → [2 5 6 7 9] [1 3 4 8] → [1 2 3 4 5 6 7 8 9]. 그림 제목 "나누어 정복하기 방법"
- **(3) 규칙 찾기(규칙을 찾아서 해결하기)**: 규칙성·패턴을 찾아 해결 — 퍼즐 패턴 맞추기, 반복 순서에서 다음 예측. 예: 정해진 범위에서 소수를 찾을 때 1을 제외하고 2부터 작은 수 순서로 배수를 지워 감. [그림 Ⅲ-13] "11은 소수지!" 보조단 "소수: 1보다 큰 자연수에서 1과 자기 자신만을 약수로 가지는 수. 예 2, 3, 5, 7, 11"
  - 지도서 해설 ① (p.206): 규칙은 '배수 지우기'(2의 배수, 3의 배수, 5의 배수 … 순으로 지움). 퍼즐 풀기, 스도쿠, 피보나치 수열 등. 대표 문제 **하노이 탑**:
    - 문제: "기둥 A에 있는 원반을 모두 기둥 C로 옮기시오." (기둥 A·B·C, 원반 1·2·3)
    - 규칙 1 한 번에 하나의 원반만 움직임 / 규칙 2 가장 위의 원반만 움직임 / 규칙 3 아래에 작은 원반이 올 수 없음(큰 원반을 작은 원반 위에 놓을 수 없다는 뜻)
    - 문제 해결 패턴: ① 아래 원반을 제외한 나머지 원반을 목표와 다른 곳으로 보냄 ② 아래 원반을 목표 지점으로 보냄 ③ 다른 곳에 있던 원반들을 다시 목표 지점으로 보냄.
    - (참고, 제안) 원반 3개 최소 이동 횟수 7회(2ⁿ−1) — 원문에는 없음.
- **(4) 되추적(되돌아가서 다시 찾기)**: 해답을 찾다가 잘못된 것 같으면 되돌아가 다른 선택. 예: 바둑·체스에서 이동 방향에 상대 돌이 있거나 불리해질 때 원래 위치로 돌아와 생각 / 갈림길에서 잘못 가면 돌아와 다른 길로. [그림 Ⅲ-14] "이쪽으로 가면 내 말이 잡힐거야. 이전 단계로 돌아가서 다른 말을 잡아보자."
  - 이 밖에: 현재 상태에서 만족하는 것을 선택하며 해결하는 방법(탐욕), 예전에 해결한 방법을 기억해 활용하는 방법(동적 계획) — 괄호 안 용어는 정리자 보충 (제안).
  - 지도서 해설 ② (p.206): 백트래킹(Backtracking). 오목·바둑·장기에서 수를 물리는 경우. 대표 문제 틱택토(Tic-Tac-Toe), **N-Queen**:
    - 문제: "크기가 N×N인 체스판 위에 퀸 N개를 서로 공격할 수 없게 놓으시오." (그림은 4×4)
    - 풀이 과정: (1, 1)에 퀸을 놓으면 → (2, 3)에 놓으면 다음 줄에 놓을 수 없음 / (2, 4)에 놓으면 (3, 2)에 놓게 되어 실패함 → 되돌아감.
    - 백트래킹 방법: 트리 구조로 만들고 (1, 1) 밑의 (2, 1), (2, 2) 이후는 가지치기하여 그 밑의 트리를 만들지 않고 과정을 반복.
  - 지도서 해설 ① 전략 4가지 (p.205): 컴퓨터 과학에서 문제의 성격과 조건에 따라 여러 전략을 적용하며, 본문 4가지는 가장 기본적이고 가장 많이 사용되는 방법임을 지도.

#### 활동으로 쑥쑥 2 "일상생활에서 알고리즘 사례 찾아보기" (교 91쪽, p.199) [비교]

  2. "위의 알고리즘이 잘못될 경우 어떤 문제가 발생할지 적어 보자."
- **예시 답안** 1: 지진 대피 문자 발송, 심폐 소생술, 화재 대피, 네비게이션 길안내, 교통 신호 제어, 은행 거래 알고리즘. 2 (지도서 표):
  | 알고리즘 | 발생할 문제 |
  |---|---|
  | 지진 대피 문자 발송 | 제대로 대피하지 못해 피해 발생 |
  | 심폐 소생술 | 심정지가 온 사람에게 응급처치를 할 수 없음 |
  | 소화기 사용 | 불을 끄는 역할을 제대로 할 수 없음 |
  | 네비게이션 길 안내 | 원하는 목적지로 안내하지 못함 |
  | 교통 신호 제어 | 교통 혼잡·사고 가능성 증가 |
  | 은행 거래 | 입·출금 오류로 금융 사고 |
- **지도상의 유의점**: 수많은 사례를 탐색하며 중요성 생각 / 앞의 활동 플러스(p.198)와 연계 / 알고리즘을 잘못 알았거나, 순서대로 실행하지 못하거나, 알고리즘이 끝나지 않아 문제가 생긴 사례를 찾아 발표. (p.199)
- **활동 평가**: 다양한 알고리즘 사례를 나열할 수 있는가? / 잘못될 경우의 문제를 설명할 수 있는가?

#### 활동으로 쑥쑥 4 "적절한 문제 해결 전략 사용하기" (교 99쪽, p.207) [비교, 분석]
- 형태: 개인 선택 → 발표 / 도구: 종이(게임 시연은 교사가)
- **지도 목표**: 사례를 중심으로 적합한 전략을 선택하여 알고리즘을 설계할 수 있다.
- **제시(원문)**: "컴퓨팅 시스템과 1부터 100 사이의 임의의 수를 맞히는 업다운 게임을 한다면, 어떤 전략으로 정답을 맞히면 좋을지 생각해 보자."
- 보조단 정의: 업다운 게임 — 컴퓨팅 시스템이 임의의 수를 뽑아 놓고 입력값이 낮으면 '업', 높으면 '다운'이라고 알려 주어 맞히는 게임. (삽화 "업!")
- **단계(원문)**
  1. "어떤 방법으로 문제를 해결하는 것이 좋을까? 아래 예시 중에서 한 가지 방법을 선택해 보자." — 가 "1부터 순서대로 물어보면서 찾기" / 나 "계속 중간 숫자를 물어보면서 찾기" / 다 "무작위로 물어보면서 찾기"
  2. "자신이 선택한 방법의 알고리즘을 적어 보고, 문제 해결에 적절한 방법인지 생각해 보자." — 표: 알고리즘 | 문제 해결에 적절한 이유 (교과서 예 이유 "시간이 오래 걸려도 답을 찾을 수 있다.")
- **예시 답안 (알고리즘)**
  - 가: ① 1부터 순서대로 말한다. ② 정답을 확인한다. ③ 정답이면 멈추고 아니면 ①, ②번을 반복한다.
  - 나: ① 중간 숫자 50을 말한다. ② 업이면 위쪽의 중간 숫자(75)를 말한다. ③ 다운이면 아래쪽의 중간 숫자(25)를 말한다. ④ 정답을 확인한다. ⑤ 정답이면 멈추고 아니면 ②, ③, ④번을 반복한다.
  - 다: ① 아무 숫자나 말한다. ② 정답인지 확인한다. ③ 정답이면 멈추고 아니면 ①, ②번을 반복한다.
- **예시 답안 및 해설 (전략 비교)** (p.207): 각 전략으로 몇 번 만에 찾았는지 비교하도록 발문. 경우에 따라 '다'가 더 적은 횟수로 맞힐 수도 있음.
  - 가 = 전체 탐색: 업다운에서 보통 쓰지 않아 선택 가능성 매우 낮음, 다양한 전략 비교를 위해 제시. 정답이 있으면 반드시 찾지만 시간이 많이 걸림.
  - 나 = 분할 정복: 범위를 줄여 가며 찾음, 데이터가 많을 때 빠름. 숫자가 정렬되어 있지 않거나 구조가 복잡하면 사용하기 힘듦.
  - 다 = 무작위: 운이 좋으면 적은 횟수, 최악은 100개 모두. 이전 경험·지식과 함께 쓰면 효과적일 수 있음.
- **지도상의 유의점**: 학생들이 '나'가 적절함을 알고 고를 가능성이 높으나, 목적은 다양한 전략 적용이므로 '가, 나, 다'를 골고루 선택해 해결하도록 지도. 업다운 게임을 모르면 시범. 교과서와 다른 전략도 허용(p.177).
- **활동 평가**: 전략에 따라 알고리즘을 작성할 수 있는가? / 선택한 전략이 적절한 이유를 설명할 수 있는가?

#### 활동으로 쑥쑥 5 "문제 상황에 적합한 해결 방법을 설계하는 보고서 작성하기" (교 100쪽, p.208) [비교, 분석] [문제 기반 학습 / 프로젝트 기반 학습]

- **지도 목표**: 문제를 이해·분석하여 적합한 알고리즘을 작성하고 비교·분석할 수 있다.
- **문제 상황(원문)**: "방학을 맞아 친구들과 주말마다 재미있는 활동을 하기로 했다. 모둠별로 모여서 각자 하고 싶은 활동을 적고, 어떤 문제 해결 전략으로 활동을 선택할지 결정해 보자."

  - 1 문제 추상화하기

    - ② "문제를 분석하여 구조화해 보자." — 표: 친구 이름 | 선호 활동 | 핵심 요소(활동 시간 | 비용 | 빈 열 2개) — 빈 행 여러 줄
  - 2 알고리즘 작성 및 분석하기
    - ① "문제 해결에 적합한 전략을 선택하고 그 이유를 적어 보자." — 표: 문제 해결 전략 | 이유
    - ② "알고리즘을 작성해 보자." — 자유 칸
  - 3 "모둠별로 결과를 발표하고, 우리 모둠 결과와 비교해 보자." — 자유 칸

  - 상태: 초기 "방학 주말 활동 미정" / 현재 "축구, 영화보기" / 목표 "주말 활동 일정표 완성" / 핵심 요소 "좋아하는 취미, 소요 시간, 주말 횟수, 비용"
  - 구조화 표 (예시에서 핵심 요소 빈 열을 '장소', '날씨'로 채움):

    |---|---|---|---|---|---|
    | 하준 | 축구 | 2 | 0 | 운동장 | 중요 |
    | 다현 | 영화보기 | 3 | 11,000 | 영화관 | 상관없음 |
  - 전략: 규칙 찾기 / 이유: "핵심 요소의 중요성에 따라 규칙을 정해서 활동하기(비용이 적게 드는 것 우선으로 활동 등)"

  - ※ 핵심 요소는 모둠별로 다를 수 있으므로 토의·토론으로 결정.

- **활동 평가**: 문제를 이해·분석하여 추상화할 수 있는가? / 알고리즘을 작성할 수 있는가? / 적합한 전략을 선택하여 해결할 수 있는가?

### 형성 평가 · 핵심 개념 정리하기
- 핵심 개념 정리하기 (p.208): 알고리즘 = 문제 해결의 방법을 단계적인 절차로 표현한 것 / 표현 방법: 자연어(일상생활의 언어), 의사 코드(프로그래밍 언어로 변환하기 쉬운 형태), 순서도(정해진 기호) / 문제 해결 전략: 전체 탐색(처음부터 끝까지 해 보기), 분할 정복(나누어 해결하고 합치기), 규칙 찾기(규칙을 찾아서 해결하기), 되추적(되돌아가서 다시 찾기).
- 평가 도구: 수행 평가 — 지도서 273쪽 수행 평가 활동지 / 지필 평가 — 286~293쪽 (p.208)
- 형성 평가 (O/X) (p.208)
  1. 알고리즘은 문제 해결 방법을 단계적인 절차로 나타낸 것이다. → O
  2. 하나의 문제를 해결할 때에는 하나의 알고리즘만 필요하다. → X (다양한 알고리즘 가능)
  3. 효율적인 알고리즘은 수행 시간이 길더라도 정확한 답이 나와야 한다. → X (효율적 = 작업량 적고 수행 시간 짧음)

### 활동지 제작 아이디어 (제안)
1. **"순서가 바뀌면?" (3~4차시 도입)**: 라면 끓이기 단계 카드 6장을 섞어 배열 → "수프가 먼저야? 물이 먼저야?" → 닭 튀기는 로봇 알고리즘을 자연어로 쓰고, 순서를 하나 바꿨을 때 결과 예측 → 알고리즘 조건 5가지 체크리스트(입력·출력·명확성·수행 가능성·유한성)로 자기 알고리즘 점검. (제안)
2. **"한 문제, 세 가지 옷" (표현 방법)**: 덧셈 알고리즘 예시를 보여 주고 학생이 "두 수 중 큰 수 출력" 알고리즘을 자연어·의사 코드·순서도(판단 기호 포함) 3가지로 작성. 순서도 기호 빈칸 채우기 포함. (제안)
3. **"천만까지 더하면?" (5차시)**: 1~n 합 순서도 2개 비교표(반복 횟수: n=10, 100, 10,000,000일 때) → 캐릭터 발문 "n이 10,000,000이 된다면 수행 시간이 얼마나 차이 날까요?" → 음악 파일 100개 찾기 짝 활동(카드 100장 대신 1~32번 뒤집은 카드로 축소해 실제 클릭 수 기록). (제안)
4. **"업다운 전략 실험" (6차시)**: 짝과 업다운 게임을 가·나·다 전략으로 각 3판씩 하고 시도 횟수를 표로 기록 → 평균 비교 → 전략 이름(전체 탐색/분할 정복/무작위) 연결 → 하노이 탑(원반 3개) 또는 4-Queen 퍼즐로 규칙 찾기·되추적 체험. (제안)
5. **"방학 주말 계획 보고서" (7차시)**: 활동으로 쑥쑥 5 칸 구조 그대로 + 모둠 상호 평가표(전략대로 구현했는가/이유가 적절한가). (제안)

### 쉬어가기 "'큐리오시티' 화성 착륙 11주년" (교 102~103쪽, p.210~211)
- **교과서 소재(요약)**: NASA의 화성 이동형 탐사 로봇(로버) 큐리오시티(Curiosity·호기심), 2012년 8월 5일 화성 도착. 화성 기후의 생명 유지 가능성 확인, 대기·지질 연구. 지구에서 실시간 제어가 불가능해 사전에 여러 상황을 예측하고 작동하는 알고리즘이 필요했음. 말풍선 "화성 표면 탐사 임무 수행 이상 없음." 접속 안내 "접속해서 확인해요! https://eyes.nasa.gov/curiosity" — "큐리오시티를 간단하게 조작해 보자."
- **교 103쪽 "큐리오시티의 화성 탐사 알고리즘"** (부품별 기능 + 알고리즘 예):
  - 수평 유지 장치: 무게를 전달하고 수평 유지, 장애물에 부딪히면 무게를 다른 쪽으로 옮겨 넘도록 함. 알고리즘 "바위가 A 바퀴에 부딪히면 무게를 B 바퀴로 옮긴다."
  - 카메라 꾸러미(머리 부분): 촬영, 레이저로 토양·암석 견본 채집. 알고리즘 "필요한 암석을 찾으면 채집한다."
  - 전자 기기: 모터와 LED 제어, 컴퓨팅 시스템 탑재. 알고리즘 "일정 간격으로 전자 기기의 상태를 확인한다." 패스파인더 모형 장치 LED 표시 코드: 본부와 연결되었으면 LED에 '연결' 메시지 표현, 그렇지 않으면 '연결 안됨' 메시지 표현.
  - 코너 스티어링: 코너 바퀴를 정밀 회전, 제자리 회전 가능. 알고리즘 "90° 회전하기 — A 바퀴는 오른쪽으로 90° 회전, E 바퀴는 왼쪽으로 90° 회전"
- **지도서 해설 — 암석 수집 알고리즘** (p.210): ① 카메라와 센서 활용(고해상도 카메라·화학 분석 센서로 관찰) ② 데이터 분석(물이 흐른 흔적, 특정 화학 성분 지역 선택) ③ 암석 수집 결정(적외선 레이저로 표면을 증발시켜 구성 원소 조사, 현미경·분광기 활용, 특징이 발견되면 채취 결정) ④ 암석 채취(구멍을 뚫어 채취 후 분석 장치로 성분·구조 분석). 중요성: 사람이 직접 조종하지 않아도 스스로 판단, 시간과 에너지 절약, 효율적 데이터 수집.
- **활동 플러스 "알고리즘의 역할 토의하기"** (p.210)
  1. "화성에서 암석을 수집하려면 어떤 알고리즘이 필요할지 이야기해 보자." 예시: 주변 지형을 카메라로 스캔한다. → 특징 있는 암석이 있는 장소를 탐색하고 선정한다. → 이동 가능한 경로를 계산하고 목표 지점으로 간다. → 암석을 수집하여 분석한 뒤 데이터를 저장한다.
  2. "큐리오시티의 자동으로 작동하는 암석 수집 알고리즘이 없다면 어떤 문제가 생길지 이야기해 보자." 예시: 모든 암석을 조사하여 시간이 오래 걸림 / 불필요한 자료가 수집되어 저장 공간 부족 / 목표 지점을 설정하지 못하고 계속 이동 등.
- **지도서 해설 — 기술적 관점** (p.211): 카메라 꾸러미=큐리오시티의 '눈'(크기·모양·위치 인식, 조건에 맞는 암석 확인) / 수평 유지 장치=흔들림 없는 안정적 데이터 수집 / 전자 기기=LED는 어두운 곳에서 질감·색상 파악, 모터는 로봇 팔·도구 배치 / 코너 스티어링=울퉁불퉁한 지형 접근성.
- **활동 플러스 "큐리오시티 되어보기"** (언플러그드, p.211): "교실 바닥에 여러 가지 색종이를 흩뿌리고, '특정 색의 종이를 가장 빨리 찾을 수 있는 알고리즘'을 만들어 수행해 보자." 예시 — 빨간색 색종이 3장 찾아오기 알고리즘: 가장 왼쪽 구석에서 시작한다. / 앞에서부터 한 줄씩 색종이를 확인한다. / 빨간 색종이가 있으면 주워서 가방에 넣는다. / 목표한 3장을 찾으면 멈춘다.

- **활동으로 쑥쑥 1 예시 답안**: "개인 평균=개인 점수/과목 수" — 개인의 총점(과목 점수 합)을 과목 수로 나눠야 하므로 "개인 점수 총합/과목 수"가 정확함. (p.195)
- **차시 계획 지도서 쪽수**: 01 차시 계획에 "지도서 쪽수 192~195쪽"으로 되어 있으나 실습(앱 정리)·핵심 개념 정리·형성 평가는 p.196에 있음. (p.174)
- **중단원 지도 계획 쪽수**: 02 교과서 쪽수를 "89~101쪽"으로 표기(중단원 마무리 101쪽 포함), 차시별 지도 계획 합은 89~100쪽. 사소함. (p.192)
- **대단원 지도 목표 2의 문장부호**: "비교·분석하여. 사례를 중심으로" — 마침표가 잘못 들어간 듯(쉼표 또는 "비교·분석하고,"). (p.172)
- **성취 수준 표 C·D 중복**: p.209 [9정03-01]의 C와 D 칸 문장이 "문제의 초기 상태와 목표 상태의 의미를 설명하고, 제의 초기 상태와 목표 상태를 구분할 수 있다."로 사실상 동일하게 인쇄되었고, 두 칸 모두 "제의"는 "문제의"의 오탈자. (p.209)
- **빅오 그래프 표기**: 그래프 곡선 라벨에 O(nⁿ)이 있음(일반적인 교재 그래프는 O(2ⁿ)이나 O(n!)을 씀). 오류라기보다 비표준 표기. (p.203)
