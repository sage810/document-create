# ch04 데이터의 구조화와 분석
> 대단원: Ⅱ. 데이터 | 지도서 p.113~115(차시별 지도 계획), p.132~149(각론) | 교과서 62~79쪽 | 성취기준: [9정02-03], [9정02-04], [9정02-05] | 차시: 5차시 (01 데이터 구조화 2차시 + 02 데이터 분석 3차시)

## 핵심 한 줄
- 수집한 데이터를 목록·표·다이어그램으로 구조화하는 과정(데이터 파악 → 내용 요소 추출 → 분류·정리 → 구조화)을 익히고, '문제 정의 → 계획 수립 → 데이터 수집 → 데이터 구조화 및 분석 → 결론 정리'의 5단계로 스프레드시트·엔트리를 활용해 건강 일지·데이터 분석 프로젝트를 수행하는 중단원. (p.132)

## 중단원 도입 — 생각의 씨앗 심기
- 위치: 교 62쪽, p.132
- 도입 글 요지: 음식 섭취량과 운동량을 비교·분석하는 것은 건강 관리에 중요하다. 둘의 균형은 체중 조절, 영양 섭취 최적화, 건강 향상에 직접 영향을 준다. 식습관·운동 습관 데이터를 수집·구조화·분석하면 효과적인 건강 관리 계획을 세울 수 있다. (p.132)
- 만화 말풍선(원문, 대화 순서대로): "현대인에게 건강 관리는 매우 중요해." / "그래." / "건강 관리를 위해 식습관과 운동 습관을 점검하고 분석해 보자." / "일주일 동안 먹은 음식과 칼로리를 조사하고 운동 시간과 운동에 소모된 칼로리를 비교해 보자." / "이렇게 데이터를 쭉 나열하니 분석하기가 쉽지 않은데?" / "데이터를 종류별로 모아서 알아보기 쉽게 정리해 보는 것은 어떨까?" / "오! 이렇게 데이터를 정리하니까 한눈에 알아보기 쉽네." / "맞아. 분석하기 쉬워서 내가 살이 찌는 원인을 바로 찾겠어." (칸 순서는 텍스트 추출 순서로 복원)
- 교과서 발문(원문): "Q 하루 동안 섭취하는 음식의 총열량과 운동으로 소모되는 열량을 어떻게 정리하고 비교·분석해 볼까?" (교 62쪽)
- 지도 방안 요지: 우리 몸은 음식에서 칼로리 단위로 에너지를 얻고 활동하며 소모한다. 먹는 양보다 움직이는 양이 적으면 몸에 쌓여 체중이 늘 수 있으므로 섭취량과 운동량의 균형이 중요하다. 섭취량·운동량을 꾸준히 기록하고 구조화·분석해 건강한 생활을 유지하는 법을 학습하게 한다. (p.132)
- 예시 답안: 하루 먹은 음식의 종류·양을 기록 → 영양 정보로 음식별 칼로리 기록 → 운동 종류·시간 기록 → 운동별 소모 칼로리 기록 → 구조화해 칼로리 차이를 계산하고, 남는 칼로리가 너무 많거나 적지 않게 식단·운동 계획을 조정. (p.132)
- 이 도입은 소단원 02의 실습 "섭취한 음식과 운동량을 관리하여 건강 일지 만들기"와 창의·융합 프로젝트 "나의 건강 관리 일지 만들기"로 이어진다.

  - ➋ 데이터 구조화 과정 알아보기: 데이터 파악 → 내용 요소 추출 → 내용 요소 분류 및 정리 → 다양한 형태의 구조화.
  - ➌ 데이터 구조화의 종류: 개념·장단점·예
    - 목록(리스트) — 예: 층별 안내도, 통화 기록, 레시피. 장점: 구조가 간단. 단점: 내용 요소 간 관계가 복잡하면 관리가 어려움.
    - 표(테이블) — 예: 주소록, 출석부, 시간표, 좌석배치표. 장점: 이해·비교가 쉬움. 단점: 구조 변경이 어렵고, 관련 데이터가 여러 표에 걸치면 중복 데이터 발생.
    - 다이어그램 — 계층형, 그래프형, 차트형. 장점: 관계를 한눈에. 단점: 지나친 단순화로 중요한 세부가 누락되거나, 설계가 부적절하면 잘못 해석될 수 있음.
  - ➍ (활동으로 쑥쑥 5) 가위바위보 대진표 만들기 — 나만의 대진표를 만들고 발표·토론.
  - ➎ (활동으로 쑥쑥 6) 동아리 관리 시스템 구조화하기 — 지문에 따라 다양한 형태로 구조화.
  - 유의점: 다양한 사례(일기 예보, 시간표, 지하철 노선도 등)로 이해를 높임 / 급식 메뉴 선호도 조사 사례로 구조화 과정을 설명 / 학번은 학년·반·번호를 차례로 나열해 구조화한 데이터임을 알리고, 주변에서 구조화가 잘 된 사례를 발표하게 함.
- **정리**: 활동 결과물 공유·피드백 / 데이터 구조화 학습 내용 정리 / 다음 차시 예고. 유의점: 형성 평가로 스스로 정리.

### 전개 — 본문 흐름과 핵심 개념
#### 1 데이터 구조화 (교 63~64쪽, p.133~134)
- 도입 문장 요지: 물건을 성격·종류·크기를 고려해 정리하면 찾기 쉽듯 데이터도 정리가 필요하다. (교 63쪽)
- 정의: 데이터 구조화는 전달하려는 데이터의 내용 요소들을 특성에 맞게 정리·배열해 통일된 모양으로 표현하는 것. 정리가 잘된 도서관에서 책을 찾기 쉬운 것과 같다.
- [그림 Ⅱ-11] 구조화 사례: 사례 1 가방 정리하기 / 사례 2 컴퓨팅 시스템의 아이콘/폴더 정리하기(이미지·문서·영화 폴더, 말풍선 "파일을 폴더로 정리해요.")
- 보조단 QnA(원문): "Q. 구조화가 필요한 이유는 무엇일까요?" — "A.전달할 내용이 많고 핵심 내용 간의 관계가 복잡할수록 내용을 효율적으로 기억하거나 더 쉽고 빠르게 전달할 수 있기 때문에 구조화 과정이 필요해요."
- 지도서 해설 ① 데이터 구조화가 필요한 이유 (p.133): 쉽게 찾을 수 있음(학번으로 학생 찾기) / 내용 요소 간 관계 이해 / 추가·수정·삭제 등 효율적 관리 / 평균·최댓값·최솟값 등을 쉽게 찾아 분석이 쉬움 → 의사결정에 도움 / 오류를 줄여 신뢰성↑.
- 구조화가 잘된 데이터는 누구나 의미를 쉽게 파악하고 체계적으로 관리할 수 있지만, 그렇지 못하면 의미 전달이 어렵고 잘못된 의미를 전할 수 있다. (교 64쪽)
- 학번 사례: 학년·반·번호를 차례로 나열한 구조화 데이터 → 성적 처리, 학교생활기록부 작성, 동명이인 구분 등에 효율적. (교 64쪽)
- [그림 Ⅱ-12] 데이터 구조화 과정 — 급식 메뉴 선호도 조사 예 (그림 확인, 교 64쪽)
  1. 데이터 파악: "수집한 데이터를 파악한다." (학생들이 설문지를 살펴보는 장면)
  2. 내용 요소 추출: "꼭 필요한 내용 요소를 뽑아낸다." — 카드: 학년, 급식 선호도(상·중·하), 영양소, 반찬류, 밥류
  3. 내용 요소 분류 및 정리: "뽑아낸 내용 요소를 비슷한 것끼리 분류하고 정리한다." — 묶음 예: '우리 학교 학생들이 좋아하는 밥'(학년·밥류·급식 선호도), '우리 학교 학생들이 좋아하는 반찬'(학년·반찬류·급식 선호도), '우리 학교 영양'(반찬류·밥류)
  4. 다양한 형태의 구조화: "내용 요소 간의 관계를 정리하여 데이터를 가장 잘 표현할 수 있는 형태로 만든다." — 막대그래프(반찬 선호), 원그래프(밥 선호), 계층도
- 지도서 해설 ① 학교에서 볼 수 있는 데이터 구조화 사례 (p.134): 학생 생활 기록부(개인 정보·학적·성적·출석·독서·행동 발달) / 시간표(학급별·교사별 표) / 출석부(일일·월별 통계표) / 도서관 도서 배치(종류별 배치, 검색·대여 시스템) / 성적표 / 식단 관리표(영양 정보·급식 계획·식자재 주문) / 학교 안내도(층별 안내) / HR 조직표(회장·부회장·총무·부서).

#### 2 데이터 구조화의 종류 (교 65~66쪽, p.135~136)
- 구조화 전에 데이터의 종류·특징·활용 목적을 알아보고 효율적인 표현 방법을 파악하는 것이 중요. (교 65쪽)
- (1) 목록(리스트): 건물 층별 안내도, 시간별 일정 목록처럼 일정한 기준에 맞춰 순서대로 나열. 구조가 간단하고 일관성이 있을 때 사용. 관계가 복잡하면 체계적 관리가 어렵다. [그림 Ⅱ-13]
  - 지도서 해설 ②: 예 층별 안내도, 통화 기록, 레시피 / 장점: 쉽고 빠르게 표현, 수정 편리 / 단점: 관계가 복잡하면 관리가 어려움. (p.135)
- (2) 표(테이블): 학급 시간표, 용돈 기입장, 아파트 단지 구조, 전화번호부처럼 서로 다른 두 기준(세로줄·가로줄)으로 나누어 표현. 중복되는 내용 요소를 정리해 효율적으로 구조화. [그림 Ⅱ-14]
  - 지도서 해설 ③: 예 주소록, 출석부, 시간표, 좌석 배치표 / 장점: 이해·수정·비교 쉬움 / 단점: 엄격한 행·열 구조라 구조 변경이나 새 데이터 유형 추가가 어려움, 관련 데이터가 여러 표에 걸치면 중복 발생. (p.135)
- (3) 다이어그램: 그림·도형·점·선·화살표로 데이터를 비교하거나 관계를 이해하기 쉽게 그림으로 표현. 혈액형 분포 비율, 지하철 노선도, 가계도, 별자리, 화학 분자 구조 등 상호 관계를 시각적으로 표현하는 데 유용. (교 66쪽)
  - [그림 Ⅱ-15] 우리나라 혈액형 분포 비율(도넛 차트): A형 34%, O형 28%, B형 27%, AB형 11% (출처: 서울아산병원 임상 병리과 자료)
  - [그림 Ⅱ-16] 다양한 다이어그램의 예: 지하철 노선도, 가계도(할아버지·할머니–고모부·고모·삼촌·숙모·아빠·엄마 / 외할아버지·외할머니–외삼촌·외숙모·이모부·이모 / 고종사촌·사촌·나·누나·외사촌·이종사촌)
  - 지도서 해설 ①: 장점 — 시각적이라 이해가 쉽고 관계를 한눈에 / 단점 — 단순화로 세부 누락, 부적절한 설계나 잘못된 해석 가능 / 종류: 계층형(수준별 분류, 예 1반~4반 토너먼트 → 우승) / 그래프형(내용 요소 간 상호 관계를 선으로 연결) / 차트형(흐름을 단계별로 나타내는 플로차트, 통계·비교를 나타내는 막대그래프·원그래프). (p.136)
  - 지식 플러스 — 마인드맵: 중심 주제에서 방사형으로 관련 아이디어를 연결하는 구조, 브레인스토밍 도구로 창의력·기억력 향상에 도움. (p.136)

- 해설 요지: 스포츠에서 데이터를 분석하는 이유 — 선수 강약점 파악과 맞춤형 훈련, 상대 팀 경기 분석으로 전략 수립, 부상 예방·관리, 잠재 선수 발굴. 스포츠 외에 어떤 분야에서 분석을 활용할지 생각해 보게 한다. (p.138)

### 전개 — 본문 흐름과 핵심 개념
- 도입 문장 요지: 문제 해결을 위해서는 데이터를 수집·구조화하고 그것을 바탕으로 분석해 의미를 해석해야 한다. (교 68쪽)
#### 1 데이터 분석과 활용 (교 68쪽, p.138)
- 문제를 해결하고 더 나은 의사 결정을 하려고 데이터를 분석·활용한다. 방대한 데이터와 신기술이 숨은 가치를 찾아 새 지식 발견을 돕는다.
- 예: 환자 데이터 → 질병 원인·치료 방법 연구 / 교육 데이터 → 최적의 교육 방법 / 시장 분석 → 홍보 전략 / 금융 데이터 → 투자 전략 / 팀 전략 분석 → 스포츠 성과.
- 지도서 해설 ① 다양한 분야에서의 데이터 분석 활용(표, p.138): 스포츠(선수·상대 팀 분석으로 경기 전략·성과) / 환경(대기·수질 오염 분석으로 대처 방안) / 국토 개발(교통 흐름·인구 분포 고려 도로 개선) / 경제(투자 전략·마케팅 전략) / 의료(사람 특성별 효과적 치료) / 교육(학생 수준에 맞는 교육).

#### 2 데이터 분석하기 (교 69~70쪽, p.139~140)
- 정의: 데이터 분석은 주어진 문제를 해결하기 위해 필요한 데이터를 수집·분석해 문제에 대한 답을 찾는 과정. (교 69쪽)
- 데이터를 활용한 문제 해결 과정(그림, 5단계): ① 문제 정의 → ② 계획 수립 → ③ 데이터 수집 → ④ 데이터 구조화 및 분석 → ⑤ 결론 정리.
- 지도서 해설 ② 데이터 분석 시 주의할 점 (p.139): 데이터 품질(오류·결측치·이상치를 사전 처리) / 분석 방법의 선택(목적에 맞는 도구·기법) / 데이터 해석(모든 변수·상황 고려, 주관 개입 주의, 다양한 해석 가능성 인지) / 법적 및 윤리적 고려(개인 정보 보호, 저작권).
- 지도서 해설 ③ 데이터 전처리(Data preprocessing) (p.139): 결측치 처리(누락 정보를 다른 값으로 채우거나 해당 데이터 제거) / 이상치 제거(크게 벗어난 값은 통계를 왜곡하므로 제거하거나 평균값·중앙값·최빈값으로 대체) / 데이터 정규화(범위를 일정하게 조정) / 데이터 형식 통일(예: 날짜 형식 DDMMYYYY).

- 형태: 모둠 / 도구: 인터넷 검색, 워드 프로세서 / 아이콘: 분석, 표현

- 단계(원문): 1 "인터넷 검색으로 데이터를 구조화한 데이터를 찾아보자." 2 "데이터가 지닌 의미와 결과를 모둠원끼리 토론하여 분석해 보자." 3 "분석한 결과로 기사를 작성해 보자." 4 "작성한 기사를 아나운서처럼 발표해 보자."
- 교과서 예시(이미지 출처: 과학기술정보통신부, 2022년 스마트폰 과의존 실태 조사): 과기정통부와 한국지능정보사회진흥원이 만 3~69세 스마트폰 이용자를 조사한 결과 23.6%가 과의존 위험군, 전체는 전년 대비 0.06% 감소했으나 청소년은 매년 상승세. 아나운서 멘트 형식("*** 기자로부터 자세한 이야기를 들어 보겠습니다. *** 기자, 나와 주십시오.")
- 예시 답안(지도서, 초중고 학생 수 그래프 분석): 2 분석 — 1970년 대비 2023년 초등학생 약 55% 감소, 중학생은 비슷, 고등학생은 2배 가까이 증가 / 2000년 대비 2023년 초 약 35%, 중 약 30%, 고 약 40% 감소. 3 기사 — 교육부·한국교육개발원 조사, 1970년 약 574만 명이던 초등학생이 2023년 약 260만 명으로 반토막. 중고생은 의무교육 확대 등으로 늘다가 최근 감소. 주원인은 저출산. 학생 수는 출산율·경제 여건·교육 정책과 밀접해 단순 통계 이상의 의미를 지니며 한국 교육 발전 방향을 결정짓는 요소.
- 지도 목표: 분석 목적에 맞게 구조화가 잘된 데이터를 선별하고 그것에 기반해 객관적으로 해석·분석할 수 있다.
- 지도상의 유의점: 자기 생각·의견 주장보다 데이터를 기반으로 분석해 신뢰성과 정확성을 주도록 지도.
- 활동 평가 항목: "데이터를 분석하기 좋도록 구조화가 잘된 데이터를 선별할 수 있는가?" / "데이터가 주는 의미를 정확히 해석하고 데이터를 기반으로 기사를 작성하였는가?"

#### 선택 활동 "데이터 분석 프로젝트" (교 72~73쪽, p.142~143) — 문제 기반 학습
- 형태: 모둠 / 도구: 인터넷 설문(구글 드라이브), 스프레드시트·프레젠테이션·워드 프로세서·그래픽 프로그램, 포스터
- 지시문(원문): 1 "데이터 분석 프로젝트는 해결해야 하는 문제를 정의하고, 필요한 데이터를 수집·분석하여 의미 있는 결론을 정리하는 과정이다. 다음과 같은 절차에 따라 데이터 분석 프로젝트를 완성해 보자." 2 "완성한 데이터 분석 프로젝트를 포스터로 만들고 발표해 보자."
- 추천 주제: 민주 시민 교육, 환경 보호, 진로 탐색, 정보 통신 윤리, 다문화 이해 등 — 데이터를 수집·분석하기 좋은 주제.
- 단계와 체크 사항(원문)
  - 단계 1 문제 정의: "주제를 정하고 해결하려고 하는 문제가 무엇인지 정의한다." 체크: "목표를 명확하게 설정해 주제를 제시하였는가?" / "데이터로 해결할 수 있는 문제인가?"
  - 단계 2 계획 수립: "필요한 데이터가 무엇인지 어떤 방법으로 수집할 것인지 계획을 수립한다." 체크: "문제를 해결할 수 있는 데이터를 수집하였는가?"
  - 단계 3 데이터 수집: "필요한 데이터를 수집하여 분류한다." 체크: "출처가 명확하고 신뢰할 수 있는 데이터인가?"
  - 단계 4 데이터 구조화 및 분석: "데이터를 분석하기 쉬운 형태로 구조화하면서 데이터의 패턴, 관계, 특성 등을 분석한다." (수집한 데이터에 맞는 응용 소프트웨어로 분류·구조화) 체크: "수집한 데이터의 의미를 알아보기 쉽게 구조화하였는가?"
  - 단계 5 결론 정리: "데이터 분석 결과를 간략하게 정리하고, 문제 해결 방법을 제안하거나 논리적인 주장을 한다." 체크: "문제 해결에 적합한 결론을 도출하였는가?"
- 지도서 해설(단계별, p.142~143)
  - 단계 1 주제 선정 기준: 확실히 정의할 수 있어 관련 데이터를 쉽게 모을 수 있는 주제 / 흥미롭고 창의적인 주제 / 이해가 쉽고 명백한 결론을 포함할 수 있는 주제. 예시 답안: "정보 기기는 학습에 도움이 될까?" — 정보 기기 활용 수업이 늘지만 반대 의견도 있어 우리 학급 학생 인식을 조사.
  - 단계 2: 적절한 수집 방법 선택, 모둠 역할 분담·일정 수립. 예시: 구글 드라이브로 설문 항목 결정(학습에 쓰는 정보 기기 종류, 학습 시간에 이용하는 시간 등).
  - 단계 3: 직접 설문·실험 또는 기존 데이터. 통계청·공공 데이터 포털 등 국가 기관, 언론사 보도·통계 데이터를 쓰면 신뢰도↑.
  - 단계 4: 직접 또는 응용 소프트웨어로 분석, 특성에 맞는 그래프·표 선택.
  - 단계 5: 조사·분석 내용, 문제 해결 과정, 결과와 주장 포함. 예상외의 사실·시사점을 곁들이면 좋음.
- 포스터 예시 "정보 기기는 학습에 도움이 될까?" (교 73쪽)
  - [주제 선택의 이유] 학교가 정보 기기 학습을 지원하지만 집중이 안 된다는 의견과 즉시 정보 검색이 가능하다는 의견이 공존 → 학생 대상 분석.
  - [수집 방법] 설문 대상 우리 반 30명, 인터넷 설문 조사.
  - [정보 기기 사용 실태] 학습에 사용하는 기기: 태블릿 67%, 노트북 17%, 스마트폰 13%, 사용 안 함 3% / 학습 이용 시간: 1~2시간 12명(최다), 2~3시간 10명, 1시간 미만 5명, 3시간 이상 2명, 기타(날마다 달라 평균 어려움) / 사용 이유(중복): 수행 평가 30명(최다), 다음은 인터넷 강의 수강, 필기·연습장, 기타(여가·어학 공부).
  - [긍정적인 의견] 도움이 된다 67% / 도움 분야: 보고서 작성, 지식 검색, 발표 작품 제작, 기타 노트·일정 관리.
  - [부정적인 의견] 도움이 안 된다는 이유로 게임·동영상 유혹 / 학습에만 쓰기 어려워 집중력이 떨어지고 다른 용도로 쓰게 된다는 의견이 최다.
  - [결론] 정보 기기는 학습에 유용하지만 사용에 주의해야 한다. 수행 평가에 가장 많이 쓰고 사용 시간은 1~2시간이 최다(오래 쓰면 방해될까 적절히 쓰는 듯). 기회가 되면 디지털 교과서를 쓰는 교과와 아닌 교과의 통계도 분석하고 싶다.
- 지식 플러스 — 전국 학생 통계 활용 대회: 통계청이 매년 개최, 주제 선정 → 통계 데이터(그래프·표)로 요약 → 다양한 관점에서 분석·해결하는 과정을 시각적으로 보여 주는 통계 포스터를 평가. (p.142)
- 지도 목표: 데이터 분석 전 과정을 데이터 기반 프로젝트형 문제 해결로 경험.
- 지도상의 유의점: 학생 수준에 따라 시각화에 워드 프로세서·스프레드시트·프레젠테이션 등 다양한 소프트웨어 활용.
- 평가 후 지도 방법: "문제 해결에 필요한 데이터를 수집하고 목적에 따라 효과적인 형태로 구조화할 수 있는가?" → 분석 과정을 이해하고 필요한 데이터를 수집 / 목적에 맞게 다양한 형태로 구조화. "수집한 데이터 간의 관계를 파악하고, 데이터에 기반하여 결론을 도출할 수 있는가?" → 소프트웨어나 프로그래밍으로 얻은 결과의 가치를 인식하고 데이터를 기반으로 주장을 논리적으로 설명.

- 소재: 멋진 그래픽·애니메이션과 VR·AR 효과로 시각적 경험을 풍부하게 하는 분야. 사례 사진: 실내 움직임·가벼운 운동으로 건강 관리까지 하는 VR 게임 / 건축가·디자인 전문가가 AR로 만든 가상 건물·공간을 탐구·디자인.
- 직업: 그래픽 디자이너·애니메이터(컴퓨터로 그림·애니메이션 제작, 게임·영화 그림) / UI/UX 디자이너(버튼·화면 배치로 프로그램·앱을 편하고 예쁘게) / 게임 아티스트(게임 속 그림·모습·세계 디자인).
- 교과서 필요한 역량: 창의성, 스토리텔링, 그래픽 디자인, 디자인 감각, 사용자 경험 이해, 피드백 수용 능력.
- 지도서 보충: UI는 화면의 버튼·메뉴, UX는 얼마나 쉽게 쓰는지 / 그래픽 디자이너는 포스터·로고·광고 / 게임 아티스트는 캐릭터·배경·아이템, 3D 모델 / 필요한 역량: 창의력, 시각적 감각, 기술적 능력, 프로그래밍 지식, 3D 모델링, UX/UI 이해, 문제 해결, 커뮤니케이션·협업 / 관련 전공: 디지털 미디어 디자인학과, 애니메이션 학과, 컴퓨터 그래픽스학과, 인공지능학과, 컴퓨터 공학과, 게임 디자인 학과 / 참고: 워크넷, 위키백과, 커리어넷. (p.144)

### 쉬어가기 — 가로세로 퍼즐 (교 76쪽, p.146)
- 지시문(원문): "다음 문제를 읽고 낱말 퍼즐을 완성해 보자."
- 가로 열쇠: 1 측정·관찰·설문으로 얻은 단순한 사실이나 값 → **데이터** / 2 0과 1로만 표현되는 코드 → **이진 코드** / 3 셀에 입력해 분석·통계·그래프를 하는 표 계산 프로그램 → **스프레드시트**
- 세로 열쇠: 1 문제를 해결하려 데이터를 수집·분석해 답을 찾는 과정 → **데이터 분석** / 2 수학적인 정보로 이미지를 표현하는 방식 → **벡터 이미지** / 3 미국 표준화 협회에서 만든 표준 코드 → **아스키코드** / 4 문자·그림을 배치해 보고서 형식 문서를 가공하는 문서 편집 프로그램 → **워드 프로세서** / 5 8비트로 구성된 저장·처리 단위 → **바이트**
- 지도서 추가 설명: 각 낱말의 보충 정의(데이터는 의사 결정·분석의 기초 자료, 이진 코드는 모든 데이터가 변환되는 기본 형식, 스프레드시트 예 Excel·Google Sheets, 벡터는 해상도에 영향받지 않음, 아스키코드 7비트, 워드 프로세서 예 Word·Google Docs, 바이트는 문자 하나를 표현할 수 있는 최소 단위). 지도서는 세로 열쇠 번호를 4~8로 매겨 교과서 번호(1~5)와 다름.
- 활동 플러스 "네모 네모 로직": 가로·세로 숫자를 보고 연속 칸을 칠해 그림을 완성하는 퍼즐. 규칙 — 1. 숫자만큼 연속된 칸을 칠한다 2. 숫자와 숫자 사이는 적어도 한 칸 띄운다 3. 숫자 순서와 칠한 칸 순서가 일치해야 한다. 문제·정답 격자는 그림으로만 제시(확인 불가(그림), 칸별 정답 생략). 비트맵(픽셀) 개념과 연결 가능 (제안).

### 창의·융합 프로젝트 "나의 건강 관리 일지 만들기" (교 77~79쪽, p.147~149) — 탐구 기반 학습
- 위치·형태: 중단원 2 끝(대단원 마무리 직전). 모둠(활동 순서 01 역할 정하기 → 02 프로젝트 방향 정하기 → 03 프로젝트 수행하기 → 04 보고서 작성하기 → 05 발표하기) / 도구: 엔트리(데이터 분석 블록, 테이블·차트) / 실습 파일: T셀파 "(엔트리) 77~79쪽 프로젝트 나의 건강 관리 일지.ent", QR https://dtqr.kr/WNb7XmV
- 수업 형태: 프로젝트 기반 학습, 디자인 기반 학습 / 준비물: 교사 컴퓨터·엔트리 실습 환경, 학생 컴퓨터·엔트리 회원 가입
- 지시문(원문): "엔트리를 활용해 섭취한 음식의 열량(kcal)과 운동량을 표로 기록해 보자. 또, 차트로 시각화하여 관리하는 프로그램을 만들어 보자." 말풍선: "프로그래밍으로 건강 관리를 하면 데이터의 접근성이 좋고, 언제 어디서나 사용 가능해요. 또한 내가 필요한 기능을 추가하여 맞춤형 앱을 만들 수 있어요."
- 지도 목표: 엔트리의 데이터 분석 기능으로 데이터를 표로 기록하고 차트로 시각화할 수 있다.
- 단계 1 배경과 오브젝트, 변수 설정하기
  1. [배경 디자인하기]–[오브젝트 추가하기]로 배경 '나의 공책' 선택
  2. [제목 쓰기]–[오브젝트 추가하기]–[글상자] 탭에서 '나의 건강 관리 일지' 추가, 글자색·배경색 설정
  3. 오브젝트 추가·배치: 글상자 '월', '/', '일', '?', '?', 'kcal' / 인터페이스 '둥근 버튼(앞/뒤)' / 음식 '밥공기' / 사람 '소놀 달리는 사람' / 차트 모양은 [파일 올리기] 또는 새로 그리기
  4. '속성'에서 변수 추가(기본값 0, 화면에서 감춤): 행 번호, 월, 일
- 단계 2 데이터 추가 및 구조화하기
  1. [데이터 분석]–[테이블 불러오기]–[테이블 추가하기]–[새로 만들기]로 데이터 입력 후 저장 — 테이블 '건강 관리 일지' 데이터셋(그림 확인):

  | 월 | 일 | 음식 섭취 열량(kcal) | 운동 소모 열량(kcal) |
  |---|---|---|---|
  | 5 | 1 | 2960 | 380 |
  | 5 | 2 | 2090 | 560 |
  | 5 | 3 | 1850 | 180 |
  | 5 | 4 | 1920 | 0 |
  | 5 | 5 | 2040 | 0 |
  | 5 | 6 | 3610 | 800 |
  2. [테이블]–[차트] 탭에서 원하는 모양(꺾은선 등)의 차트를 만들어 저장 — 두 계열(음식 섭취 열량, 운동 소모 열량) 꺾은선.
- 단계 3 프로그래밍하기 (핵심 블록 구조, 그림 확인)
  1. 배경 오브젝트: [시작하기 버튼을 클릭했을 때] → [행 번호 를 1 (으)로 정하기]
  2. 둥근 버튼(뒤) — 회전 방식을 바꿔 모양을 뒤집음: [오브젝트를 클릭했을 때] → [만일 (행 번호 값 > 1) (이)라면] → [행 번호 에 -1 만큼 더하기]. 둥근 버튼(앞): [오브젝트를 클릭했을 때] → [만일 (행 번호 값 < 테이블 건강 관리 일지 의 행 개수) (이)라면] → [행 번호 에 1 만큼 더하기]. 조건을 쓰는 이유: 테이블 첫 행과 마지막 행에서 행 번호가 범위를 벗어나지 않게 하기 위함.
  3. 월·일 오브젝트: [시작하기] → [계속 반복하기] → [(테이블 건강 관리 일지 의 (행 번호 값) 번째 행의 월 값) (이)라고 글쓰기] (일도 같은 구조). 계속 반복하는 이유: 행 번호가 바뀔 때마다 계속 글을 다시 쓰기 위함. ※ 행 번호는 [데이터 분석] 테이블의 행 번호.
  4. ?, ? 오브젝트(음식 섭취·운동 소모): [시작하기] → [계속 반복하기] → [만일 (행 번호 값 = 1) (이)라면 → '?' (이)라고 글쓰기 / 아니면 → (테이블의 행 번호 번째 행의 음식 섭취 열량(kcal) 값) (이)라고 글쓰기] (운동 소모 열량도 같은 구조). 행 번호가 1일 때 '?'로 두는 이유: 처음 글자 '?'를 나타내기 위함. (테이블 1행이 머리글인 구조로 해석됨)
  5. 차트 오브젝트: [오브젝트를 클릭했을 때] → [테이블 (건강 관리 일지) 의 (차트) 차트 창 열기]
- 단계 4 레벨 업하기 — "데이터를 추가하거나 삭제할 수 있는 기능을 넣어보자."
  - 추가(+) 오브젝트: [클릭했을 때] → [테이블 건강일지 에 행 추가하기] → ["월을 입력하세요" 묻고 대답 기다리기] → [테이블의 (행 개수) 번째 행의 월 을(를) 대답 (으)로 바꾸기] → 일, 음식섭취열량(kcal), 운동소모열량(kcal)도 같은 방식 → [테이블 건강일지 을(를) 현재 상태로 남기기](추가 데이터를 [데이터 분석]–[테이블]에 반영).
  - 삭제(×) 오브젝트: [클릭했을 때] → [변수 행번호 보이기] → ["몇 번째 행을 삭제할까요?" 묻고 대답 기다리기] → [테이블 건강일지 대답 번째 행 삭제하기] → [변수 행번호 숨기기] → [현재 상태로 남기기]. 단, 마지막 행을 삭제할 때 주의.
  - 나만의 평가 점검: "표를 만들어 평가해 보세요." (교과서 Link 238쪽)
- 엔트리 화면 설명(지도서): ① 오브젝트(캐릭터·사물·글상자·배경 등 명령으로 움직일 수 있는 것) ② 오브젝트 선택 → 블록 꾸러미에서 블록 조립소로 끌어와 조립 ③ 실행 화면 [▶] 클릭.
- 지도상의 유의점: 엔트리 기초 사용법을 간단히 설명한 뒤 진행 / 개성 있는 화면을 설계할 학생은 미리 오브젝트를 디자인하도록 사전 안내.

## 오개념 · 지도 유의점 모음
- 가계도 동기 유발 시 가정 환경을 고려해 학급 HR 조직도 등 대체 주제를 허용. (p.113)
- 목록은 관계가 복잡한 데이터에 부적합, 표는 구조 변경이 어렵고 여러 표에 걸치면 중복 발생, 다이어그램은 단순화로 세부 누락·잘못된 해석 위험 — 각 형태의 단점까지 함께 지도. (p.113, p.135~136)
- 지하철 노선도·가계도는 표가 아니라 다이어그램이 효율적(시험 대비 02-06). (p.169)
- 수집 후 정리 없이 구조화하면 정보가 얽히고, 구조화 방식이 바뀌면 전달 의미가 달라질 수 있음. (p.145)
- 결론은 분석 결과에 근거, 선입견 배제, 실행 가능한 제안 — 의견 주장보다 데이터 기반 기사 작성. (p.140, p.141)
- 전처리(결측치·이상치·정규화·형식 통일)와 분석 시 법적·윤리적 고려(개인 정보, 저작권). (p.139)
- 셀 병합은 보기 좋지만 정렬·분석을 제한할 수 있음(ch03 p.128과 연결) — 건강 일지 ② 단계는 병합을 쓰므로 원자료 시트와 분리해 쓰게 함 (제안).
- 데이터 공유는 "무조건 하지 않는 것"이 아니라 신중하게. 합계·평균 처리는 스프레드시트. (p.145)
- 창의·융합 프로젝트는 엔트리 선행 수준에 따라 Ⅲ 단원 이후로 미룰 수 있음. (p.114)

## 원문 오류 의심
- p.135 지도서 해설 ③ 표 정의 "세로줄(행)과 가로줄(열)" — 행은 가로줄, 열은 세로줄이므로 괄호가 뒤바뀜.
- p.140 건강 일지 단계 4 ② 잉여 칼로리 수식 "=F4-(I4:I12)" — 범위를 괄호로만 묶어 SUM이 빠짐. =F4-SUM(I4:I12)가 의도로 보임. 같은 쪽 ① 표의 5월 3일 "=SUM(E27:E36)"은 다른 날과 달리 E열(운동 종류 열)을 참조하고 있어 D열의 오기로 보임. 또 ①의 5월 1일 운동 소모 범위 =SUM(G4:G12)는 음식 범위(D4:D14)와 끝 행이 다름.
- p.134 활동 플러스 시험 공부 계획서 예시 "필요한 시간: 단원당 45시간씩" — 중학생 기준 비현실적, '4~5시간'의 오기 가능성.
- p.141 지식 플러스 AVERAGE 설명 "A1부터 A10까지의 값의 합의 평균 구하기" — '값의 평균'으로 고쳐야 자연스러움. p.149 "테이블 블러오기" 오탈자(불러오기).
- p.145 중단원 마무리 스스로 점검하기 "데이터 분석 및 구조화"는 본문 단계명 "데이터 구조화 및 분석"과 순서가 뒤바뀜.
- p.146 쉬어가기 지도서 추가 설명의 세로 열쇠 번호(4~8)가 교과서 퍼즐 번호(세로 1~5)와 다름. 또 바이트를 "문자 하나를 표현할 수 있는 최소 단위"라 했으나 본문은 한글 등은 2바이트(유니코드)로 표현됨 — 단정적 표현.
- p.109 대단원 지도 계획의 02 데이터 분석 칸은 수업 방법과 평가 방법 구분이 모호(서술·논술이 수업 방법 칸에 있는 것처럼 배치).
- p.115 성취기준 [9정02-05] 문장 끝이 "해결할 수 있다."로, p.109의 "해결한다."와 다름.
- p.148 엔트리 단계 3 ④의 "행 번호 값이 1일 때 '?'" 처리는 테이블 1행이 데이터(5월 1일)이면 첫날 값을 숨기게 됨. p.148 테이블 그림은 1행이 머리글(월·일·…)로 보여 의도는 맞을 수 있으나, 단계 2 차트와 행 번호 기준이 헷갈릴 수 있음.
