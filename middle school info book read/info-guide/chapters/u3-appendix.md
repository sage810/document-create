### 활동으로 마무리하기 (교 157쪽, p.265)

## 창의·융합 프로젝트
### "Frogger를 분석하여 구현하기" (교 153~155쪽, p.261~263) — 모둠, 탐구 학습, 스크래치(엔트리도 가능) + 마이크로비트
- **수업 형태**: 탐구 학습 / **준비물**: 교사 — 스크래치/엔트리 계정, 학생 — 인터넷 연결 컴퓨터, 노트북 (p.261)
- **지도 목표**: 고전 게임의 동작을 관찰하고 핵심 기능을 분석·구현해 자신만의 창의적인 게임으로 발전시킴. (p.261)
- **지도상의 유의점** (p.261): 디지털 게임의 가치와 의미를 생각해 보고, 플레이어로 즐기기보다 **원리를 파악하고 프로그래밍으로 재탄생시킬 수 있는 표현의 매체**로 인식시킴 / 게임 만들기에 변수·조건 개념을 쓸 수 있음을 인식 / 피지컬 컴퓨팅으로 컨트롤러를 만들어 인터페이스의 다양한 가능성 탐색.
- **도입 자료**: 야생동물이 도로를 건너다 죽거나 다치는 경우가 많은데, 이것이 창작 아이디어가 되어 1981년 길과 강을 건너 집으로 돌아가는 개구리의 여정을 담은 **Frogger** 게임이 탄생. "Frogger에 대해 알아보자." 게임 화면 사진 "Frogger(1981) 게임". 지도서: 1981년 Konami 개발, 상업적 성공. 직접 플레이하거나 영상을 보고 특징·기능을 알아본 뒤, "가장 단순한 모습의 Frogger가 되기 위한 최소한의 기능과 게임 속 논리"를 토론. 목표는 **소비자가 아닌 구성 요소를 분석하는 생산자의 입장**이 되는 것. (p.261)
- **목표 발문**: 1 "고전 게임을 보고 영감을 얻어 보자." 2 "Frogger 게임이 가진 핵심 요소가 무엇인지 파악하여 길 건너기 게임을 만들어 보자." (p.261)
- **활동 순서**: 01 역할 정하기 → 02 프로젝트 방향 정하기 → 03 프로젝트 수행하기 → 04 보고서 작성하기 → 05 발표하기. **모둠원 구성** 표(이름 | 역할). (p.261, 순서는 그림 배치로 복원)
- **단계 1 문제 추상화하기** — 빈칸 구조: ① "문제가 무엇인지 적어 보기 ( )" ② "문제 상태를 정의하고 핵심 요소를 찾아보기" ③ "문제를 입력, 처리, 출력 형태로 만들어 보기"
  - 예시 답안: 문제 "개구리 게임 만들기" / 초기 상태: 게임 배경만 있는 상태 / 현재 상태: 개구리가 출발선에 가만히 있는 상태 / 목표 상태: 개구리가 장애물을 피해 목적지까지 도달한 상태 / 핵심 요소: 플레이어는 개구리를 입력 장치로 이동시킨다, 장애물은 좌우로 움직이며 등장할 때 속도가 달라진다, 개구리가 장애물에 닿으면 게임을 새로 시작한다.
  - 입력: 개구리를 조작하기 위해 키보드 방향키를 입력 / 처리: 키보드 입력에 따라 개구리 움직이기, 장애물 좌우로 움직이기, 개구리가 장애물에 닿았을 경우 게임을 다시 시작하기 / 출력: 개구리, 장애물을 화면에 보여 주기 (p.261)
- **단계 2 알고리즘 설계하기**: "추출한 핵심 요소를 바탕으로 알고리즘을 설계해 보자." 지도서: 개구리·장애물·집(목적지) 3개 스프라이트(오브젝트)가 필요하며, 각 동작을 문장으로 적으며 설계. (p.261)

  | 요소 | 개구리 | 장애물 | 집(목적지) |
  |---|---|---|---|
  | 동작 | ○키보드 이벤트에 따라 상하좌우 움직인다. ○만약 장애물에 닿으면 처음부터 시작한다. ○만약 집에 도착하면 게임은 성공한다. | ○왼쪽 혹은 오른쪽에서 시작해서 반대 방향으로 이동한다(x축 이동을 한다.). ○만약 왼쪽 혹은 오른쪽 벽에 도달하면 다시 처음 위치로 이동한다. ○처음 위치에서 시작할 때 움직이는 속도가 바뀐다. | ○집은 특별한 기능이 없다. |
- **단계 3 프로그래밍하기** (교 154쪽, 스크래치, 그림 렌더링으로 확인)
  ```
  [개구리]
  깃발 클릭했을 때 → [새로 시작하기▾] 신호 보내기
  [새로 시작하기] 신호를 받았을 때
      x: 0 y: -165 (으)로 이동하기
      무한 반복하기
          만약 <(청록)색에 닿았는가?> (이)라면
              pop 재생하기
              [새로 시작하기] 신호 보내기
          만약 <집 에 닿았는가?> (이)라면
              "앗호 성공~" 말하기
  왼쪽 화살표 키를 눌렀을 때 → x좌표를 -10 만큼 바꾸기
  오른쪽 화살표 키를 눌렀을 때 → x좌표를 10 만큼 바꾸기
  아래쪽 화살표 키를 눌렀을 때 → y좌표를 -15 만큼 바꾸기
  위쪽 화살표 키를 눌렀을 때 → y좌표를 15 만큼 바꾸기

  [장애물] (청록색 막대 스프라이트)
  [새로 시작하기] 신호를 받았을 때
      x: -270 y: -100 (으)로 이동하기
      속도 을(를) (7 부터 30 사이의 난수) 로 정하기
      무한 반복하기
          x좌표를 (속도) 만큼 바꾸기
          만약 <(x좌표) > 270> (이)라면
              x: -270 y: -100 (으)로 이동하기
              속도 을(를) (7 부터 30 사이의 난수) 로 정하기
  ```
  - 교과서 말풍선(발문): "지금은 개구리가 움직이는 속도를 바꾸기 위해 여러 숫자를 변경해야 해요. 효과적으로 바꿀 수 있는 방법은 무엇일까요?" / "왼쪽에서 오른쪽으로 이동하는 장애물이에요. 오른쪽에서 왼쪽으로 이동하게 하려면 어떻게 해야 할까요?" / "여러 개의 기존 장애물을 배치하려면 어떻게 해야 할까? 각 장애물의 시작 위치가 달라지려면 어떤 값이 달라야 할까?" / "기존 장애물 코드를 복사해서 사용하다 보면 여러 장애물이 동일한 속도가 되는 문제가 발생할 수 있어. 원인을 찾고 디버깅해 보자." (p.262)
  - 지도서 해설 (p.262)
    - 개구리: 깃발 클릭 시 [새로 시작하기] 신호로 모든 스프라이트를 처음 상태로 / 방향키 이벤트에 따라 x·y 좌표 변화로 이동 / 장애물에 닿았을 때·집에 닿았을 때 조건문 완성 / 본문은 **장애물은 색상으로, 목적지는 스프라이트로** 확인 — 차이와 장단점을 의논.
    - 장애물: 신호를 받으면 초기 위치로 이동, 임의 속도로 x 이동 / 왼쪽 벽에서 등장해 오른쪽으로 사라지는 구조라 속도는 양수 / x좌표가 270보다 커지면 왼쪽 벽으로 옮기고 속도를 다시 임의로 → 매번 다른 속도로 등장.
    - 집: 시각적 표현만, 특별한 기능 없음. 더 재밌게 만들려면 집에도 동작을 넣을 수 있을지 의견 나누기.

## 쏙쏙 요약 정리
(지도서 전용. 빈칸이 아닌 요약문 형태라 핵심 낱말을 **굵게** 표시함)

### 01 추상화와 알고리즘 (p.266)
- **문제 해결을 위한 상태 정의하기**: '문제'는 생활 속에서 해결해야 하는 질문 또는 과제. 문제를 이해·분석해 **초기 상태**(문제를 시작할 때), **현재 상태**(문제의 현재), **목표 상태**(목표에 도달한 상태)를 정의.
- **문제 해결에 필요한 핵심 요소 찾기**: 어떤 부분이 중요한지 찾고, 문제를 작은 부분으로 나눠 필요한 요소를 찾음. **핵심 요소** = 문제에서 찾아낸 중요한 요소.
- **문제 구조화하기**: 상태 정의 → 핵심 요소 찾기 → 정리·배열해 **통일된 구조**로 만들기. 체계적 분석, 요소 간 관계 이해에 도움. **목록(리스트), 표, 다이어그램** 등으로 작성.
- **문제 추상화하기**: 공통 특성이나 핵심 요소를 **추출**. 불필요한 요소 제거로 관계 파악이 쉬움. **입력, 처리, 출력** 형태로 표현하면 절차·흐름 이해가 쉬움. 과정: **문제 상태 파악 – 문제 분해 – 핵심 요소 추출 – 구조화**.
- **알고리즘의 개념**: 문제 해결 방법을 **단계적인 절차**로 표현한 것, 동작들의 모임. 하나의 문제에 다양한 알고리즘 설계 가능. 잘못 표현되면 해결이 더 복잡해짐.
- **알고리즘의 특징(조건)**: ① **입력** ② **출력** ③ **명확성**(각 단계에서 무엇을 하는지 명확) ④ **수행 가능성**(각 명령이 논리적으로 수행 가능) ⑤ **유한성**(주어진 절차·횟수만큼 처리 후 반드시 종료).
- **알고리즘 표현 방법**: ① **자연어** ② **의사 코드**(특정 언어 문법을 따르지 않고 프로그래밍 언어로 바꾸기 쉬운 형태) ③ **순서도**(정해진 기호, 흐름을 한눈에 파악).
- **알고리즘 분석**: 결과가 정확한지, 구조가 단순하고 오류 수정이 쉬운지, **작업량과 수행 시간**, **기억 장소 사용량** 확인·비교. 효율적인 알고리즘 = 작업량이 적어 수행 시간이 짧고 기억 장소 사용량이 적은 것.
- **문제 해결 전략**: **전체 탐색**(처음부터 끝까지 해보기) / **분할 정복**(나누어 해결하고 합치기) / **규칙 찾기**(규칙을 찾아서 해결하기) / **되추적**(되돌아가서 다시 찾기).

### 02 프로그래밍 (p.268)
- **변수와 리스트**: 변수는 데이터를 저장하는 기억 장소, 여러 데이터면 여러 변수가 필요해 번거로움. **리스트**는 여러 데이터를 **순차적으로 저장**하고 **하나의 이름**으로 관리하는 데이터 구조, **배열**이라고도 함.
- **리스트의 특징**: 입력된 데이터 = **항목**, 순차 저장 / 서로 다른 유형의 데이터 저장 가능 / 번호는 **1번부터** / 항목 번호로 검색·수정·삭제가 쉬움.
- **연산자**: 일정 규칙에 따라 계산할 때 쓰는 기호. **산술 연산자**(+, -, × 또는 *, /), **비교 연산자**(>, <, =, !=), **논리 연산자**(참·거짓의 논리적 관계).
- **논리 연산자**: 결과는 **참, 거짓**. 프로그램 흐름을 제어하는 조건식에 활용, 여러 개 결합 가능. 종류: **논리곱(AND)** — A, B 모두 참일 때만 참 / **논리합(OR)** — 하나라도 참이면 참 / **논리 부정(NOT)** — A가 참이면 거짓, 거짓이면 참.

  | A | B | A 그리고 B | A 또는 B | A가 아니다 |
  |---|---|---|---|---|
  | 참 | 참 | 참 | 참 | 거짓 |
  | 참 | 거짓 | 거짓 | 참 | 거짓 |
  | 거짓 | 참 | 거짓 | 참 | 참 |
  | 거짓(원문 "참") | 거짓 | 거짓 | 거짓 | 참 |
- **중첩 제어문**: 제어문(조건문, 반복문) 안에 또 다른 제어문을 포함한 구조. ① **중첩 조건문** ② **중첩 반복문**(많은 데이터를 효율적으로 처리하지만 잘못 쓰면 느려지거나 **무한 루프**) ③ 조건문과 반복문이 겹친 경우(복잡한 흐름을 명확히 표현).
- **함수**: 특정 기능을 하는 여러 명령어를 **하나의 블록으로 정의**하고 필요할 때마다 **호출**. 반복 작업에 효율적, 필요한 부분만 수정해 재사용 → 시간·노력 절약. **매개 변수** = 함수 호출 시 전달되는 입력값을 받아 저장하는 변수.
- **디버깅**: 실행 중 오류가 발생한 코드를 찾아 수정하는 과정. 오류는 **정상적으로 실행되지 않는 경우**와 **실행은 되지만 의도대로 작동하지 않는 경우**로 구분. 안정적인 프로그램을 만듦.

- 중단원 3(문제 해결과 프로그래밍)에 대한 쏙쏙 요약 정리·형성 평가는 없음. (p.266~269 확인)

### 활동지 03 "문제 해결 전략 세우기" (p.273)
- 연계: 02 알고리즘 표현과 분석, 교 97~98쪽

- 목표 발문: "다음의 문제를 읽고 문제 해결에 적합한 전략을 선택해서 해결해 보자."
- 제시 자료: 수아가 방학에 읽을 책 구입, 제한된 시간·예산 안에서 가장 많은 책. 조건: **예산 35,000원, 읽을 시간 15시간**.

  | 책 이름 | 가격 | 소요 시간 | 책 이름 | 가격 | 소요 시간 |
  |---|---|---|---|---|---|
  | 해리포터 | 13,000 | 4 | 현대 소설 | 15,000 | 6 |

- 칸 구조와 예시 답안
  - 1 "문제 해결을 위한 전략을 선택해 보자." 체크박스 4개: □ 전체 탐색 □ 분할 정복 □ 규칙 찾기 □ 되추적
  - 2 "선택한 방법에 따라 알고리즘을 작성해 보고, 적합한 방법인지 이유를 적어 보자." 표(알고리즘 | 문제 해결에 적합한 이유)
    - 전체 탐색: 모든 책의 가능한 조합 생성 → 각 조합의 총비용·총시간 계산 → 예산·시간 제한 내이면 그중 가장 많은 책 조합 기록 → 마지막에 최적 조합 반환. 이유: 데이터가 많지 않고 최적의 해를 찾을 수 있음.
    - 되추적: 각 책을 선택할지 말지 결정 → 현재까지 총비용·시간 계산 → 초과하면 그 경로를 포기하고 다른 조합 → 모든 경로 탐색 후 최적 조합 반환. 이유: 불필요한 경로를 일찍 제거해 전체 탐색보다 효율적.
- 평가 기준 "문제 해결에 적합한 문제 해결 전략 선택을 선택하여 알고리즘을 설계할 수 있다."(원문 그대로)

  - 중 "사례를 중심으로 문제 해결에 적합한 전략을 선택하여 기본적인 알고리즘을 설계할 수 있다."
  - 하 "사례를 중심으로 문제 해결에 적합한 전략을 선택하여 일부 알고리즘을 설계할 수 있다."
- (제안) 실제 정답 조합을 지도서가 제시하지 않음. 가장 싼 세 권도 12,000×3 = 36,000원 > 35,000원이므로 최대 2권. 시간 15시간도 함께 만족하는 2권 조합은 여러 개 → "가장 많은 책"만으로는 해가 하나로 정해지지 않음을 토론 소재로 쓸 수 있음.
