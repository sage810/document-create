# ch02 피지컬 컴퓨팅
> 대단원: Ⅰ. 컴퓨팅 시스템 | 지도서 p.57~59, 74~89 | 교과서 26~41쪽 | 성취기준: [9정01-02], [9정01-03] | 차시: 6차시 (01 개념 2차시 + 02 활용 4차시)

## 핵심 한 줄
- 피지컬 컴퓨팅은 센서(입력)로 환경 변화를 읽고 마이크로컨트롤러(처리)가 프로그램대로 판단해 액추에이터(출력)로 물리 세계에 영향을 주는 것이며, 마이크로비트·MakeCode로 '문제 발견·정의 → 장치 구상(입력-처리-출력) → 시스템 설계 → 구현 → 개선'의 프로젝트를 수행한다. (p.75~82)

## 중단원 도입 — 생각의 씨앗 심기
(교 26쪽, p.74)
- 도입 문장 요지: 빛·소리 등 환경 변화에 따라 문제를 해결하는 피지컬 컴퓨팅에 관심이 늘고, 몇 개의 장치를 조립하고 프로그램을 만드는 시도가 늘면서 상상의 범위도 확대됨.
- 교과서 발문(원문): "Q 사람들은 어떤 부분에서 피지컬 컴퓨팅으로 새로운 아이디어를 공유할까?" / "세상에 없던 물건이나 장치를 만든 사례로는 무엇이 있을까?"
- 장면(삽화)과 말풍선
  - 시민 과학자: 환경을 관찰하고 수치를 측정하는 장치를 만들어 생태계를 기록하거나 환경 변화를 관찰. 말풍선 "오호, 우리 동네엔 저런 새들이 살고 있군!"
  - 수리할 권리: 피지컬 컴퓨팅을 배우면 시스템의 구조·원리를 이해하는 능력이 생김 → "고장 나면 쉽게 버려지는 전자 제품을 수리할 권리(Right to Repair)를 되찾아 보는 건 어떨까?" 말풍선 "내가 직접 수리해 보겠어!" (*수리할 권리: 구매한 물품을 스스로 수리·개조할 권리)
  - 메이커 상상: "소리도 나고, 불도 켜지는 나만의 조명 장치를 만들어 보자!" / 식물 상태에 따라 음악이 나오는 화분, 사람이 다가가면 빛나는 가방, 오래 앉으면 경고음을 내는 의자가 실제 제품으로 개발되기도 함.
- 지도 방안(p.74): 그림으로 피지컬 컴퓨팅으로 할 수 있는 일을 살피고, 새 아이디어를 공유하는 부분을 알아봄 → 세상에 없던 물건·장치 사례를 인터넷 검색으로 조사 → 내가 해결하고 싶은 문제를 어떻게 해결할지 상상하고 자유롭게 이야기.
- 예시 답안(p.74)
  - Q1: 설계 문서와 소스 코드를 커뮤니티에 공유 → 다른 사람이 만들어 보고 피드백·개선해 다시 공유.
  - Q2: 수조의 물고기 양분을 수경 재배로 화초에 공급하는 가정용 아쿠아포닉스(Aquaponics).

- **도입**: 전시 학습 확인[운영체제의 기능] → 생각의 씨앗 심기로 피지컬 컴퓨팅 기반 다양한 활동을 소개해 관심도 높임 → "시중에서 판매하는 완제품과 자신이 직접 만든 장치는 어떤 점이 다를지 생각해 보도록 한다." 유의점: DIY, Make 문화를 소개하고 학생 수준에서 참여할 방법을 소개해 기대감 높임.
- **전개**
  - ➊ 개념 이해: 피지컬(Physical)에 담긴 "물리적"의 의미 → 교과서 26~27쪽 사례로 직접 만들어 쓸 수 있음 소개 → 27쪽 아두이노·마이크로비트 시스템 이미지와 개발 환경 설명 → 28쪽 입력-처리-출력 구조도로 외부 변화를 데이터로 수집·처리·다양한 동작으로 출력하는 과정 설명.
  - ➋ 구성 요소: 28~29쪽 구성 요소와 역할을 입력-처리-출력순으로 구분, 센서·마이크로컨트롤러·액추에이터 개념을 명확히. 처리 장치 마이크로컨트롤러 개념.
  - ➌ 동작 원리: 입력 센서와 출력 액추에이터의 관계, 전기 회로와 달리 프로그래밍으로 기능을 수정할 수 있음.
  - ➍ 생활 속 피지컬 컴퓨팅과 가치: (활동으로 쑥쑥 3) [문제 상황]을 시스템으로 해결할 때 필요한 입출력 장치 정리.
  - 유의점: 실물 장치를 보여 주면 도움 / 국내외 Make 프로젝트 사례를 영상으로 소개 / 입출력 장치를 스마트폰 기능과 연결해 비교 설명.
- **정리**: 생활 속 장치의 구성 요소·동작 원리를 이해하고 발표, 차시 예고. 유의점: 앞서 배운 컴퓨팅 시스템 동작 원리와 공통점·차이점 구분.
- 소단원 지도상의 유의점(p.75): 개념·구성 요소를 생활 속 구체적 사례와 연결.

### 동기 유발 — 새싹 틔우기
- 제목 발문: "손바닥 위에 올라가는 컴퓨터?" (교 27쪽, p.75)
- 삽화: 아두이노로 만든 공기 오염도 감지기, 교육용 마이크로비트로 만든 만보기(손바닥 위의 작은 보드). 말풍선 "이렇게 작은 장치로 무엇을 할 수 있을까요?"
- 해설(p.75): 아두이노 같은 작은 장치는 센서·액추에이터로 환경을 감지하고 물리적 영향을 줌 = 디지털 세계와 물리적 실제 세계를 연결. 작은 장치로 문제 해결·창의적 표현이 가능함을 안내하며 나만의 표현물을 상상하게 유도.

### 전개 — 본문 흐름과 핵심 개념
**1 피지컬 컴퓨팅의 이해 (교 27쪽, p.75)**
- 정의: 빛·소리 등을 감지하는 센서로 환경 변화를 읽고, LED·모터 등 출력 장치인 액추에이터로 물리적 영향을 미치며 외부 세계와 상호 작용하는 것.
- 예: 어두워지면 켜지는 가로등, 장애물을 피하며 서빙하는 로봇. 3D 프린터, 드론, 사물 인터넷(IoT)이 피지컬 컴퓨팅 개발 환경으로 만들어짐. 대표 개발 환경: 아두이노, 마이크로비트.
- [그림 Ⅰ-12] 보조단 "피지컬 컴퓨팅 시스템의 개발 환경": 아두이노는 다양한 입출력 장치 연결·간편 프로그래밍 / 마이크로비트는 배우기 쉽고 기본 입출력 장치가 한 보드에 포함 / 보드에 입출력 장치를 연결해 시스템을 만들고 프로그래밍해 작동(Link 28, 29쪽).
- 용어: 사물 인터넷(IoT) = 평범한 물건들이 인터넷에 연결되어 정보를 주고받고 원하는 대로 작동하는 기술(냉장고가 우유 유통 기한 알림, 스마트폰으로 집 온도 조절).
- 해설(p.75): 활용 영역(자동화, IoT, 로봇 공학, 스마트 홈, 웨어러블, 교육). 메이커 페어(Maker Faire)에서 전문가·비전문가 공유. 발전 배경 = 오픈 소스 커뮤니티 + 비전문가에게 열린 교육 기회·문화.

**2 피지컬 컴퓨팅 시스템의 동작 원리 (교 28~29쪽, p.76~77)**
- 기본 동작 '입력-처리-출력'. 데스크톱·스마트폰처럼 여러 작업보다 **특정 작업**을 위해 목적에 맞는 입출력 장치와 구성되어 물리 세계와 상호 작용.
- [그림 Ⅰ-13] 입력-처리-출력 구조도: 입력(센서: 온습도 센서, 빛 센서) → 처리(마이크로컨트롤러) → 출력(액추에이터: 버저, LED).
- 말풍선: "피지컬 컴퓨팅 시스템은 다양한 센서로 외부 환경의 상황을 감지하여 데이터를 입력받고, 마이크로컨트롤러로 처리해서 그 결과를 다양한 출력 장치로 표현해요." / "피지컬 컴퓨팅 시스템의 구성 요소와 역할을 알아보아요."
- [그림 Ⅰ-14] 구성 요소와 역할
  - 입력 장치(센서: 밝기·소리·입력·온도 등 감지·측정 → 마이크로컨트롤러에 전달): 버튼(눌림), 기울기 센서(x·y·z축 기울어짐), 빛 센서(조도·밝기 센서, 주변 밝기), 소리 센서, 온습도 센서, 초음파 센서(박쥐처럼 초음파로 거리), 조이스틱(원하는 방향), 터치 스위치(접촉 여부).
  - 처리 장치: 마이크로컨트롤러가 포함된 피지컬 컴퓨팅 보드 — 프로그램으로 센서 데이터를 처리하고 결과를 출력 장치로 보냄.
  - 출력 장치(정보 전달 장치·액추에이터 → 빛·소리·움직임): 레이저(강한 빛), LCD(정보를 화면에), 7세그먼트 LED(숫자·문자용 LED 7개 + 점 1개), 버저('삐삐'), 모터(시계/반시계 방향 360도 회전), LED(다양한 색).
  - 용어: 액추에이터 = 시스템의 명령을 실제 물리적 동작으로 변환하는 장치 / 마이크로컨트롤러 = 두뇌 역할 작은 컴퓨터, CPU 외 메모리·입출력 포트를 하나의 칩에 포함.
- 전기 회로 vs 피지컬 컴퓨팅: [그림 Ⅰ-15] 전기 회로 전등도 같은 기능 가능하지만, [그림 Ⅰ-16] 처리 장치를 이용한 LED 출력은 마이크로컨트롤러가 있어 HW·SW가 통합 동작 → 프로그래밍으로 기능 변경·추가 쉬움.
  - 의사코드 예(교 29쪽): "만약 버튼이 눌리면 / LED 켜기 / 아니면 / LED 끄기" → 변형 "LED로 모스 부호": "만약 버튼이 눌리면 / LED 빠르게 깜빡이기 / 아니면 / LED 천천히 깜빡이기", "LED로 밝기 조절하기".
  - 해설 추가 예(p.77): 반대로 동작하기(누르면 LED 끄기, 아니면 켜기), 깜빡이는 전등(누르면 켜기→1초 쉬기→끄기→1초 쉬기, 아니면 끄기).
  - 보조단 모스 부호: 점과 선을 배합해 문자·기호를 나타내는 전신 부호, 새뮤얼 모스 고안.
- 말풍선 발문: "우리 주변에서 입력-처리-출력 과정을 거쳐 외부 환경과 상호 작용하는 피지컬 컴퓨팅 시스템의 사례를 찾아 발표하고 토론해 보세요." (교 29쪽)
- 해설(p.76~77)
  - 사례: 온도 조절 히터(온도 센서→히터 켜고 끄기), 자동 블라인드(빛 센서→모터), 스마트 화분(습도 센서→펌프로 물).
  - 입력은 아날로그(연속 신호) / 디지털(이산 데이터)로 나뉨. 온도 센서는 온도를 전압(아날로그)으로, 처리 장치가 디지털로 변환.
  - 입력값 표: 온도 센서(LM35) 아날로그 0~1023 섭씨 / 빛 센서(LDR) 아날로그 0~1023 빛의 세기 / 초음파 센서(IR 센서) 아날로그 0~1023 거리 / 터치 센서 디지털 0 혹은 1 접촉 여부.
  - 출력 제어: 디지털값 1/0(LED 켜기/끄기) / 디지털·PWM(LED 밝기, 모터 속도·방향, 서보모터 0~180도, 스피커 톤) / I2C 통신으로 디스플레이 출력.
  - 처리 장치: 마이크로컨트롤러는 작업을 프로그래밍한 후 그 작업을 중점 처리. 라즈베리파이는 마이크로프로세서 기반으로 OS를 올려 데스크톱처럼 쓰면서도 입출력 장치 제어 가능.
  - 그 밖의 센서 안내: 연기, 인체 감지, 레이저, 불꽃 감지, 진동, 적외선 센서.
  - 지식 플러스 "아두이노와 브레드보드": 회로 설계·보완 반복을 돕는 브레드보드. ① 브레드보드에 입출력 장치 연결해 HW 구성 ② 개발 환경 프로그램으로 SW 구현. 출처: 프릿징(Fritzing).

### 활동 (01)
#### 활동으로 쑥쑥 3 "피지컬 컴퓨팅 시스템 구성하기" [분석·추론] (교 30쪽, p.78) — 개인/짝, 언플러그드(설계 표)
- **지도 목표**: 생활 속 문제 상황에 활용할 시스템을 구성할 수 있다.
- **지시문**: "보기를 참고하여 각각 주어진 문제 상황에 필요한 입출력 장치의 역할과 함께 프로그래밍할 때 처리해야 하는 조건을 적어 보자."
- **칸 구조**(문항마다): [입력 장치 + 역할] → [조건 처리: 만약 [ ]면 / [ ] / 아니면 / [ ]] → [출력 장치 + 역할]
- **보기**: "입력 장치는 온습도 센서, 출력 장치는 모터를 사용한다. 온습도 센서로 외부 환경의 온도를 측정한 값을 입력하고, 처리 장치는 온도가 30℃를 넘으면 모터를 회전시켜 바람이 나오도록 설계한다." → 온습도 센서(주변의 온도와 습도를 측정) / 만약 [온도가 30°C를 넘으]면 [모터를 돌린다.] 아니면 [모터를 멈춘다.] / 모터(회전 운동으로 바람을 일으킨다).
- **문항과 예시 답안**
  1. "해가 지면 주변의 밝기에 따라 자동으로 빛을 조절하는 조명을 만들어 보자." (입력 빛 센서·출력 LED와 역할은 제시됨) → 만약 [밝기 센서값이 300보다 작으]면 [LED를 켠다.] 아니면 [LED를 끈다.]
  2. "교실에서 떠들면 소음 강도에 따라 경고 메시지를 보여 주는 안내판을 만들어 보자." (입력 소리 센서 제시) → 소리 센서 역할: 소음을 측정한다 / 만약 [음향 감지 센서값이 50보다 크]면 [LCD에 경고 메시지를 띄운다.] 아니면 [LCD를 끈다.] / 출력 LCD: 정보를 화면에 나타낸다.
  3. "연기가 나면 울리는 경보기를 만들어 보자." (모두 빈칸) → 연기 센서: 연기를 감지한다 / 만약 [연기 센서값이 300보다 크]면 [버저를 켠다.] 아니면 [버저를 끈다.] / 버저: 소리를 낸다.
- **지도상의 유의점**: 실제 장치를 만드는 것이 아니므로 개념적 동작 흐름 이해에 초점 / 배우지 않은 센서(연기 센서 등)는 직접 조사 / 조건 처리는 프로그래밍의 **조건문과 같은 구조**임을 인식, 프로그래밍을 통한 기능 구현의 중요성 강조.
- **활동 평가 항목**: "피지컬 컴퓨팅 시스템을 구성하여 주어진 문제를 해결할 수 있는가?"
- 평가 도구: 수행 평가 p.100~103, 지필 p.104~107.

### 형성 평가 · 핵심 개념 정리하기 (p.78)
- 형성 평가 1 (빈칸): 피지컬 컴퓨팅 시스템은 (**입력**) - 처리 - (**출력**)의 기본 동작 과정.
- 형성 평가 2 (빈칸): 다양한 (**센서**)로 환경 변화를 읽고, 출력 장치인 (**액추에이터**)로 물리적 영향.
- 핵심 개념: 피지컬 컴퓨팅 / 입력 장치(센서→마이크로컨트롤러 전달) / 처리 장치(마이크로컨트롤러) / 출력 장치(정보 전달 장치·액추에이터로 빛·소리·움직임).

### 활동지 제작 아이디어 (제안) (01)
1. **센서 탐정 카드 분류**: 그림 Ⅰ-14의 센서·액추에이터 카드 14장을 입력/처리/출력 3칸에 분류 → 각 카드에 "무엇을 감지/표현?" 한 줄 → 스마트폰 속 같은 역할 장치 찾기(지도서 유의점 연계).
2. **전기 회로 vs 마이크로컨트롤러**: 같은 버튼·LED로 할 수 있는 일 비교 표 → 의사코드 "만약 버튼이 눌리면 ~ 아니면 ~"을 3가지로 변형(반대로, 깜빡이기, 모스 부호) 작성.
3. **우리 학교 문제 해결 설계도**: 활동 3 구조(입력-조건 처리-출력)를 그대로 빈칸 템플릿으로 → 학교 문제(급식실 소음, 복도 조명, 화분 물 주기) 중 하나 선택해 작성 → 경곗값을 왜 그렇게 정했는지 설명.

## 소단원 02 피지컬 컴퓨팅의 활용 (교 31~35쪽, p.79~83)
### 수업 흐름 (차시별 지도 계획)
#### 3~4차시 (p.58) — 교 31~32쪽, 지도서 79~80쪽, 2시간
- **학습 목표**: "피지컬 컴퓨팅 시스템의 동작 원리를 설명할 수 있다."
- 수업 형태: 문제 기반, 탐구, 토의·토론, 프로젝트 기반 학습 / 준비물: 교과서, 컴퓨터, 마이크로비트
- **도입**: 전시 학습 확인[피지컬 컴퓨팅의 개념과 구성 요소] → 새싹 틔우기로 센서의 활용법 설명 → 마이크로비트를 관찰하고 특징 설명. 유의점: 하나의 센서로도 다양한 활용이 가능함 / 작은 마이크로비트를 관찰한 결과를 이야기하고 기능 유추.
- **전개**
  - ➊ 마이크로비트 시작하기: 교육용 마이크로비트의 특징 — 기존 보드와 달리 일상에서 자주 쓰는 입출력 장치가 **내장**된 보드, 입출력 구성 설명. USB 케이블 연결 방법과 MakeCode 접속 방법.
  - ➋ 구성 요소 알아보기: 입출력 장치 구성, 기본 동작 원리를 다시 숙지해 마이크로비트와 연결.
  - ➌ 마이크로비트로 표현하기: 실습 2가지 표현 예제 실행. 두 종류 입력 센서 방식 — **디지털 방식 버튼과 아날로그 방식 빛 센서의 값 차이**를 실습으로. 기본 예제 후 모둠별로 각자 다른 표현으로 확장.
  - 유의점: USB 유선 연결과 블루투스 무선 연결이 가능하나 **MakeCode로 프로그램을 올리려면 유선 연결** / 유선 연결 시 외장 드라이브로 잡히고 hex 파일을 붙여 넣어 설치 — USB 메모리에 파일을 저장하는 방식으로 비유 / 설치 후 배터리팩을 연결해 독립 실행, 무선 동작 시 활용 방법 구상.
- **정리**: 모둠별 표현 공유·피드백, 차시 예고. 유의점: 동일한 입출력 장치로도 다른 용도의 표현을 만들게 지도.

#### 5~6차시 (p.59) — 교 33~41쪽, 지도서 81~89쪽, 2시간
- **학습 목표**: "목적에 맞게 피지컬 컴퓨팅 시스템의 구성 요소를 선택하고 구상할 수 있다."
- 수업 형태: 문제 기반, 탐구, 토의·토론, 프로젝트 기반 학습 / 준비물: 교과서, 노트와 필기도구, 마이크로비트
- **도입**: 전시 학습 확인[피지컬 컴퓨팅 시스템의 동작 원리] → 구성 요소와 기본 동작 원리 확인 → 피지컬 컴퓨팅으로 주변 문제를 해결하는 것의 의미를 질문해 호기심 유발. 유의점: 일반 시스템과 마이크로비트의 차이(자주 쓰는 입출력 장치 내장).
- **전개**
  - ➊ 프로젝트 과정 이해: '문제 발견과 정의, 입력-처리-출력 장치 구상, 시스템 설계, 구현'을 본문 카운터 예제로 이해·연습. 장치 구상 단계에서 입력-처리-출력 영역으로 핵심 요소가 나오게 지도.
  - ➋ 나만의 문제 발견·정의: 마이크로비트로 해결할 수 있는 나만의 문제를 모둠 활동으로 찾음.
  - ➌ 문제 해결 장치 만들기: 입력-처리-출력으로 기능을 구상하고 알고리즘 설계 → 문제 상황 시연, 동작 실험 → 오류 상황 파악·개선.
  - 유의점: 단번에 해결이 아니라 **구현하며 점진적으로 개선**하는 과정 인식(이후 디버깅 내용과 연결) / 내장 장치 외 별도 키트로 확장 가능, 학교 환경에 따라 실습 범위 결정.
- **정리**: 만든 장치 공유·프로젝트 과정 정리, 결과물의 새 문제점과 개선 방법 정리, 차시 예고. 유의점: 문제 해결을 위한 **프로토타이핑**의 의미 이해.
- 소단원 지도상의 유의점(p.79): 기본 개념·구성 요소가 마이크로비트로 구체적으로 연결되도록 **실습 중심**.
- 참고: 교 36~41쪽(진로 디자인, 중단원 마무리, 쉬어가기, 창의·융합 프로젝트)도 이 계획(교 33~41쪽) 범위에 들어감. 창의·융합 프로젝트는 2차시 이상 필요해 보이므로 별도 차시 확보 권장 (제안).

### 활동 (02)
#### 실습 "마이크로비트로 간단한 표현 만들기" (교 32쪽, p.80) — 모둠/개인, MakeCode + 마이크로비트
- 도입 지시문: "마이크로비트의 센서값은 버튼처럼 불연속적인 값을 가진 [방법 1]과 빛 센서처럼 연속적으로 변하는 값을 가진 [방법 2]가 있다. 각 방법으로 간단한 표현을 만들어 보자."
- **지도 목표**: 마이크로비트의 입출력 장치를 이해하고 간단한 표현을 프로그래밍할 수 있다.
- **방법 1 "버튼을 눌러 감정을 빛으로 표현하기"** — [조건] "입력 장치는 A, B 버튼, 출력 장치는 LED를 사용해 보자." (디지털 입력: 누르기/안 누르기)
  - ➊ "코드를 입력해 보자." 블록 구성(렌더링 확인):
    - `[A ▼ 버튼 눌릴 때]` 안에 `[아이콘 출력 (얼굴 아이콘 ▼)]`
    - `[B ▼ 버튼 눌릴 때]` 안에 `[아이콘 출력 (다른 얼굴 아이콘 ▼)]`
    - `[A+B ▼ 버튼 눌릴 때]` 안에 `[LED 출력 (5×5 격자에 직접 그린 모양: 가운데 세로 3줄 위쪽 + 아래 전체가 켜진 형태)]`
  - ➋ "결과를 확인해 보자." — A 버튼을 눌렀을 때 / B 버튼을 눌렀을 때 / A와 B 버튼을 함께 눌렀을 때 서로 다른 LED 그림.
  - 해설: 입력=디지털 입력 방식 버튼, 출력=LED 화면. 버튼 동작 이벤트 블록은 **조건문 블록의 종류**로 볼 수 있음. 원하는 조건에서 다양한 LED 출력을 시도.
- **방법 2 "주변이 어두워지면 소리를 내는 장치 만들기"** — [조건] "입력 장치는 밝기 센서, 출력 장치는 스피커를 사용해 보자." (아날로그 입력 0~255)
  - ➊ 블록 구성: `[무한반복] { [만약 < (빛 밝기) < (100) > 이면] { [재생 (하품 ▼) (완료될 때까지 ▼)] } }`
  - ➋ 결과: "마이크로비트를 손으로 가려 빛 센서값이 100 미만이면 "피유우우~" 하품 소리 출력"
  - 해설: 밝기 센서는 아날로그 입력 → 0~255 수치. 조건 블록 + 비교 연산 블록 활용. **주변 밝기에 따라 비교할 값이 달라질 수 있음**(먼저 `수 출력(빛 밝기)`로 확인).
- **지도상의 유의점**: 방법 1·2의 입출력 장치 종류·특징 이해 / 방법 1(이벤트형 조건)과 방법 2(무한반복+만약 비교 조건)의 **조건문 차이 구분**.
- **활동 평가 항목**: "마이크로비트의 입력 장치와 출력 장치를 구분해서 사용할 수 있는가?" / "센서의 두 가지 입력 방식을 이해하고, 목적에 맞는 표현물을 만들 수 있는가?"
- 자료: T셀파 중학 정보 자료실 [실습 파일] 32쪽 실습 방법 1.hex, 32쪽 실습 방법 2.hex. QR [방법 1] https://dtqr.kr/LNfH6Uo , [방법 2] https://dtqr.kr/JcmdlOR

  - [문제 정의] "축제 기간, 다양한 체험활동이 이뤄질 대강당의 입장객을 항상 100명 이하로 설정해서 운영해 보자."
  - 보조단 QnA: 종이·아날로그 카운터 대신 마이크로비트 디지털 카운터의 장점은? → 해설: 두뇌 기억·종이 기록보다 실수 감소 / 직접 프로그래밍해 원하는 기능 추가 가능.
  - 보조단: 보드는 단독 동작(설치·이동 편리) 또는 컴퓨터 연결(기존 프로그램 확장) 가능.
  - 해설: 축제의 다른 문제 — 경품 추첨, 게임 도구, 특별 역할 LED 명찰.
- **(2) 문제를 해결하는 장치 구상하기** — "들어오는 사람과 나가는 사람의 수를 세고 강당 내 인원을 100명 이하로 유지할 수 있도록 알려 주는 피지컬 컴퓨팅 시스템을 구상해 보자. 이 문제를 해결하는 데 필요한 '입력-처리-출력'을 생각해 보자."
  - 입력: 들어올 때와 나갈 때를 구분하는 입력 장치 필요 / 처리: 들어오면 증가, 나가면 감소, 100명 초과 시 입장 불가 / 출력: 현재 인원수 표시, 100명 초과 입장 시 경고음.
- **(3) 피지컬 컴퓨팅 시스템 설계하기** — "입출력 부품들을 선택하고 구성하면 우리 목적에 맞는 피지컬 컴퓨팅 시스템을 설계할 수 있다."
  - 입력: 두 개의 버튼 — A 버튼: 사람이 들어올 때 / B 버튼: 사람이 나갈 때
  - 처리: 현재 인원수를 계속 출력 / 처음 인원수 0 / A 누르면 +1 / B 누르면 −1 / 100명 초과 시 증가 불가·경고음
  - 출력: 인원수를 LED로 항상 표시 / 스피커(버저)로 경고음
- **(4) 피지컬 컴퓨팅 시스템 구현하기** — "설계한 시스템을 마이크로비트의 MakeCode 환경을 이용해서 구현해 보자." (블록 구성, 렌더링 확인)
  - ❶ "'인원수'를 저장할 변수를 만들고, 0으로 초기화한다. 항상 LED로 현재 인원수를 보여 준다."
    - `[시작하면] { [인원수 ▼ 에 (0) 저장] }`
    - `[무한반복] { [숫자 출력 (인원수 ▼)] }`
  - ❷ "A 버튼을 누르면 인원수를 1 증가시키고, B 버튼을 누르면 인원수를 1 감소시킨다."
    - `[A ▼ 버튼 누를 때] { [인원수 ▼ 값 (1) 증가] }`
    - `[B ▼ 버튼 누를 때] { [인원수 ▼ 값 (-1) 증가] }`
  - ❸ "인원수가 100명을 초과하지 않도록 'A 버튼 누를 때' 확인하는 조건문을 추가한다. 100명을 초과하면 인원수를 증가하는 대신 경고음을 내도록 한다."
    - `[A ▼ 버튼 누를 때] { [만약 < (인원수 ▼) > ▼ (100) > 이면] { [재생 (튀어오름 ▼) (완료될 때까지 ▼)] } [아니면] { [인원수 ▼ 값 (1) 증가] } }`
  - 해설(p.82): 한 번에 구현하지 않고 기본 기능부터 **점진적 구현** — ① 변수·출력 ② A·B 기본 기능 ③ 100명 초과 경고 조건문 추가.
  - 자료: [실습 파일] 34쪽 본문 카운터.hex (T셀파)
- **개선**(보조단, 교 34쪽): "이 장치를 사용하다 보면 몇 가지 문제점이 발생한다. 장치를 더 유용하게 만들 방법을 찾아보자."
  - (1) 발견한 문제: 장치를 손에 들고 있다가 떨어뜨림 / 버튼을 제대로 눌렀는지 확신이 들지 않음
  - (2) 개선할 방법 찾기: "장치를 손에 잘 고정할 방법이 있을까?" / "버튼이 정확히 눌렸음을 알려 주는 방법이 있을까?"
  - 해설: 소프트웨어 문제 외 **하드웨어적 문제**도 발견 → 손목 스트랩·목걸이 부착 / 누를 때마다 표시음, 증가·감소 시 음 높이를 다르게.
- **하나 더 하기**: "수를 세는 카운터 장치는 일상에서 여러 문제를 해결하는 데 쓰일 수 있다. 이 장치를 활용해서 해결할 수 있는 우리 주변의 문제를 찾아보자."

#### 활동으로 쑥쑥 4 "피지컬 컴퓨팅 시스템 구상하기" [분석·표현] (교 35쪽, p.83) — 개인/모둠, MakeCode 블록 제한 설계
- **지도 목표**: 주어진 입출력 기능으로 해결할 수 있는 생활 속 문제를 찾아 시스템으로 구상.
- 지시문: "보기의 블록을 활용하여 해결할 수 있는 생활 속 문제를 생각해 보고, 이 문제를 해결하는 피지컬 컴퓨팅 시스템을 구상해 보자."
- **보기 블록**(렌더링 확인): `[시작하면]`, `[무한반복]`, `[만약 (참 ▼) 이면]`, `[아이콘 출력 (하트 ▼)]`, `<흔들림 ▼ 동작>`(가속도 센서 조건). 드롭다운 목록: 흔들림, 로고 위쪽, 로고 아래쪽, 스크린 하늘 방향, 스크린 땅 방향, 왼쪽 기울임, 오른쪽 기울임, 자유 낙하, 가속도 3g, 6g, 8g. 말풍선 "여러 가지 동작을 감지할 수 있도록 선택할 수 있어요. 생활 속 문제에 어울리는 동작 유형을 생각해 보세요."
- **단계와 예시 답안**
  1. "생활 속 문제를 발견해 보자." — 표현의 도구: 말없이 제스처로 디지털 이모티콘을 보내는 모자나 장갑 / 측정의 도구: 요가·윗몸 일으키기·아령 들기에서 정확한 몸동작 확인.
  2. "피지컬 컴퓨팅 시스템을 설계해 보자." — 이름: 이모티콘 장갑 / 입력: 흔들기 동작 입력받기, 로고 위쪽으로 손을 내리는 동작 입력받기 / 처리: 로고 위쪽이면 지우기, 손을 흔들면 하트 표시 / 출력: LED로 아이콘 출력.
  3. "구상한 피지컬 컴퓨팅 시스템을 사용할 때 발생할 수 있는 문제점과 개선 방법을 찾아보자." — 문제점: 여러 동작을 넣고 싶은데 구분이 어렵다 / 개선: [만약~이면]만으로는 어려우니 [만약~이면, 아니면] 논리 블록으로 동작 구분을 명확히.
  4. "우리 주변의 문제를 피지컬 컴퓨팅 시스템으로 해결할 경우, 장점이 무엇인지 토론해 보자." — 다양한 입출력 장치를 목적에 맞게 사용 / 사물·신체에 붙이거나 형태 재구성이 쉬움 / 특정 문제 전용 장치로 만들 수 있음.
- **지도상의 유의점**: 입력은 가속도 센서, 출력은 LED 매트릭스로 **제한** — 제약 속 창의적 표현 / 가속도 센서가 감지하는 여러 움직임을 먼저 실험한 뒤 관련 생활 문제를 찾으면 도움.
- **활동 평가 항목**: "입력–처리–출력 구성을 고려해 피지컬 컴퓨팅 시스템을 설계할 수 있는가?" / "목적에 맞게 피지컬 컴퓨팅 구성 요소를 선택하고 구상할 수 있는가?"

### 형성 평가 · 핵심 개념 정리하기 (p.83)
- 형성 평가 1 (빈칸): 손쉽게 물리적 장치를 만들고 프로그래밍하는 보드, 아두이노보다 쉬움 → **마이크로비트**.
- 형성 평가 2 (빈칸): 센서는 버튼처럼 (**불연속적인**) 값이나 빛 센서처럼 (**연속적인**) 값.
- 핵심 개념: 마이크로비트 / 마이크로비트의 센서값(불연속·연속).

### 활동지 제작 아이디어 (제안) (02)
1. **마이크로비트 부품 해부도**: 그림 Ⅰ-17 앞·뒷면 윤곽에 부품 이름 쓰기 → 입력/출력/처리/통신/전원 색칠 분류 → "이 부품으로 할 수 있는 일" 한 줄.
2. **디지털 vs 아날로그 실험지**: `수 출력(빛 밝기)`로 밝은 곳/손으로 가림/책상 밑 값 기록 표 → 경곗값 정하기 → 방법 2 코드의 100을 내 교실 값으로 고치기 → 버튼(0/1)과 비교 서술.
3. **축제 카운터 4단계 프로젝트 기록장**: 문제 정의 → 입력-처리-출력 표 → ❶❷❸ 블록 단계별 체크 → 테스트(101명째에 경고음?) → 하드웨어·소프트웨어 개선안 각 1개.
4. **제약 속 창작(이모티콘 장갑)**: 가속도 동작 11종 실험 체크리스트 → 동작-아이콘 매핑 표 → 문제점·[만약~아니면] 개선.

## 중단원 마무리
(교 37쪽, p.85)
- 스스로 점검하기
  - 피지컬 컴퓨팅의 구성: "피지컬 컴퓨팅의 개념과 동작 원리를 이해하는가?" / "피지컬 컴퓨팅의 생활 속 사례와 가치를 설명할 수 있는가?" / "생활 속의 문제에 적합한 피지컬 입출력 장치를 판단할 수 있는가?"
  - 피지컬 컴퓨팅의 활용: "문제 해결 목적에 맞는 피지컬 컴퓨팅 시스템을 구상할 수 있는가?" / "구상한 시스템을 문제 상황에 맞게 더 유용하게 개선할 수 있는가?"
- 문항(아이디어 스케치·토론): "마이크로비트에 포함된 입출력 장치로도 다양한 일상의 문제를 해결할 수 있다. 다음 [일상의 문제 상황]에서 마이크로비트를 어떻게 사용하면 좋을지 아이디어를 스케치하고 친구들과 토론해 보자." — 표 [일상의 문제 상황 | 아이디어 스케치] 3행.
  1. "윗몸 일으키기를 하는데 몇 번 했는지 자동으로 세어 줬으면 좋겠어." → 디지털 카운터로 횟수 기록, 손을 못 쓸 때 밝기·기울기 변화로 카운터 증가.
  2. "누군가 내 사물함을 몰래 열었을 때 깜짝 놀라게 할 수 있을까?" → 사물함을 열면 빛을 감지해 삐삐 알람음.
  3. "의자에 오래 앉아 있으면 건강에 좋지 않아. 스트레칭을 할 때를 알려 줘." → 설정한 시간이 되면 알람음을 내는 장치.
- 지도 목표: 마이크로비트 입출력 장치 종류를 이해하고 생활 문제 해결 방안 설명.
- 유의점: 입력-처리-출력 관계를 함께 생각 / 모범 답안을 요구하기보다 다른 접근 가능성 토론 / 일반 시스템과 다른 피지컬 장치로 해결하는 장점을 함께 이야기.
- 해설: 한 번에 완성하기보다 스케치 → 마이크로비트로 제작 → 직접 사용하며 새 문제 발견·개선.

### 창의·융합 프로젝트 "몸을 움직여서 즉흥 연주하기" (교 40~41쪽, p.88~89) — 모둠, 마이크로비트 + 배터리팩, 프로젝트 기반 학습/디자인 기반 학습
- **문제 상황**(원문 요지): 피아노는 손으로, 드럼은 스틱으로, 트럼펫은 입으로 연주. "만약 몸의 움직임으로 춤을 추듯이 연주하는 악기가 있다면 어떨까? 피지컬 컴퓨팅은 우리의 상상을 현실로 만들어 준다."
- **지도 목표**: 몸의 움직임으로 음악을 연주하는 창의적 표현을 만들 수 있다. 준비물: 교사(수업 지도안, 컴퓨터, 마이크로비트) / 학생(교과서, 컴퓨터, 마이크로비트).
- **활동 순서**: 01 프로젝트 방향 정하기 → 02 역할 정하기 → 03 프로젝트 수행하기 → 04 보고서 작성하기 → 05 발표하기. "나만의 평가 점검표를 만들어 평가해 보아요." (Link 238쪽)
- **1 생활 속에서 문제를 발견하기** — 해설: 익숙한 악기도 처음엔 자연스럽지 않았을 것, 익숙한 방식에서 벗어나는 창의 활동. 소재 테레민(1920년대 최초의 전자 악기, 레온 테레민, 안테나 옆 허공에서 손을 움직여 연주; 출처 위키백과).
- **2 몸으로 연주하는 악기 구상하기** — 지시문: "원하는 몸의 움직임을 생각해 보고, 그에 어울리는 소리를 찾아보자. 마이크로비트를 부착하는 몸의 위치에 따라서 다양한 움직임을 만들 수 있다." / "마이크로비트에서 몸의 움직임을 측정하기 좋은 센서를 찾아보자. 또 움직임에 어울리는 소리를 다양한 멜로디나 효과음으로 표현해 보자."
  - 표 [몸의 움직임 | 연결할 소리] 예: 팔을 수평으로 뒀다가 위로 올리기 → 상승하는 멜로디 소리 '도레미~'
  - 해설 표 [가속도 센서 | 움직임]: 스크린 하늘 방향 → 머리 뒤에 부착하고 고개를 숙이는 행동 / 왼쪽·오른쪽 기울임 → 팔·다리에 부착하고 들고 내리는 행동 / 자유 낙하 → 몸에 부착하고 점프. 음계가 오르거나 내려가는 진행 고민.
- **3 피지컬 컴퓨팅 시스템으로 만들기**
  - 단계 1 마이크로비트로 연결하기: "마이크로비트를 몸에 부착하고 자유로운 움직임을 표현하기 위해서는 마이크로비트를 배터리로 동작시켜야 한다. 몸의 어떤 부위에 부착할지 고민해 보고, 마이크로비트를 고정할 방법을 찾아보자. 손목뿐만 아니라 머리, 혹은 다리에 부착하면 더 재미있는 몸동작을 만들 수 있다." (해설: 부착 방법 고안도 창작의 중요한 과정)
  - 단계 2 입력-처리-출력 설계: (1) 입력 — 가속도 센서로 상하좌우 움직임 측정, 동작이 어떤 움직임을 만드는지 확인해 선택 / (2) 처리 — "'(원하는 움직임) 감지될 때' 블록을 이용해 소리를 연주할 수 있는 조건문을 완성한다." / (3) 출력 — 움직임에 어울리는 소리 선택, 음악 카테고리 블록으로 멜로디·효과음.
    - 블록 예(렌더링 확인, 흐릿함): 멜로디 — `[재생 (♪ 멜로디 편집) 멜로디를 (120)(bpm) 템포로 연주 (완료될 때까지 ▼)]`, 음정 — `[재생 (음정 (도 ▼)) (1 ▼) 박자 ... (완료될 때까지 ▼)]` → "특정 음정이나 멜로디 연주 가능" / 효과음 — `[재생 (기가기가 ▼ 등 내장 효과음) (완료될 때까지 ▼)]`, `[재생 (사운드 파형 편집) (완료될 때까지 ▼)]` → "독특한 효과음 만들기 가능" (블록 내 작은 글씨는 일부 확인 불가)
    - 해설(입력·처리·출력): 입력=가속도 센서, [감지될 때] 블록의 움직임 중 몸동작에 어울리는 것 선택 / 처리=[감지될 때]는 조건문 블록, 감지되면 내부 블록 실행 / 출력='음악' 카테고리에서 여러 블록 실험.
    - 삽화: 몸에 마이크로비트를 단 학생들이 "띠리리리리~" "삐유우우~" 소리를 내며 동작.
  - 단계 3 프로그래밍하기: "프로그래밍을 한 마이크로비트를 몸에 부착한 후 움직여 보고, 원하는 소리가 나오는지 알아보자." (해설: 간단한 조건문이지만 동작과 소리를 맞추기 위해 실험·수정 반복)
  - 예시 프로그램 구조(제안·재구성): `[스크린 하늘 방향 ▼ 감지될 때] { [재생 멜로디(상승)] }`, `[왼쪽 기울임 ▼ 감지될 때] { [재생 음정 도] }`, `[자유 낙하 ▼ 감지될 때] { [재생 효과음] }` — 실습 파일 "41쪽 프로젝트 즉흥 연주하기.hex"(T셀파)에 원본.
- **4 악보를 만들고 즉흥 연주하기** — 지시문: "친구들과 각자의 역할을 나누고, 서로 다른 움직임과 악기를 연결해서 어울리는 소리를 찾아보자. 모두가 함께 소리를 낼 수도 있지만, 서로의 음색이나 악기에 따라 연주하는 순서를 정할 수 있다." / "현대의 음악가 중에는 자신만의 악보를 만들어 곡을 연주하기도 한다. 친구들과 움직임을 표현하는 우리만의 약속을 정하여 악보를 만들고, 즉흥 연주를 해 보자." (그림: 어느 현대 음악가의 악보). 해설: 전통 악보가 아닌 모둠별 몸 움직임 규칙을 담은 개성 있는 악보.
- **지도상의 유의점**: 대중 음악 재현보다 생소한 소리 표현 / 부착 방식에 따라 가속도 인식이 달라지므로 **센서값 먼저 확인** / 무작위 동작보다 센서가 정확히 인식하는 **대표 동작**을 함께 만듦 / 정답이 없는 활동, 학생 주도 접근.
- **PBL/DBL 운영**: PBL — "몸의 움직임이 음악이 될 수 있을까?"라는 문제를 제시하고 센서 특징·동작 방식·소리 구성을 협력 활동으로 / DBL — 창의적 신체 인터페이스 구상 과제 + 여럿이 함께 연주할 새로운 악보 설계.

## 오개념 · 지도 유의점 모음
- 마이크로컨트롤러는 출력 장치가 아님(처리 장치, 입출력 제어 핵심 부품). (p.105)
- 피지컬 컴퓨팅은 '입력-출력'만이 아니라 '입력-처리-출력', 소프트웨어가 HW만큼 중요. (대단원 마무리 05, p.90)
- 버튼(디지털 0/1)은 "센서값이 50보다 작으면" 같은 연속값 비교 조건에 부적합. (p.90)
- 스마트폰 거치대 경고: 기울기보다 **밝기 센서**(올려 두면 어둡다가 들면 밝아짐) — 하나의 센서 다용도 사고. (p.90, p.79)
- 마이크로비트 빛 센서는 0~255(아두이노 아날로그 입력 표는 0~1023) — 범위 혼동 주의. (p.76, p.80)
- 경곗값(100 등)은 교실 밝기에 따라 달라지므로 먼저 수 출력으로 측정. (p.80)
- MakeCode 업로드는 유선 필요, 블루투스는 무선 연결용; hex 파일은 USB 메모리 저장처럼 붙여 넣기. (p.58)
- 구현은 점진적으로, 개선은 HW(스트랩)·SW(표시음) 양면. (p.82)
- 활동 3은 실제 제작이 아닌 개념적 흐름, 조건 처리 = 조건문. (p.78)
- 가속도 센서는 부착 위치·방향에 따라 인식이 달라짐. (p.88)

## 원문 오류 의심
- p.85 [9정01-03] 성취 수준 A와 B가 동일 문장으로 인쇄됨(B는 "선택하고 시스템을 구성하는 과정을 통해 … 유연한 태도를 인식"일 것으로 추정 — p.58의 B 문장).
- p.58~59 차시별 계획의 A/B/C와 p.85 5단계 A~E가 대응이 맞지 않음(p.58 B = p.85 C에 가까운 문장이지만 "유연한 태도를 인식"까지 포함). 출처 기준 차이로 보임.
- p.76 입력값 표 "초음파 센서(IR 센서)" — 초음파 센서와 IR(적외선) 센서는 다른 센서. 또 초음파 센서는 보통 디지털 펄스 방식으로 거리 측정.

- p.78 핵심 개념 정리 "엑추에이터"(2회) ↔ 본문 "액추에이터" 표기 혼용.
- p.79 마이크로비트 입력 목록에 "소리 센서"와 "마이크"가 중복 나열(V2의 소리 감지는 마이크).
- p.53 참고 문헌 "Tomlgoe" 표기 오류(ch01과 동일).
